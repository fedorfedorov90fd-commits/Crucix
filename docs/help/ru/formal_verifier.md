# Формальная верификация: formal_verifier.py

## Простое объяснение (для новичков)

Этот файл — «математический судья» системы. Обычный ИИ часто «галлюцинирует» — предполагает, но не доказывает. Этот модуль не предполагает. Он доказывает.

**Что он делает:**

1. **Принимает набор фактов** — например, «источник А заявил о мире», «источник Б поставляет оружие».
2. **Применяет аксиомы** — правила логики, заданные в конфиге. Например: «если поставляют оружие и обучают армию, то это состояние войны».
3. **Проверяет согласованность** — можно ли все факты и аксиомы сделать истинными одновременно.
4. **Возвращает результат** — `sat` (согласовано) или `unsat` (противоречие), с доказательством.

**Зачем это нужно:**

Если система скажет «источник А лжёт», начальник спросит: «Почему?». Обычный ИИ ответит: «Потому что я так думаю». Этот модуль ответит: «Потому что факты А и Б не могут быть истинными одновременно. Вот минимальный набор противоречащих фактов. QED».

**Аналогия:**

Это как калькулятор для логики. Вы вводите: «Если A, то B. Если B, то C. A истинно». Калькулятор выдаёт: «C истинно». Не «вероятно», не «возможно», а «доказано».

## Научная база (для специалистов)

Модуль использует **SMT-решатель Z3** (Microsoft Research) — стандартный инструмент автоматического доказательства теорем и верификации программного обеспечения.

**Формально:**

Задача формулируется как проверка выполнимости (satisfiability) набора булевых формул:

1. **Факты** кодируются булевыми переменными: `A = True`, `B = False`.
2. **Аксиомы** кодируются импликациями: `Implies(And(premises), conclusion)`.
3. **Проверка:** `s.check() == sat` — существует ли выполнение, при котором все аксиомы и факты истинны.

**Если `unsat`:**

Извлекается `unsat_core` — минимальное противоречивое подмножество фактов и аксиом. Это «доказательство»: какие именно утверждения конфликтуют.

**Если `sat`:**

Возвращается модель — конкретное назначение значений переменных, при котором всё истинно. Это «доказательство согласованности».

**Почему Z3:**

- **Стандарт индустрии.** Используется в верификации процессоров, компиляторов, протоколов.
- **Поддержка теорий.** Не только булева логика, но и арифметика, массивы, битовые векторы.
- **Открытый исходный код.** Бесплатный, активно развивается.
- **Python-биндинги.** `pip install z3-solver`.

**Ограничения:**

- Z3 не «понимает» естественный язык. Факты должны быть предварительно формализованы — это делает отдельный слой.
- `unsat` — не приговор источнику, а сигнал о противоречии в наборе утверждений. Интерпретируйте вместе с контекстом.
- Аксиомы должны быть явными и версионируемыми: изменение правил меняет выводы.

## Как работает (пошагово)

1. Создаётся решатель: `s = Solver()`.
2. Из конфига загружаются `logic_rules` — аксиомы в виде пар «посылки → следствие».
3. Для каждого правила выполняется `s.add(Implies(And(...premises), conclusion))`.
4. Текущие факты добавляются как булевы переменные со значениями: `s.add(A == True)`. Пустые/невалидные факты отбрасываются.
5. `s.check()` возвращает:
   - `sat` — набор согласован. Модель содержит значения всех переменных.
   - `unsat` — есть противоречие. Извлекается `unsat_core`.
6. При `unsat` формируется объект-доказательство (`proof_object`) с указанием противоречащих фактов.
7. Результат используется как «нотариальная» проверка аналитического вывода.

**Формат ответа:**

```python
{
    'consistent': True,           # или False
    'derived': ['state_of_war'],  # что следует из фактов
    'proof': 'QED',               # доказательство
    'unsat_core': [...]           # если inconsistent — минимальный набор противоречий
}

Пример использования
python

from services.formal_verifier import verify_narrative

# Факты: поставляют оружие, обучают армию
result = verify_narrative(facts={
    "supply_weapons": True,
    "training_army": True
})
print(result)
# {'consistent': True, 'derived': ['state_of_war'], 'proof': 'QED'}

# Факты: поставляют оружие, но это не война
result = verify_narrative(facts={
    "supply_weapons": True,
    "state_of_war": False
})
print(result)
# {'consistent': False, 'unsat_core': ['supply_weapons', 'state_of_war'], 'proof': '...'}

Что происходит:

    В первом случае: аксиома «если поставляют оружие и обучают армию, то это война» + факты «поставляют» и «обучают» → вывод «война». Согласовано.

    Во втором случае: аксиома «если поставляют оружие, то это война» + факты «поставляют» и «не война» → противоречие. unsat.

Практические рекомендации

    Аксиомы должны быть явными и версионируемыми. Изменение правил меняет выводы. Фиксируйте версию в отчёте.

    Z3 не «понимает» естественный язык. Факты должны быть предварительно формализованы. Это делает отдельный слой (NLP-модуль).

    unsat — не приговор источнику. Это сигнал о противоречии в наборе утверждений. Интерпретируйте вместе с контекстом.

    Используйте unsat_core для объяснения результата. Аналитику нужно видеть, какие именно факты конфликтуют.

    Модуль хорошо подходит для проверки регламентов и правил мониторинга. Не используйте для «доказательства вины» источника.

    Не злоупотребляйте. Z3 — мощный инструмент, но не для каждой задачи. Применяйте там, где есть формальные правила (юридические, логические).

    sat — не «истина». Это «согласованность с аксиомами». Если аксиомы неверны — вывод тоже неверен.

    proof_object — криптографическое доказательство. Сохраняйте его в БД для аудита.

    Для сложных правил — используйте And, Or, Not, Implies. Z3 поддерживает всю булеву логику.

    Для арифметики — используйте Int, Real. Z3 поддерживает линейную арифметику.
