Event Map — первый из пяти независимых модулей платформы Crucix. Он визуализирует точечные события (конфликты, протесты, кибератаки, катастрофы) по всему миру.

Ниже приведена подробная техническая справка, извлеченная из вашего манифеста, которая объясняет архитектуру и текущее состояние системы.

1. Суть и место в экосистеме

Event Map — это геопространственный слой инцидентов. В отличие от других карт Crucix, он работает не с агрегированными показателями (как Metrics Map), а с конкретными точками на карте.

84 слоя данных, разделенных на 12 категорий (от вооруженных конфликтов до экологических катастроф).
Принцип автономии (R1–R6): Карта полностью изолирована. У нее нет зависимостей от других модулей (Metrics, Semantic, Network, Forecast). Если упадет Event Map, остальные четыре продолжат работать. Все данные (включая границы стран world.geojson) хранятся локально.
2. Как это работает (Архитектура загрузки)

Загрузка карты строго детерминирована (DAG — направленный ациклический граф). Порядок скриптов в index.html критичен:

Инициализация: Создается глобальный объект window.CrucixMap.
Ядро: Подключаются core.js (язык, уведомления), countries.js (список из 90 стран) и layers.js (каталог 84 слоев).
Визуализация: maps-config.js задает иконки и цвета, event-adapter.js типизирует события, map-controls.js инициализирует Leaflet.
Данные: markers.js запрашивает данные через fetch('/api/layers/<id>').
Если API работает: Маркер ставится на основе реальных координат.
Если API недоступен (Offline fallback): Срабатывает детерминированный генератор. Для каждой из 90 стран создается 2–5 фейковых маркеров со смещением координат, чтобы карта не выглядела пустой.
3. Визуализация и данные
Общий объем: При активации всех 84 слоев на карте отображается около 1260 маркеров.
Кластеризация: Используется Leaflet MarkerCluster. При отдалении маркеры группируются по категориям (например, кластер «Конфликты» будет красным).
Приоритизация: Каждому маркеру присваивается приоритет (Low/Medium/High/Critical) на основе статуса страны, свежести события и количества источников. Критические маркеры всегда отображаются выше остальных.
Панель слоев: Справа находится панель из 85 кнопок (84 слоя + «Все»), позволяющая включать и выключать категории инцидентов.
4. Текущий статус (на 30.09.2026)

Согласно вашему манифесту, базовый функционал (84 слоя, автономность, локальные данные, offline-режим) полностью готов. Однако есть четыре незавершенных модуля, требующих внимания:

Heat Map (Карта плотности): Кнопка HEAT работает нестабильно. Нужно доработать логику сбора координат всех активных маркеров для передачи в L.heatLayer и добавить легенду.
Timeline (Временная шкала): Модуль не синхронизирован с маркерами по датам. Требуется добавить временные метки (timestamp) к каждому маркеру и настроить фильтр диапазона дат.
Кнопка «Enable All»: Существует риск, что цикл активации всех 84 слоев может прерваться или не обработать часть данных. Нужна проверка итерации и логирование.
Snapshot (Копирование данных): Кнопка COPY должна генерировать JSON-файл размером 1–2 МБ со статусом всех маркеров. Нужно проверить, что в дамп попадают все 1260 точек, а не только заголовки слоев.
