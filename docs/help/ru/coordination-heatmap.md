# Тепловая карта координации: coordination-heatmap.js

## Простое объяснение (для новичков)

Этот файл — «тепловизор» информационного поля. Он рисует матрицу, где по одной оси — источники, по другой — темы, а цвет ячейки показывает, насколько синхронно источник освещает тему.

**Что это значит на практике:**

- Ярко-красная ячейка — источник активно и синхронно пишет об этой теме.
- Бледная или белая ячейка — источник тему игнорирует или пишет редко.
- Если целая строка красная — источник «вездесущ», пишет обо всём.
- Если целый столбец красный — тема «взорвалась», о ней пишут все.

**Зачем это нужно:**

Вы открываете дашборд и сразу видите: кто с кем синхронен, кто «спит», а какая тема «горит». Это визуальное доказательство координации: если десять мелких сайтов одновременно вспыхивают красным по одной теме — это уже не случайность.

**Аналогия:**

Представьте карту пробок. Зелёный — свободно, красный — затор. Здесь то же самое, только вместо дорог — источники, а вместо машин — новости. Красная ячейка = «пробка» из синхронных публикаций.

## Научная база (для специалистов)

Виджет реализует классическую тепловую карту (heatmap) на D3.js. Используется для визуализации матрицы «источник × тема», где значение ячейки — коэффициент синхронности (`sync_score`).

**Архитектура:**

- **Библиотека:** D3.js v7.9.0 (локально, `lib/d3.min.js`).
- **Тип визуализации:** `scaleBand` для осей (автоматическое распределение ячеек без наложений).
- **Цветовая схема:** `d3.interpolateReds` — от белого (нет связи) к ярко-красному (полная синхронизация).
- **Очистка:** `container.selectAll('*').remove()` перед каждой перерисовкой — защита от накопления SVG-элементов.
- **Подсказки:** `append('title')` — нативные HTML-подсказки при наведении.

**Почему `scaleBand`:**

Это стандартный инструмент D3 для категориальных осей. Он автоматически вычисляет ширину каждой полосы так, чтобы ячейки не наезжали друг на друга, независимо от количества источников и тем. Без `scaleBand` пришлось бы вручную вычислять координаты — это источник ошибок.

**Почему `interpolateReds`:**

Интуитивно понятная семиотика: белый — нет связи, красный — полная синхронизация. Это соответствует «тепловой» метафоре: чем «горячее», тем интенсивнее.

**Почему `rotate(-45)`:**

Стандарт читаемости для длинных имён источников. Без поворота подписи наезжают друг на друга и становятся нечитаемыми.

**Ограничения:**

- Работает с «плоским» массивом данных — не важно, как вычислен `sync_score`.
- Не содержит бизнес-логики — только отображение.
- Требует, чтобы `sync_score` был в диапазоне 0–1.

## Как работает (пошагово)

1. `renderCoordinationHeatmap(containerId, dataMatrix)` принимает ID контейнера и массив данных.
2. Находит контейнер по ID.
3. Очищает предыдущий SVG (`container.selectAll('*').remove()`).
4. Извлекает уникальные источники и темы из `dataMatrix`.
5. Вычисляет ширину и высоту SVG на основе количества источников и тем.
6. Создаёт `scaleBand` для осей X (темы) и Y (источники).
7. Создаёт цветовую шкалу `scaleSequential(interpolateReds)` с доменом [0, 1].
8. Рисует оси с поворотом подписей на -45°.
9. Рисует ячейки: для каждой пары `(источник, тема)` — прямоугольник с цветом по `sync_score`.
10. Добавляет подсказки: при наведении на ячейку — точный процент синхронности.
11. Добавляет текст внутри ячеек: процент синхронности (например, «95%»).

**Формат данных:**

```javascript
[
  { source: 'ТАСС', topic: 'geopolitics', sync_score: 0.95 },
  { source: 'ТАСС', topic: 'economy', sync_score: 0.42 },
  { source: 'Reuters', topic: 'geopolitics', sync_score: 0.18 },
  // ...
]

Пример использования

В HTML-странице:
html

<div id="coordination-heatmap"></div>
<script type="module" src="/widgets/coordination-heatmap.js"></script>

В другом виджете (программно):
javascript

import { renderCoordinationHeatmap } from '/widgets/coordination-heatmap.js';

const dataMatrix = [
  { source: 'ТАСС', topic: 'geopolitics', sync_score: 0.95 },
  { source: 'РИА', topic: 'geopolitics', sync_score: 0.91 },
  { source: 'Reuters', topic: 'geopolitics', sync_score: 0.12 },
  { source: 'ТАСС', topic: 'economy', sync_score: 0.42 },
  { source: 'Reuters', topic: 'economy', sync_score: 0.78 }
];

renderCoordinationHeatmap('coordination-heatmap', dataMatrix);

Что появится на экране:

Матрица, где:

    По оси X — темы (geopolitics, economy).

    По оси Y — источники (ТАСС, РИА, Reuters).

    Ячейки окрашены: ТАСС × geopolitics — ярко-красная (0.95), Reuters × geopolitics — бледная (0.12).

    При наведении на ячейку — подсказка «ТАСС vs geopolitics: 95.0%».

Практические рекомендации

    sync_score должен быть в диапазоне 0–1. Если значения выходят за пределы — цветовая шкала сломается. Нормализуйте данные перед передачей.

    Очистка перед перерисовкой — container.selectAll('*').remove(). Без этого SVG накапливаются и тормозят браузер.

    scaleBand — не меняйте на scaleLinear. Для категориальных осей scaleBand — стандарт.

    Поворот подписей на -45° — стандарт для длинных имён. Если имена короткие (до 8 символов), можно не поворачивать.

    interpolateReds — интуитивная семиотика. Для других целей можно interpolateBlues (холодная) или interpolateViridis (равномерная).

    Подсказки append('title') — нативные HTML-подсказки. Работают во всех браузерах, не требуют JS.

    Текст внутри ячеек — процент синхронности. Полезен для быстрого чтения, но при большом количестве ячеек может быть шумным. Отключайте при > 100 ячеек.

    Работает с «плоским» массивом — не важно, как вычислен sync_score. Это делает виджет универсальным: можно передавать данные из любого источника.

    Не содержит бизнес-логики — только отображение. Вся логика — в source-coordination-api.mjs.

    overflow-x: auto — при большом количестве источников матрица не влезает в экран. Горизонтальный скролл спасает.

    Максимум ячеек — ~1000. При большем количестве браузер начинает тормозить. Если источников и тем больше — агрегируйте данные.
