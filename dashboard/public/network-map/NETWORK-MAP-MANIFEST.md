## 1. НАЗНАЧЕНИЕ И МЕСТО В ЭКОСИСТЕМЕ CRUCIX

### 1.1. Что такое Crucix — экосистема из 5 карт

Crucix — геополитическая OSINT-платформа. Она состоит из **5 автономных карт**, каждая визуализирует свой класс данных:

1. **Event Map** (`/event-map/`) — точечные события на карте (митинги, атаки, инциденты). 84 слоя, маркеры.
2. **Metrics Map** (`/metrics-map/`) — количественные индикаторы по странам (экономика, финансы, ESG, кибер, энергетика). 75 слоёв, choropleth.
3. **Semantic Map** (`/semantic-map/`) — семантический анализ текстов (тональность, нарративы, дезинформация). 35 слоёв.
4. **Forecast Map** (`/forecast-map/`) — вероятностные прогнозы (рецессия, конфликты, риски). 16 слоёв.
5. **Network Map** (`/network-map/`) — графы связей (кибер-сети, торговля, финансы, миграция). **12 слоёв**, SVG-граф. **ЭТА КАРТА.**

### 1.2. Зачем именно 5 карт, а не одна

Пять карт — это реализация принципа **Separation of Concerns** (Dijkstra 1974). Каждый класс данных требует собственной модели визуализации:

- **События** → позиция + цвет (точечные маркеры). Канал: Position.
- **Количественные индикаторы** → позиция (страна) + интенсивность цвета (choropleth). Канал: Position + Color intensity.
- **Семантика** → позиция + категориальный цвет + форма. Канал: Position + Hue + Shape.
- **Вероятности** → позиция + цвет + прозрачность (opacity). Канал: Position + Color intensity + Transparency.
- **Связи** → топология графа (force-directed). Канал: Position (force) + Shape. **ЭТО КАНАЛ NETWORK MAP.**

Попытка объединить всё в одну карту нарушила бы **принцип сепарабельности каналов** (Munzner 2014). Разделение на 5 карт — научно обоснованное решение, а не организационное удобство.

### 1.3. Что делает Network Map

Network Map визуализирует **графы связей между сущностями**. Каждый слой — это сеть определённого типа:

- Торговля: экспортно-импортные связи между странами
- Кибер: кибератаки и их источники/цели
- Финансы: финансовые потоки и банковские связи
- Миграция: миграционные потоки между странами
- Дипломатия: дипломатические отношения и альянсы
- Военные: военные союзы и партнёрства
- Энергетика: цепочки энергоснабжения
- Логистика: цепочки поставок
- Социальные медиа: сети распространения информации
- Разведка: сети обмена разведданными
- Транспорт: транспортные коридоры
- Связь: телекоммуникационные сети

Итого: **12 слоёв в 12 категориях**.

### 1.4. Уникальная особенность: SVG Force-Directed Graph (Barabasi 2016)

Network Map — единственная карта в экосистеме, которая **не использует Leaflet**. Вместо географической карты — SVG-граф с физической симуляцией связей.

**Force-directed simulation** моделирует граф как физическую систему:
- **Кулоновское отталкивание** (Coulomb repulsion): `F = k / r²` — все узлы отталкиваются друг от друга.
- **Гуково притяжение** (Hooke attraction): `F = (d − L) × 0.1` — связанные узлы притягиваются. Где `d` — текущее расстояние, `L` — идеальная длина связи.
- **Гравитация** (gravity): все узлы слабо притягиваются к центру — предотвращает разлетание графа.
- **Интегрирование Верле** (Verlet integration): обновление позиций узлов с учётом скорости и затухания.

Сложность: O(n²) — приемлемо для n < 500 узлов. При большем количестве — кластеризация или иерархический layout.

Методологическая основа: Barabasi 2016, «Network Science» — сила-направленная укладка графов.

### 1.5. Отличия от остальных 4 карт

- **Network Map:** топология связей, SVG-граф, без Leaflet, без world.geojson. 12 слоёв. Канал: Position (force) + Shape.
- **Event Map:** точечные маркеры на географической карте. 84 слоя.
- **Metrics Map:** choropleth по странам. 75 слоёв.
- **Semantic Map:** choropleth по странам с sentiment-адаптером. 35 слоёв.
- **Forecast Map:** probability-заливка с opacity. 16 слоёв.

Network Map оперирует **отношениями** между сущностями, а не точечными событиями, числовыми индикаторами, текстами или вероятностями. Это принципиально другой класс данных, требующий принципиально другой визуализации.

## 6. КАК РАБОТАЕТ FORCE-DIRECTED GRAPH

### 6.1. Физическая симуляция

При клике на слой:
1. `loadLayer(layerId)` → `GraphView.loadLayer(layer)`.
2. `fetch('/api/layers/<id>')`.
3. Если 404 → `renderGraphFallback(layer)`:
   - Генерация узлов из `countries.js` (выборка по категории слоя).
   - Генерация рёбер: детерминированный seed, каждый узел связан с 2–4 другими.
   - Тип узла = категория слоя (страна → Circle, организация → Square, событие → Triangle, финансовый → Diamond).
   - Узлы и рёбра передаются в `GraphView.render(nodes, edges)`.
4. Если API работает — `NetworkAdapter.convert(layerId, data, countries)`:
   - Извлекает узлы и рёбра из данных.
   - Присваивает типы узлам.
   - Возвращает {nodes, edges} для graph-view.

### 6.2. Force Simulation (Verlet Integration)

Каждый кадр:
1. **Кулоновское отталкивание** (O(n²)):
   - Для каждой пары узлов (i, j): `F = k / r²`, где `r` — расстояние, `k` — константа отталкивания.
   - Направление: от j к i (и наоборот).
2. **Гуково притяжение** (O(E), E — число рёбер):
   - Для каждого ребра (i, j): `F = (d − L) × 0.1`, где `d` — текущая длина, `L` — идеальная длина.
   - Направление: от i к j (и наоборот).
3. **Гравитация** (O(n)):
   - Для каждого узла: `F = g × (center − position)`, где `g` — константа гравитации.
   - Притягивает все узлы к центру canvas.
4. **Verlet integration**:
   - `new_position = position + (position − prev_position) × damping + force × dt²`.
   - `damping = 0.85` — затухание (предотвращает осцилляцию).
   - `dt = 1/60` — шаг времени (60 FPS).

### 6.3. Параметры физики

| Параметр | Значение | Описание |
|----------|----------|----------|
| `repulsion_k` | 5000 | Сила кулоновского отталкивания |
| `attraction_k` | 0.1 | Коэффициент гуково притяжения |
| `ideal_length` | 80 | Идеальная длина ребра (px) |
| `gravity` | 0.02 | Сила притяжения к центру |
| `damping` | 0.85 | Затухание скорости |
| `dt` | 1/60 | Шаг времени |
| `max_iterations` | 300 | Максимум итераций до остановки |

### 6.4. Остановка симуляции

Симуляция останавливается, когда:
- Кинетическая энергия системы < порога (0.001).
- Достигнут `max_iterations` (300).
- Пользователь кликнул на узел (пауза для досье).

## 7. ФОРМЫ УЗЛОВ

Network Map использует **4 формы узлов** для визуального различения типов сущностей:

| Форма | SVG element | Тип | Цвет | Размер |
|-------|------------|------|------|--------|
| Circle | `<circle>` | Страна / кибер-узел | #00aaff (синий) | r=8 |
| Square | `<rect>` | Организация | #32cd32 (зелёный) | 16×16 |
| Triangle | `<polygon>` | Событие | #ff8c00 (оранжевый) | 14px |
| Diamond | `<polygon>` | Финансовый объект | #ffd700 (золотой) | 14px |

### 7.1. Визуальные параметры

- **Обводка** — белая, 1.5px, для контраста с тёмным фоном.
- **Прозрачность** — 0.9 для активных, 0.4 для неактивных слоёв.
- **Подпись** — название узла под формой, шрифт 10px, белый.
- **Z-index** — выбранный узел поверх всех.
- **Hover** — увеличение размера на 30%, подсветка обводки.

### 7.2. Рёбра

- **Цвет** — серый (#888) по умолчанию.
- **Толщина** — пропорциональна весу связи (1–4px).
- **Прозрачность** — 0.6 для активных, 0.2 для неактивных.
- **Направление** — стрелка для направленных связей (кибератаки, финансовые потоки).
- **Подпись** — вес связи при наведении.

## 11. NETWORK-ADAPTER — ДЕТАЛЬНО

### 11.1. Назначение

`network-adapter.js` конвертирует данные связей (из API или fallback) в формат для SVG-графа: массив узлов и массив рёбер.

### 11.2. Параметры

```javascript
NetworkAdapter.convert(layerId, networkData, countries)
```

### 11.3. Формат узлов

```javascript
{
  id: "us",
  label: "США",
  type: "country",        // country | organization | event | financial
  shape: "circle",        // circle | square | triangle | diamond
  color: "#00aaff",
  size: 8,
  x: 0,                   // начальная позиция
  y: 0,
  vx: 0,                  // скорость
  vy: 0
}
```

### 11.4. Формат рёбер

```javascript
{
  source: "us",
  target: "cn",
  weight: 0.85,           // сила связи (0–1)
  directed: true,         // направленная связь
  color: "#888",
  width: 2
}
```

### 11.5. Spatial Proxies для генерации рёбер

| Proxy | Логика связей | Применение |
|-------|--------------|------------|
| trade_volume | страны с большим объёмом двусторонней торговли | торговля |
| attack_source_target | источник атаки → цель | кибер |
| capital_flow | направление финансовых потоков | финансы |
| migration_direction | направление миграционных потоков | миграция |
| alliance_membership | члены общих альянсов | дипломатия, военные |
| supply_chain_links | поставщик → потребитель | энергетика, логистика |
| information_flow | распространение информации | социальные медиа |
| physical_routes | транспортные маршруты | транспорт, связь |

## 13. ЧТО НУЖНО ДОДЕЛАТЬ

### 13.1. Стабильность force simulation
Проблема: при большом числе узлов (>300) симуляция может быть нестабильной — узлы «разлетаются» или осциллируют.

Требуется:
- Настроить `damping` (0.85) — возможно, повысить до 0.9 для больших графов.
- Добавить `alpha decay` — постепенное затухание энергии.
- При n > 300 — уменьшить `repulsion_k` (5000 → 3000).

### 13.2. Панель досье
Проблема: панель может не открываться при клике на узел.

Требуется:
- Проверить, что `graph-view.js` корректно вызывает `openDossier(node)`.
- Панель должна показывать: тип, категорию, связи, метрики.
- Клик вне узла — закрывает панель.

### 13.3. Различение форм узлов
Проблема: 4 формы (Circle, Square, Triangle, Diamond) могут быть визуально неразличимы при малом размере.

Требуется:
- Минимальный размер узла — 8px (Circle r=8, Square 16×16, Triangle/Diamond 14px).
- При наведении — увеличение на 30%.
- Выбранный узел — увеличение на 50% + подсветка.

### 13.4. Метрики графа
Проблема: PageRank, Betweenness могут быть не реализованы в `graph-panel.js`.

Требуется:
- Реализовать Degree centrality, Betweenness centrality, PageRank.
- Отображать в панели досье.
- Логировать при вычислении.

### 13.5. Кнопка «Включить все»
Проверить обработку всех 12 слоёв. При активации всех 12 — ~530 узлов, ~1060 рёбер.

## 21. ГЛОССАРИЙ

- **Force-directed graph** — метод укладки графа, моделирующий физическую систему сил.
- **Coulomb repulsion** — отталкивание между всеми парами узлов: `F = k / r²`.
- **Hooke attraction** — притяжение между связанными узлами: `F = (d − L) × k`.
- **Verlet integration** — метод численного интегрирования для обновления позиций.
- **Node** — узел графа, представляет сущность (страна, организация, событие, финансы).
- **Edge** — ребро графа, представляет связь между сущностями.
- **Dossier** — панель с подробной информацией о выбранном узле.
- **Degree centrality** — важность узла по числу связей.
- **Betweenness centrality** — роль узла как посредника на кратчайших путях.
- **PageRank** — мера влияния узла (Page 1998).
- **Barabasi 2016** — методологическая основа: «Network Science».
- **O(n²)** — вычислительная сложность кулоновского отталкивания (приемлемо для n < 500).
