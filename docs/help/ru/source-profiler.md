# Профилировщик источников: source-profiler.mjs

## Простое объяснение (для новичков)

Этот файл — «детектор лжи» и «счетчик скорости» для каждого источника. Он анализирует не сами новости, а поведение источников: как быстро они публикуют информацию и насколько узко они сфокусированы на одной теме.

**Что он делает:**

1. **Считает задержку (latency)** — сколько в среднем времени проходит между публикацией новости и текущим моментом. Если источник опаздывает на 24 часа — он работает как «архив», а не как новостная лента.
2. **Считает смещение (bias)** — насколько узко источник специализирован. Если он пишет только про геополитику — `bias` близок к 1.0 (узкий специалист). Если обо всём подряд — `bias` ниже (зашумлённый агрегатор).
3. **Считает объём (item_count)** — сколько статей у источника в выборке. Нельзя доверять профилю по одной новости.

**Зачем это нужно:**

В оперативной работе важна скорость. Источники с высокой задержкой должны иметь меньший вес в общем индексе. Узкие специалисты могут быть авторитетнее, но их нельзя использовать для общей картины.

**Аналогия:**

Представьте, что вы сравниваете двух журналистов. Один публикует новости через 5 минут после события — он «быстрый». Другой — через сутки — он «аналитик». Один пишет только о спорте — он «эксперт». Другой — обо всём — он «универсал». Профилировщик измеряет эти характеристики численно.

## Научная база (для специалистов)

Модуль реализует **профилирование источников** через две метрики: задержку (latency) и смещение (bias).

**Формально:**

**1. Latency (задержка):**

Для источника `s` с набором статей `I_s`:

**latency_hours(s) = (1/|I_s|) · Σ (now - published_at(i)) / 3600000**

где `i ∈ I_s`, `now` — текущее время.

Высокое значение (24+ часа) означает, что источник работает как «архив» — публикует с большой задержкой.

**2. Bias (смещение):**

**bias_score(s) = 1 / unique_categories(s)**

где `unique_categories(s)` — число уникальных категорий в `I_s`.

- `bias = 1.0` — источник пишет только об одной теме (узкий специалист или бот-ферма).
- `bias → 0` — источник пишет обо всём (зашумлённый агрегатор).

**3. Item count (объём):**

**item_count(s) = |I_s|**

Малое значение (< 5) означает, что профиль ненадёжен.

**Почему `Set` для категорий:**

`Set` — структура данных с проверкой уникальности за O(1). Это эффективный способ убрать дубликаты категорий перед подсчётом.

**Принцип «follow the latency»:**

Источники с низкой задержкой обычно первыми публикуют важные новости. Это может означать, что они «ближе к событию» — имеют инсайдерскую информацию или работают быстрее. Высокая задержка — источник «перерабатывает» новости, добавляет контекст, но опаздывает.

**Ограничения:**

- `Date.now()` делает вычисления динамическими: профиль меняется в реальном времени. При повторном запросе через час — другие числа.
- `item_count` показывает объём выборки. Профиль по одной новости — ненадёжен.
- `bias` на основе категорий — грубая метрика. Категории могут быть неполными (много `general`).

## Как работает (пошагово)

1. `calculateSourceMetrics(sourceName, items)` принимает имя источника и массив его статей.
2. Вычисляет `latency_hours` — среднее время между `published_at` и `now`.
3. Вычисляет `bias_score` — `1 / unique_categories`.
4. Вычисляет `item_count` — длину массива.
5. Возвращает объект: `{ source, latency_hours, bias_score, item_count }`.

**Формат ответа:**

```json
{
  "source": "ТАСС",
  "latency_hours": 2.5,
  "bias_score": 0.33,
  "item_count": 42
}

Интерпретация:

    latency_hours = 2.5 — источник публикует с задержкой 2.5 часа. Быстрый.

    bias_score = 0.33 — пишет о 3 уникальных темах. Средняя специализация.

    item_count = 42 — достаточно данных для надёжного профиля.

Пример использования
javascript

import { calculateSourceMetrics } from './scripts/analyzers/source-profiler.mjs';

const newsArray = await processRSSFeed('/api/rss-feed/');

// Профиль для одного источника
const metrics = calculateSourceMetrics('ТАСС', newsArray.filter(n => n.source === 'ТАСС'));
console.log(metrics);
// { source: 'ТАСС', latency_hours: 2.5, bias_score: 0.33, item_count: 42 }

// Профили для всех источников
const sources = [...new Set(newsArray.map(n => n.source))];
const profiles = sources.map(s => calculateSourceMetrics(s, newsArray.filter(n => n.source === s)));
console.log(profiles);

Что происходит:

    Для источника «ТАСС» вычисляется задержка (2.5 часа), смещение (0.33), объём (42 статьи).

    Эти данные можно сохранить в БД (таблица sources) для долгосрочного мониторинга.

    Можно отсортировать источники по latency — самые быстрые первыми.

    Можно отсортировать по bias — самые узкие первыми.

Практические рекомендации

    Данные напрямую попадают в таблицу sources — для долгосрочного мониторинга. Обновляйте раз в сутки.

    Без профилировщика общий индекс строится на шуме: сложно отличить быстрый авторитетный источник от медленного агрегатора.

    Принцип «follow the latency» — кто первый сообщил, тот, вероятно, знал заранее. Это не всегда так, но полезная эвристика.

    bias_score — не «предвзятость» в смысле «врёт». Это «узость специализации». Источник с bias = 1.0 может быть экспертом, а может — ботом.

    item_count < 5 — профиль ненадёжен. Не делайте выводов по малым выборкам.

    Date.now() — динамические вычисления. Профиль меняется в реальном времени. Не кешируйте надолго.

    Для долгосрочного мониторинга — сохраняйте профили в БД с меткой времени. Тогда можно отслеживать тренды: «источник стал быстрее», «источник стал шире».

    latency_hours — не всегда «плохо». Медленный источник может быть аналитическим, с контекстом. Быстрый — новостным, без контекста.

    Комбинируйте с source-coordination-api.mjs — если источник быстрый и синхронный с другими, это сильный сигнал координации.

    Не используйте bias как единственный критерий. Источник может быть узким, но авторитетным (например, отраслевое издание).

    item_count — не показатель качества. Источник может иметь 1000 статей, но все — низкого качества.

    Для отчётов — переводите latency_hours в минуты для малых значений. 0.5 часа = 30 минут — понятнее, чем «0.5».
