# Граф RSS-связей: rss-graph.js

## Простое объяснение (для новичков)

Этот файл — «паутина смыслов». Он рисует граф, где узлы — это источники и темы, а связи — это то, как часто они появляются вместе. Узлы «отталкиваются» друг от друга, а связи «притягивают». В результате граф самоорганизуется: связанные узлы держатся вместе, несвязанные — разъезжаются по углам.

**Что он делает:**

1. **Запрашивает данные** у API `/api/layers/articles?limit=500`.
2. **Строит узлы** — источники (ТАСС, Reuters, ...) и темы (энергетика, кибер, ...).
3. **Строит связи** — если источник пишет о теме, между ними появляется связь.
4. **Запускает force-симуляцию** — узлы «отталкиваются», связи «притягивают». Граф «успокаивается» за несколько секунд.
5. **Добавляет интерактивность** — узлы можно перетаскивать мышью.

**Как читать граф:**

- Узлы в одной куче — источники, которые пишут об одном и том же.
- Узлы в разных углах — источники, которые пишут о разном.
- Толстая связь — сильная связь (много общих тем).
- Тонкая связь — слабая связь (мало общих тем).

**Зачем это нужно:**

Вы сразу видите «эхо-камеры»: если группа источников всегда в одной куче, а другая — в другой, это визуальное доказательство двух информационных миров. Без чтения текстов.

**Аналогия:**

Это как карта друзей в социальной сети. Люди, которые общаются друг с другом, — рядом. Люди из разных компаний — в разных углах. Граф показывает структуру связей, а не содержание разговоров.

## Научная база (для специалистов)

Виджет реализует визуализацию **force-directed graph** на D3.js. Это стандартный метод визуализации сетевых структур, основанный на физической симуляции.

**Архитектура:**

- **Библиотека:** D3.js v7.9.0 (локально, `lib/d3.min.js`).
- **Тип графа:** force-directed. Узлы — «магниты», связи — «пружины».
- **Силы:**
  - `forceLink` — притягивает связанные узлы на расстоянии `distance`.
  - `forceManyBody` — расталкивает все узлы (сила `-500`).
  - `forceCenter` — удерживает граф в центре экрана.
  - `forceCollide` — предотвращает наложение узлов.
- **Холст:** SVG. 960×600 — стандарт для академических дашбордов.
- **Tick-симуляция:** ~60 раз в секунду пересчитываются позиции узлов. Граф «успокаивается» за несколько секунд.

**Почему force-directed:**

Это единственный способ визуализировать 100+ узлов так, чтобы выделить кластеры. Альтернативы (дерево, матрица) не дают интуитивного понимания структуры. Force-directed граф «самоорганизуется»: плотные группы видны сразу.

**Формально:**

Сила притяжения между узлами `i` и `j`:

**F_attract(i, j) = k · (d(i, j) - L)**

где `k` — жёсткость пружины, `d(i, j)` — текущее расстояние, `L` — желаемое расстояние.

Сила отталкивания:

**F_repel(i, j) = -k' / d(i, j)²**

где `k'` — сила отталкивания.

Сумма сил определяет ускорение узла. На каждом `tick` позиции обновляются.

**Формат данных:**

```json
{
  "nodes": [
    { "id": "ТАСС", "group": "russian" },
    { "id": "Reuters", "group": "western" },
    { "id": "энергетика", "group": "topic" }
  ],
  "links": [
    { "source": "ТАСС", "target": "энергетика", "value": 15 },
    { "source": "Reuters", "target": "энергетика", "value": 3 }
  ]
}

Ограничения:

    При 1000+ узлах браузер начинает тормозить. Для больших графов — Canvas или WebGL.

    Force-directed граф нестабилен: при каждом запуске узлы могут располагаться по-разному. Это не баг — это свойство симуляции.

    forceCollide нужен, чтобы узлы не накладывались. Без него граф «схлопывается» в точку.

Как работает (пошагово)

    При загрузке страницы (DOMContentLoaded) вызывается mountRssGraph().

    mountRssGraph() находит контейнер по id (по умолчанию 'rss-graph').

    Отправляет fetch('/api/layers/articles?limit=500').

    Получает JSON, извлекает data.items.

    Строит узлы: уникальные источники и темы из статей.

    Строит связи: для каждой статьи — связь «источник → тема».

    Создаёт d3.forceSimulation(nodes).

    Добавляет силы: forceLink, forceManyBody, forceCenter, forceCollide.

    Рисует линии (связи) и круги (узлы).

    На каждом tick пересчитывает позиции.

    Добавляет drag-handlers: узлы можно перетаскивать мышью.

Структура SVG:
html

<svg viewBox="0 0 960 600">
  <!-- Связи -->
  <line x1="..." y1="..." x2="..." y2="..." stroke="#555" />
  <!-- Узлы -->
  <circle cx="..." cy="..." r="10" fill="#3b82f6">
    <title>ТАСС</title>
  </circle>
</svg>

Пример использования

В HTML-странице:
html

<div id="rss-graph"></div>
<script type="module" src="/widgets/rss-graph.js"></script>

В другом виджете (программно):
javascript

import { mountRssGraph } from '/widgets/rss-graph.js';

mountRssGraph('my-graph-container');

Что появится на экране:

    Граф 960×600.

    Узлы: источники (синий), темы (зелёный).

    Связи: линии между узлами.

    При наведении на узел — подсказка с ID.

    При перетаскивании — узел «отцепляется» и следует за мышью.

Практические рекомендации

    distance: 100 — жёсткость «пружины». Чем больше — тем дальше узлы друг от друга. Для плотных графов — уменьшайте.

    strength: -500 — сила расталкивания. Чем больше по модулю — тем сильнее узлы отталкиваются. Для больших графов — увеличивайте.

    forceCollide().radius(40) — предотвращает наложение. Без него узлы «схлопываются» в точку.

    width: 960, height: 600 — стандарт для академических дашбордов. Не меняйте без необходимости.

    Drag-handlers — позволяют вручную распутать граф. Это важно для сложных участков.

    viewBox — 0 0 960 600. Позволяет масштабировать SVG без потери качества.

    Ограничение на количество узлов — 100–200. При большем количестве браузер тормозит. Для больших графов — Canvas или WebGL.

    forceSimulation нестабилен — при каждом запуске узлы могут располагаться по-разному. Это не баг — это свойство симуляции.

    tick-события — обновляют позиции 60 раз в секунду. Не добавляйте тяжёлые операции в tick — это замедлит граф.

    Цветовая кодировка — russian (синий), western (красный), topic (зелёный). Интуитивно.

    Не используйте forceLink без id — d3.forceLink(links).id(d => d.id). Иначе граф не построится.
