================================================================================
CRUCIX — NETWORK MAP — СПРАВКА
================================================================================
Версия карты: 1.0
Дата справки: 2026-09-30
Раздел: Network Map (relations)
Тип карты: граф связей
================================================================================

Network Map — интерактивная карта связей между сущностями (странами,
организациями, событиями, финансовыми структурами). Отображает граф в
force-directed виде на чистом SVG, без использования Leaflet.

Карта — одна из 5 автономных карт экосистемы Crucix:

  1. Event Map     — точечные события на географической карте.
  2. Metrics Map   — числовые индикаторы по странам (choropleth).
  3. Semantic Map  — семантический анализ текстов.
  4. Network Map   — граф связей (ЭТА КАРТА).
  5. Forecast Map  — вероятностные прогнозы.

Каждая карта автономна. Данные между картами не пересекаются — разные
модели данных, разные единицы измерения, разные способы визуализации.
Network Map работает с графами: узлы + рёбра. Events — с точками.
Metrics — с числами по странам.

================================================================================
1. НАЗНАЧЕНИЕ КАРТЫ
================================================================================

1.1. Что визуализирует Network Map

Network Map показывает граф связей между сущностями. Примеры связей:

  - кибер-атаки (страна → APT → C2-сервер → ботнет → цель);
  - торговые пути (страна-экспортёр → порт → страна-импортёр);
  - финансовые потоки (юрисдикция → банк → юрисдикция);
  - миграционные коридоры (страна-источник → транзит → страна-назначения);
  - социальные связи (очаг протеста → распространение → очаг).

Каждый слой — свой граф. Всего 12 слоёв в 2 категориях:

  Категория "flow" (7 слоёв):
    🕸️ cyber-network            — Кибер-сеть
    📦 trade-routes              — Торговые пути
    💰 financial-flows           — Финансовые потоки
    ₿  crypto-trace              — Трассировка крипто
    🏦 banking-network           — Банковская сеть
    ⛓️  supply-chain              — Цепочки поставок
    🏢 shell-companies           — Шелл-компании

  Категория "social" (5 слоёв):
    🏃 refugee-flows             — Потоки беженцев
    🚶 migration-network         — Миграционная сеть
    🔥 social-unrest             — Очаги напряжённости
    📞 phone-network             — Телефонная сеть
    📱 social-media-network      — Соцсети

1.2. Как устроен граф

Каждый граф состоит из двух частей:

  УЗЛЫ (nodes) — сущности 4 типов:
    ● circle     — страна (country)         #58a6ff (синий)
    ■ square     — организация (organization) #f0883e (оранжевый)
    ▲ triangle   — событие (event)          #f85149 (красный)
    ◆ diamond    — финансовый (financial)   #3fb950 (зелёный)

  РЁБРА (edges) — связи 4 типов:
    flow         — поток (сплошная, широкая)
    transaction  — транзакция (сплошная, зелёная)
    control      — управление (пунктирная, оранжевая)
    influence    — влияние (пунктирная, фиолетовая)

У каждого ребра есть вес (weight). Чем толще ребро — тем сильнее связь.

1.3. Что показывает каждый тип узла

Узел описывается полями:

  id      — уникальный идентификатор (RU, US, C2-1, APT-28)
  label   — человекочитаемое название (Россия, США)
  type    — тип: country, organization, event, financial
  weight  — начальный вес (по умолчанию 1)
  x, y    — координаты на SVG (обновляются force-симуляцией)
  vx, vy  — скорость (для симуляции)

Типы:
  country      — страна. Узлы: RU, US, CN, KP, IR, UA, BY.
  organization — организация. Узлы: C2-1, C2-2, C2-3, BOT-1, BOT-2,
                  BOT-3, APT-28, APT-29, Lazarus.
  event        — событие. Узлы: Victim-EU, Victim-US, Victim-UA,
                  Phish-1.
  financial    — финансовый узел (пока не используется в demo).

1.4. Что показывает каждое ребро

Ребро описывается полями:

  source  — ID узла-источника
  target  — ID узла-назначения
  type    — тип связи: flow, transaction, control, influence
  weight  — вес (1–5)

Пример: RU → C2-1, type=control, weight=3.
"Россия управляет C2-сервером №1 с весом 3."

1.5. Что можно делать

  - переключать 12 слоёв (flow + social);
  - фильтровать маркеры по слоям;
  - включать Louvain-сообщества (6 групп);
  - менять размер узла по 5 метрикам;
  - включать heatmap по метрике (5 цветов);
  - искать узел по подстроке;
  - подсвечивать путь A → B (BFS);
  - экспортировать граф в SVG или PNG;
  - копировать полный снапшот состояния (~105 КБ) в буфер обмена;
  - сохранять позиции узлов между сессиями.

2.5. Карта (SVG-граф, центр экрана)

Force-directed граф на чистом SVG. Без Leaflet.

Силы, действующие на узлы:
  - Coulomb repulsion (отталкивание): F = k / r².
  - Hooke attraction (притяжение по рёбрам): F = (d − L) × 0.1.
  - Gravity (притяжение к центру): слабое.
  - Verlet integration (интеграция по времени).

Узлы рисуются 4 формами:
  Страна       — ● circle   (радиус 18 px)
  Организация  — ■ square   (14×14 px)
  Событие      — ▲ triangle (26×26 px)
  Финансовый   — ◆ diamond  (16×16 px)

Рёбра — линии. Пунктирные, если type=control или influence.

3. КНОПКИ УПРАВЛЕНИЯ
================================================================================

3.1. 🔄 Сброс (graph-controls)

Назначение: сброс позиций узлов на исходные случайные.

Действие:
  1. Все узлы получают новые случайные координаты в центре карты.
  2. Force-симуляция перезапускается.
  3. Позиции в localStorage обнуляются.

Когда использовать:
  - если узлы «слиплись» после долгой симуляции;
  - если нужно заново разложить граф;
  - при переходе на другой слой.

3.2. 🔍+ / 🔍− (graph-controls)

Увеличение / уменьшение масштаба SVG-графа.

  🔍+  →  увеличение в 1.3 раза (зум 1.3×).
  🔍−  →  уменьшение в 0.77 раза (зум 0.77×).

Точка зума — центр SVG. Изменения через transform: scale.

3.3. 💾 SVG (graph-controls)

Скачать граф в формате SVG.

Файл: network-<layerId>-<timestamp>.svg.

Содержимое: вся SVG-структура (узлы, рёбра, подписи).
Элементы .dimmed (приглушённые) при экспорте восстанавливаются.

Формат: XML, image/svg+xml. Открывается в Illustrator, Inkscape, Figma.

3.4. 🖼️ PNG (graph-controls)

Скачать граф в формате PNG.

Файл: network-<layerId>-<timestamp>.png.

Процесс:
  1. SVG сериализуется.
  2. Растеризуется через <canvas> в 2× масштабе.
  3. Фон заливается #0a0a0f (тёмный).
  4. Файл сохраняется через canvas.toBlob.

Разрешение: примерно 2× от размеров SVG (~1800×1040 px).

3.5. 🎨 Сообщества (graph-controls)

Назначение: визуализация сообществ по алгоритму Louvain.

Первый клик — включение:
  1. Запускается Louvain на текущем графе.
  2. Каждый узел окрашивается по своему сообществу (6 цветов).
  3. В легенде появляется блок «Сообщества (Louvain)».
  4. Кнопка подсвечивается синим.
  5. Показывается уведомление: Сообществ: 6 (Q=0.54).

Повторный клик — выключение:
  1. Узлы возвращаются к цветам по типу.
  2. Блок «Сообщества (Louvain)» в легенде исчезает.
  3. Кнопка гаснет.

Палитра (10 цветов, используются первые 6):
  Сообщество 0 — #58a6ff (синий)
  Сообщество 1 — #3fb950 (зелёный)
  Сообщество 2 — #f0883e (оранжевый)
  Сообщество 3 — #a371f7 (фиолетовый)
  Сообщество 4 — #f85149 (красный)
  Сообщество 5 — #e3b341 (жёлтый)

3.6. 📊 Метрики (graph-controls)

Назначение: изменить размер узла по выбранной метрике.

Циклическое переключение при каждом клике:
  1. null → Degree
  2. Degree → Betweenness
  3. Betweenness → Closeness
  4. Closeness → PageRank
  5. PageRank → Eigenvector
  6. Eigenvector → null (сброс)

Размер узла: min=8 px, max=32 px.
  Малые значения метрики → маленький узел.
  Большие значения метрики → большой узел.

Рядом с кнопкой — метка текущей метрики:
  Degree (0.17–1.00), Betweenness (0.00–1.00),
  Closeness (0.38–1.00), PageRank (0.14–1.00),
  Eigenvector (0.00–1.00).

Пример:
  При Degree: C2-1 = огромный узел, US / IR / UA / BY = крошечные.
  При PageRank: Victim-EU = огромный, BOT-1 = средний, C2-1 = средний.
  При Eigenvector: C2-1 = огромный, BOT-1 = средний, KP = средний.

3.7. 🌡️ Тепловая (топбар)

Назначение: heatmap по выбранной метрике.

Метрика берётся из 📊 Метрики. Если метрика не выбрана — PageRank
по умолчанию.

Первый клик — включение:
  1. Каждый узел окрашивается в 1 из 5 heat-цветов по значению.
  2. В легенде появляется блок «🌡️ <метрика>» с 5 диапазонами.
  3. Кнопка подсвечивается красным.
  4. Показывается уведомление: Heatmap: PageRank (0.14–1.00).

Повторный клик — выключение:
  1. Узлы возвращаются к цветам по типу.
  2. Блок «🌡️» в легенде исчезает.
  3. Кнопка гаснет.

Палитра heatmap (5 цветов):
  #1f77b4 — синий (min … 20 %)
  #4ec4ff — голубой (20 … 40 %)
  #7ee787 — зелёный (40 … 60 %)
  #f0c33c — жёлтый (60 … 80 %)
  #f85149 — красный (80 … 100 %, max)

Пример (PageRank, диапазон 0.14–1.00):
  Victim-EU (1.00)       → красный
  BOT-1 (0.62)           → жёлтый
  C2-1 (0.57)            → зелёный
  BOT-2 (0.38)           → голубой
  BY (0.14)              → синий

3.11. 📄 PDF (топбар)

3.12. Поиск узла (graph-controls)

Input для поиска узла по подстроке.

Поиск идёт по:
  - id (RU, C2-1);
  - label (Россия, C2 Server #1);
  - type (country, organization).

Поведение:
  - Совпадения подсвечиваются (класс highlighted).
  - Несовпадения приглушаются (класс dimmed).
  - Поле подсвечивается зелёным, если есть совпадения.
  - Поле подсвечивается красным, если нет.

Пример: «C2» → подсветятся C2-1, C2-2, C2-3.

3.13. Path-поиск От → До (graph-controls)

Назначение: найти кратчайший путь между двумя узлами (BFS).

Как работает:
  1. В поле «От» — ID или label начального узла.
  2. В поле «До» — ID или label конечного узла.
  3. Кнопка → — запускает поиск.
  4. Узлы на пути подсвечиваются (highlighted).
  5. Остальные — приглушаются (dimmed).
  6. Рёбра пути — толстые, выделенные.
  7. Уведомление: Путь: RU → C2-1 → BOT-1.

Пример: RU → Victim-US.
  Путь: RU → APT-28 → C2-2 → BOT-2 → Victim-US (5 шагов).

================================================================================
4. МЕТРИКИ (9 АЛГОРИТМОВ)
================================================================================

Каждая метрика — отдельный алгоритм анализа графа. Метрики вычисляются
автоматически при запросе (кнопка 📊 Метрики, попап узла, снапшот).

Все значения нормализованы в диапазон [0, 1].

4.1. Degree Centrality (Степенная центральность)

Что показывает: сколько связей у узла.

Формула:
  C_deg(v) = deg(v) / max(deg)

где deg(v) — число связей узла v (входящие + исходящие).

Интерпретация:
  - Высокий Degree — «популярный» узел.
  - Низкий Degree — периферийный узел.

Применение в OSINT:
  - Хаб сети (много связей).
  - Точка концентрации активности.

Топ в текущем графе (20 узлов):
  1. C2-1       — 1.0000 (6 связей)
  2. APT-28     — 0.6667 (4 связи)
  3. Victim-EU  — 0.5000 (3 связи)
  4. BOT-1      — 0.5000 (3 связи)

4.2. Betweenness Centrality (Посредничество)

Что показывает: через сколько кратчайших путей проходит узел.

Формула:
  C_bet(v) = Σ_{s≠v≠t} σ_st(v) / σ_st

где σ_st — число кратчайших путей от s к t,
    σ_st(v) — число кратчайших путей через v.

Алгоритм: Brandes 2001, сложность O(VE).

Интерпретация:
  - Высокий Betweenness — узел-посредник.
  - Низкий Betweenness — узел на периферии.

Применение в OSINT:
  - Единая точка отказа (single point of failure).
  - Ключевой маршрут передачи данных.

Топ в текущем графе:
  1. C2-1       — 1.0000 (посредник между странами и ботнетами)
  2. CN         — 0.6009
  3. APT-29     — 0.5150
  4. BOT-1      — 0.5107

4.3. Closeness Centrality (Близость)

Что показывает: насколько узел близок ко всем остальным.

Формула:
  C_clo(v) = (N − 1) / Σ_{u≠v} d(v, u)

где d(v, u) — кратчайшее расстояние между v и u.

Алгоритм: BFS от каждого узла, сложность O(V(V+E)).

Интерпретация:
  - Высокий Closeness — «в центре» сети.
  - Низкий Closeness — далеко от всех.

Применение в OSINT:
  - Быстрый доступ к любой точке сети.
  - Оптимальный старт для распространения.

Топ в текущем графе:
  1. C2-1       — 1.0000
  2. BOT-1      — 0.8704
  3. CN         — 0.8545
  4. RU         — 0.8393

4.4. Louvain Community Detection (Сообщества)

Что показывает: разбиение графа на сообщества.

Алгоритм: Blondel et al. 2008.

Метрика качества: модульность Q.

Формула модульности:
  Q = (1 / 2m) × Σ_ij [A_ij − k_i k_j / (2m)] × δ(c_i, c_j)

где m — сумма весов рёбер,
    A_ij — вес ребра между i и j,
    k_i, k_j — степени узлов,
    c_i, c_j — сообщества узлов,
    δ — символ Кронекера.

Интерпретация модульности Q:
  - Q < 0.30 — слабая структура.
  - Q 0.30–0.50 — умеренная.
  - Q > 0.50 — сильная структура.

Текущий результат:
  Сообществ: 6.
  Модульность Q: 0.5404 (сильная структура).

Сообщества:
  [0] C2-2, BOT-2
  [1] RU, BY, APT-28, Phish-1
  [2] CN, C2-3, APT-29
  [3] KP, IR, C2-1, Lazarus
  [4] US, BOT-1, Victim-EU, Victim-US
  [5] UA, BOT-3, Victim-UA

Применение в OSINT:
  - Выявление «кланов» в сети.
  - Понимание структуры группировок.

4.5. PageRank (Brin & Page 1998)

Что показывает: важность узла по числу и качеству входящих связей.

Формула:
  PR(v) = (1 − d) / N + d × Σ_{u → v} PR(u) / L(u)

где d = 0.85 — damping factor,
    N — число узлов,
    L(u) — число исходящих связей u.

Алгоритм: итеративный, сложность O(E × iterations).

Интерпретация:
  - Высокий PageRank — узел, на который ссылаются многие.
  - Низкий PageRank — узел без входящих ссылок.

Применение в OSINT:
  - Топ целей атаки (жертвы получают много входящих рёбер).
  - Ключевые узлы для атаки.

Топ в текущем графе:
  1. Victim-EU       — 1.0000 (3 входящих)
  2. BOT-1           — 0.6239
  3. Victim-UA       — 0.6203
  4. C2-1            — 0.5685

Параметры:
  damping = 0.85, maxIter = 100, tolerance = 1e-6.
  Сходимость: 23 итерации.

4.6. Eigenvector Centrality (Bonacich 1972)

Что показывает: важность узла по важности его соседей.

Формула:
  A × x = λ × x

где A — матрица смежности,
    x — вектор центральности,
    λ — собственное значение.

Алгоритм: степенной метод (power iteration).
  x_{k+1} = A × x_k / ||A × x_k||

Параметры:
  maxIter = 500, tolerance = 1e-6.
  Сходимость: 134 итерации.

Особенность:
  В двудольных графах строгая сходимость невозможна
  (собственные значения ±λ). Значения всё равно стабилизируются.

Интерпретация:
  - Высокий Eigenvector — узел, связанный с важными узлами.
  - Низкий Eigenvector — узел в изоляции.

Применение в OSINT:
  - Скрытые акторы (связаны с центром, но не в центре).
  - Например, KP — ранг 3 при низком Degree.

Топ в текущем графе:
  1. C2-1            — 1.0000
  2. BOT-1           — 0.8376
  3. KP              — 0.6635
  4. Lazarus         — 0.5992

4.7. Clustering Coefficient (Watts & Strogatz 1998)

Что показывает: насколько соседи узла соединены между собой.

Локальный коэффициент:
  C_i = 2 × E_i / (k_i × (k_i − 1))

где E_i — число рёбер между соседями i,
    k_i — число соседей i.

Глобальный коэффициент:
  C = (1 / N) × Σ C_i

Транзитивность (Watts-Strogatz):
  T = 3 × triangles / closed_triples

Текущий результат:
  Global clustering: 0.1033.
  Transitivity: 0.0769.
  Triangles: 3.

Интерпретация:
  < 0.10 — низкая кластеризация (деревья, иерархии).
  0.10–0.30 — умеренная.
  > 0.30 — высокая (плотные кланы).

Применение в OSINT:
  - Двудольные графы (страны → APT → C2 → жертвы) дают низкий
    clustering. Это норма для иерархических сетей.
  - Высокий clustering — «кланы» (например, все страны знают друг друга).

Топ-3 локальных:
  1. KP              — 1.0000 (все соседи соединены)
  2. Lazarus         — 1.0000
  3. C2-1            — 0.0667

4.8. Network Diameter (Диаметр сети)

Что показывает: максимальное кратчайшее расстояние между узлами.

Диаметр:
  D = max_{u, v} d(u, v)

Средняя длина пути:
  L = (1 / (N(N−1))) × Σ_{u ≠ v} d(u, v)

Алгоритм: BFS от каждого узла, сложность O(V(V+E)).

Текущий результат:
  Диаметр: 9.
  Средняя длина пути: 3.8421.
  Пар проанализировано: 380 (20 × 19).

Интерпретация:
  - Компактный граф — диаметр < 5.
  - Разреженный граф — диаметр > 7, есть периферия.

Эксцентриситет узла:
  e(v) = max_u d(v, u)

Топ-5 центральных (низкий ecc):
  CN = 5, APT-29 = 5, C2-1 = 6, C2-3 = 6, RU = 7.

Топ-5 периферийных (высокий ecc):
  Phish-1 = 9, BOT-2 = 9, C2-2 = 9, BY = 9, UA = 9.

Применение в OSINT:
  - Периферийные узлы — потенциальные точки входа.
  - Центральные узлы — контрольные точки.

4.9. Assortativity (Newman 2002)

Что показывает: смешиваются ли узлы одного типа между собой.

Формула:
  r = (Σ e_ii − Σ a_i²) / (1 − Σ a_i²)

где e_ii — доля рёбер внутри типа i,
    a_i — доля концов рёбер типа i.

Диапазон: [−1, +1].
  +1 — полная ассортативность (однотипные соединяются).
   0 — случайное смешение.
  −1 — полная диссортативность (разнотипные соединяются).

Текущий результат:
  Коэффициент: −0.3390.
  Вывод: диссортативность (иерархия).

Матрица смешения типов:
                country  organization  event
  country             0            27      7
  organization       27            21     19
  event               7            19      2

Интерпретация:
  - Страна ↔ страна = 0 — страны НИКОГДА не соединяются напрямую.
  - Страна ↔ организация = 27 — основной поток.
  - Организация ↔ организация = 21 — есть внутренние связи.
  - Организация ↔ событие = 19.
  - Событие ↔ событие = 2 — почти нет.

Применение в OSINT:
  - Иерархическая структура (страна → организация → событие).
  - Диссортативность — стандарт для кибер-графов.

  {

5.4. Как формируется демо-граф

Демо-графы хранятся в файле js/network-adapter.js внутри функции
generateDemo(layerId). Для каждого слоя определён свой набор узлов
и рёбер.

Если API-эндпоинт /api/layers/<layerId> не отвечает (404 или timeout),
карта использует демо-граф. Это единственный режим работы в offline.

Важно: в demo-графах узлы «страна» реальные (RU, US, CN, KP, IR, UA, BY),
но организации и события — синтетические (C2-1, APT-28, BOT-1,
Victim-EU). Это учебные данные для демонстрации алгоритмов.

  ...

Применение: Excel, Google Sheets, R, Python (pandas).

5.6. Матрица смежности

Для N узлов — матрица N × N. Элемент [i][j] = вес ребра i → j.

Пример (первые 5 строк для 20 узлов):
             RU  US  CN  KP  IR  UA  BY  C2-1 ...
  RU          0   0   0   0   0   0   0    3 ...
  US          0   0   0   0   0   0   0    0 ...
  CN          0   0   0   0   0   0   0    2 ...
  KP          0   0   0   0   0   0   0    4 ...
  IR          0   0   0   0   0   0   0    1 ...

Матрица симметрична (неориентированный граф):
  matrix[i][j] = matrix[j][i].

Плотность: 44 направленных пары из 380 возможных = 11.58 %.

6.7. Автономность (R1–R6)

Network Map — автономная карта. Принципы:

  R1. Ноль cross-map зависимостей.
      Никакие скрипты Network Map не обращаются к файлам соседних карт.
      grep -rn '\.\./' js/ blocks/ → пусто (кроме навигационных ссылок).

  R2. Локальный world.geojson.
      Файл data/world.geojson (~250 КБ) лежит в папке карты.
      Fetch идёт через fetch('data/world.geojson') — относительно карты.

  R3. Свои 12 слоёв.
      Ровно 12 слоёв, ID уникальны. Ни одного чужого.
      grep -c 'id:' js/layers.js → 12.

  R4. Свои maps-config.js и presets.json.
      Конфигурация и пресеты — локальные.

  R5. manifest.json → local_cross_map: 0, failure_domain: 1.
      Паспорт карты подтверждает автономность.

  R6. Сбой в Network Map не влияет на 4 остальные.
      Failure domain = 1. Проверяется через throw new Error('test')
      в консоли Network Map — соседние карты продолжают работу.

6.8. Что делает карта без сервера

Network Map работает полностью offline:

  1. HTML, JS, CSS загружаются с диска.
  2. world.geojson загружается из data/.
  3. API-эндпоинты /api/layers/* дают 404.
  4. Fallback: используется демо-граф из js/network-adapter.js.
  5. Все алгоритмы работают (Louvain, PageRank, Eigenvector).
  6. Экспорт SVG/PNG работает.
  7. Кнопка КОПИРОВАТЬ работает.
  8. Справка HELP работает (файл docs/help/ru/network-map.txt).
  9. Сохранение позиций узлов в localStorage.

Причина: вся логика карты — в JS-файлах. API — только источник данных.
Если данных нет, demo-графы дают полную картину для демонстрации.

7.3. Глоссарий

Термин              Определение
------------------  ---------------------------------------------------------
Узел (node)         Вершина графа. В Network Map — страна, организация,
                    событие или финансовая сущность. Имеет id, label, type,
                    weight, координаты x/y.

Ребро (edge)        Связь между двумя узлами. Имеет source, target, type,
                    weight. Направление: source → target.

Граф (graph)        Совокупность узлов и рёбер. В Network Map — один из
                    12 слоёв.

Слой (layer)        Отдельный граф. Всего 12 слоёв, разделены на категории
                    flow (7) и social (5).

Степень (degree)    Количество рёбер, инцидентных узлу. В неориентированном
                    графе — сумма входящих и исходящих.

Центральность       Мера важности узла в графе. В Network Map — 3 вида:
(centrality)        degree, betweenness, closeness.

Betweenness         Центральность посредничества. Показывает, насколько
centrality          часто узел лежит на кратчайших путях между другими
                    узлами. Высокая betweenness = «мост» между сообществами.

Closeness           Центральность близости. Обратная сумма кратчайших
centrality          расстояний от узла до всех остальных. Высокая closeness =
                    узел «близко» ко всем.

Louvain             Алгоритм обнаружения сообществ (Blondel et al. 2008).
                    Разбивает граф на сообщества, максимизируя модульность Q.
                    Сложность O(n log n).

Сообщество          Группа узлов, которые плотно связаны между собой и
(community)         слабо — с остальным графом. Результат Louvain.

Модульность (Q)     Метрика качества разбиения на сообщества. Q ∈ [−0.5, 1].
                    Q > 0.3 — хорошее разбиение. Q > 0.5 — отличное.

PageRank            Алгоритм ранжирования узлов по «влиянию» (Page & Brin,
                    1998). Используется Google. Итеративный: вес узла
                    распределяется между соседями.

Eigenvector         Центральность собственного вектора. Узел важен, если
centrality          важны его соседи. Рекурсивное определение.

Clustering          Коэффициент кластеризации. Показывает, насколько соседи
coefficient         узла связаны между собой. C ∈ [0, 1].
                    Локальный — для узла, глобальный — для графа.

Транзитивность      Глобальный clustering coefficient. Отношение числа
(transitivity)      треугольников к числу «троек» (paths длины 2).

Диаметр графа       Максимальное кратчайшее расстояние между любыми двумя
(diameter)          узлами. Показывает «размер» графа.

Средний путь        Среднее кратчайшее расстояние между всеми парами узлов.
(avg path length)   Характеризует «компактность» графа.

Ассортативность     Склонность узлов соединяться с похожими (по степени).
(assortativity)     Положительная — «богатые с богатыми». Отрицательная —
                    «богатые с бедными». В cyber-network ожидается
                    отрицательная.

Матрица смежности   Таблица N × N, где элемент [i][j] = вес ребра i → j.
(adjacency matrix)  Симметрична для неориентированного графа.

Плотность           Отношение числа рёбер к максимально возможному.
(density)           density = m / (n·(n−1)). В cyber-network ~11.58 %.

DOT                 Формат Graphviz для описания графов. Используется для
                    импорта в Gephi, yEd, Graphviz.

D3 JSON             Формат JSON с полями nodes и links. Используется для
                    импорта в D3.js, Cytoscape.js, Sigma.js.

CSV                 Comma-Separated Values. Табличный формат для Excel,
                    Google Sheets, R, Python (pandas).

Force-симуляция     Алгоритм раскладки узлов на плоскости. Узлы отталкиваются
(force-directed)    (charge), рёбра притягиваются (link distance).

Reheat              Перезапуск force-симуляции с текущими позициями.
                    Используется, если граф «застыл» в неоптимальной форме.

DOM-слепок          Снимок DOM-дерева с координатами, размерами и цветами
(DOM snapshot)      элементов. Включает до 500 элементов.

Снапшот             Полный дамп состояния карты: граф, метрики, конфигурация,
(snapshot)          DOM, стили, экспорт. Кнопка КОПИРОВАТЬ.

Маркер (marker)     Точка на карте Leaflet. В Network Map — 106 маркеров
                    для 12 слоёв.

vizType             Тип визуализации слоя: graph (SVG-граф), flow (потоки),
                    marker (точки на карте).

Категория слоя      flow (7 слоёв: кибер, торговля, финансы, крипто,
(category)          банки, поставки, шелл) или social (5 слоёв: беженцы,
                    миграция, протесты, телефония, соцсети).

Автономность        Принцип: карта работает без сервера и без других карт.
(autonomy)          R1–R6 — правила автономности.

Failure domain      Область отказа. Для Network Map = 1 (только эта карта).

Cross-map           Зависимость от других карт. Для Network Map = 0.

7.4. Часто задаваемые вопросы (FAQ)

Q: Почему граф маленький — всего 20 узлов?
A: Это демо-граф. При подключении API /api/layers/cyber-network граф
   расширится до реальных данных. Демо-граф предназначен для демонстрации
   алгоритмов и работы offline.

Q: Почему узлы «дрожат»?
A: Это force-симуляция. Узлы отталкиваются, рёбра притягиваются. Нажмите
   Space для паузы или R для перезапуска.

Q: Как сохранить позиции узлов?
A: Клавиша S — сохранить в localStorage. Клавиша L — загрузить. Клавиша X —
   сбросить.

Q: Как экспортировать граф в Gephi?
A: Нажмите КОПИРОВАТЬ, найдите секцию DOT-ФОРМАТ, сохраните в файл .dot,
   откройте в Gephi через File → Open.

Q: Как экспортировать граф в Excel?
A: Нажмите КОПИРОВАТЬ, найдите секции CSV: УЗЛЫ и CSV: СВЯЗИ, сохраните
   в файлы .csv, откройте в Excel.

Q: Что такое Louvain и зачем он нужен?
A: Louvain — алгоритм обнаружения сообществ. Он разбивает граф на группы
   плотно связанных узлов. Это помогает увидеть структуру: какие страны
   образуют блок, какие C2-серверы обслуживают один ботнет, и т.д.

Q: Что такое модульность Q?
A: Метрика качества разбиения на сообщества. Q > 0.3 — хорошее разбиение.
   Q > 0.5 — отличное. В cyber-network Q ≈ 0.54 (6 сообществ).

Q: Почему assortativity отрицательная?
A: В cyber-network узлы с высокой степенью (C2-серверы, ботнеты) связаны
   с узлами с низкой степенью (жертвы, страны). Это классическая
   «звезда» — отрицательная ассортативность.

Q: Как проверить, что карта автономна?
A: Откройте консоль (F12), вставьте:
   grep -rn '\.\./' js/ blocks/ → должно быть пусто.
   Или см. раздел 6.9.

Q: Почему кнопка КОПИРОВАТЬ даёт 92 КБ, а не 250 КБ?
A: 92 КБ — достаточно для полной диагностики. Дальнейший рост — за счёт
   алгоритмов (Louvain, PageRank, Eigenvector, Clustering, Diameter),
   а не за счёт искусственного раздувания DOM.

Q: Как добавить новый слой?
A: Откройте js/layers.js, добавьте объект в массив allLayers. Затем
   добавьте демо-граф в js/network-adapter.js → generateDemo(layerId).

Q: Как добавить новый алгоритм?
A: Откройте js/relations.js, добавьте метод в объект window.Relations.
   Затем добавьте секцию в js/topbar.js → copyAllData.
