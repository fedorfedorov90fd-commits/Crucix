# Семантическое ядро: nlp_semantic_core.py

## Простое объяснение (для новичков)

Этот файл — «мозг понимания» системы. Он читает текст и превращает его в набор чисел — «вектор смысла». После этого можно сравнивать тексты не по словам, а по смыслу.

**Как это работает:**

Каждое слово и предложение можно представить точкой в многомерном пространстве смыслов. «Мир» и «перемирие» окажутся рядом. «Мир» и «бомба» — далеко. Модуль переводит заголовок в такую точку и смотрит, к какому эталонному «полюсу» (теме) она ближе.

**Что делает модуль:**

1. **Переводит текст в вектор** — массив из 384 чисел. Это «ДНК» смысла новости.
2. **Сравнивает вектор с эталонами тем** — для каждой темы (энергетика, кибер, экономика) есть свой эталонный вектор.
3. **Определяет тему** — если близость выше порога (0.4), новость относится к теме. Даже если ни одного ключевого слова из словаря в ней нет.
4. **Ищет подмену понятий** — сравнивает векторы двух описаний одного события. Если тематическая близость высокая, а лексическая — низкая, это `TERM_SUBSTITUTION`.

**Зачем это нужно:**

Обычный поиск по словам не работает, когда противник меняет формулировки. «Война» → «специальная операция». «Санкции» → «защита рынка». Словарь этого не поймает. Эмбеддинги — поймают: смысл остался тем же, вектор остался тем же.

**Аналогия:**

Представьте, что у вас есть карта смыслов. «Собака» и `dog` — на одной точке (разные языки, один смысл). «Собака» и «кошка» — рядом (оба животные). «Собака» и «самолёт» — далеко (разные категории). Модуль строит такую карту и ищет ближайшие точки.

## Научная база (для специалистов)

Модуль реализует **векторное представление текста** через Sentence-Transformers — архитектуру на основе трансформеров, обученную на парах предложений (contrastive learning).

**Модель:**

`all-MiniLM-L6-v2` — компактная (22M параметров), но мощная модель. 384-мерные эмбеддинги. Обучена на 1B пар предложений.

**Формально:**

1. **Эмбеддинг:** `v = model.encode(text)`, где `v ∈ R^384`.
2. **Косинусное сходство:** `cos(θ) = (a · b) / (||a|| · ||b||)`.
3. **Классификация:** `topic = argmax_t cos(v, TOPIC_VECTORS[t])`, если `cos > 0.4`.
4. **Подмена понятий:** `sim = cos(v_ru, v_en)`. Если `sim < 0.6` и `topic_ru == topic_en` — `TERM_SUBSTITUTION`.

**Почему Sentence-Transformers, а не TF-IDF:**

TF-IDF работает на уровне слов. Если противник заменит «война» на «специальная операция», TF-IDF не увидит сходства. Sentence-Transformers работает на уровне смысла: вектор «война» и вектор «специальная операция» будут близки, потому что модель обучена на парах с похожим смыслом.

**Почему `all-MiniLM-L6-v2`:**

- **Компактная.** 22M параметров, ~90 MB. Работает на CPU.
- **Быстрая.** ~1000 предложений в секунду на CPU.
- **Качественная.** Хороший баланс между скоростью и точностью.

**Ограничения:**

- Модель требовательна к RAM. Выносите в отдельный сервис или кэшируйте эмбеддинги в БД.
- Порог 0.4 эмпирический. Калибруйте на вашей выборке (precision/recall).
- Для коротких заголовков эмбеддинги менее устойчивы. Дополняйте анализом первых абзацев `content`.
- Модель чувствительна к языку. Для русского и английского — работает, для редких языков — хуже.

## Как работает (пошагово)

1. При старте загружается модель `SentenceTransformer('all-MiniLM-L6-v2')`.
2. Вычисляются эталонные векторы `TOPIC_VECTORS` для каждой темы из словаря понятий.
3. `get_semantic_signature(text)` возвращает numpy-массив из 384 чисел — «отпечаток» смысла.
4. `categorize_by_embedding(text)` считает косинусное сходство с каждым эталоном.
5. Выбирает максимум. Если превышает порог (0.4) — присваивает тему.
6. `detect_term_substitution(text_ru, text_en)` сравнивает векторы двух описаний.
7. Если тематическая близость высокая, а лексическая — низкая, помечает как `TERM_SUBSTITUTION`.
8. Тензоры PyTorch конвертируются в numpy через `.cpu().numpy()` для дальнейших расчётов.

**Формат ответа для классификации:**

```python
{
    'topic': 'energy',
    'confidence': 0.72
}

Формат ответа для подмены:
python

{
    'type': 'TERM_SUBSTITUTION',
    'similarity': 0.42,
    'western_term_vector': [...],  # 384 числа
    'russian_term_vector': [...]   # 384 числа
}

Пример использования
python

from services.nlp_semantic_core import get_semantic_signature, categorize_by_embedding, detect_term_substitution

# Получаем вектор смысла
vec = get_semantic_signature("Переговоры по энергетике возобновились")
print(vec.shape)  # (384,)

# Определяем тему
topic = categorize_by_embedding("Переговоры по энергетике возобновились")
print(topic)  # 'energy'

# Ищем подмену понятий
flag = detect_term_substitution("защита рынка", "market sanctions")
print(flag)
# {'type': 'TERM_SUBSTITUTION', 'similarity': 0.42, ...}

Что происходит:

    get_semantic_signature превращает текст в 384-мерный вектор.

    categorize_by_embedding сравнивает вектор с эталонами тем и выбирает ближайший.

    detect_term_substitution сравнивает два вектора: если тематически близки, а лексически далеки — это подмена.

Практические рекомендации

    Модель требовательна к RAM. Выносите в отдельный сервис или кэшируйте эмбеддинги в БД. Не пересчитывайте одно и то же.

    Порог 0.4 эмпирический. Калибруйте на вашей выборке (precision/recall) перед промышленным использованием.

    Для коротких заголовков эмбеддинги менее устойчивы. Дополняйте анализом первых абзацев content.

    Кэшируйте TOPIC_VECTORS между перезапусками (например, в pickle). Не пересчитывайте при каждом старте.

    Детектор подмены понятий — вспомогательный сигнал. Интерпретируйте вместе с контекстом, а не как окончательный вывод.

    all-MiniLM-L6-v2 — компактная, но мощная. Для больших корпусов можно all-mpnet-base-v2 (768-мерные, но медленнее).

    Для многоязычных корпусов — paraphrase-multilingual-MiniLM-L12-v2. Тогда «собака» и dog будут в одной точке.

    .cpu().numpy() — обязательно. Тензоры PyTorch не совместимы с numpy напрямую.

    SentenceTransformer — не требует GPU для инференса. Для обучения — GPU.

    Не используйте для категоризации того, что уже есть в словаре. Если слово «война» есть в TAXONOMY — используйте словарь. Эмбеддинги — для сложных случаев.

    Комбинируйте с kolmogorov_complexity.py. Эмбеддинги дают «понимание», сжатие — «шаблонность». Вместе — полная картина.
