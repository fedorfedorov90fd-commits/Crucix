# 09. Нормализатор

[← Назад к INDEX](./INDEX.md)

## Расположение

/home/ta8_/Рабочий стол/Crucix/apis/sources/smartscroll-local/processing/normalizer.mjs

## Назначение

Приведение сырых событий к единому формату, извлечение сущностей и определение геополитической полярности источника. Нормализация выполняется до дедупликации, что позволяет использовать полярность и сущности на всех последующих стадиях обработки.

## Класс

Normalizer

## Методы

- `normalize(raw)` — нормализация одного события
- `normalizeBatch(raws)` — пакетная нормализация массива событий
- `_loadPoleRules()` — загрузка правил полярности из source-camps.json при инициализации
- `_detectPole(source)` — определение полярности источника по домену или имени
- `_cleanText(text)` — очистка текста
- `_extractEntities(text)` — извлечение сущностей по шаблонам
- `_normalizeDate(date)` — приведение даты к ISO
- `_genId(raw)` — генерация детерминированного id

## Обработка

1. Очистка текста через `_cleanText`: удаление переводов строк CRLF, неразрывных пробелов, схлопывание повторных пробелов, ограничение пустых строк
2. Извлечение сущностей через `_extractEntities` по четырём шаблонам:
   - аббревиатуры от 2 до 6 заглавных букв
   - имена собственные (заглавная буква + 2-20 строчных)
   - даты в формате «число месяц-словом»
   - идентификаторы событий вида «рейс MH370» или «flight AA123»
3. Фильтрация стоп-слов (русские и английские предлоги, союзы, местоимения)
4. Ограничение: не более 30 сущностей на событие
5. Определение полярности источника через `_detectPole`
6. Приведение даты к ISO через `_normalizeDate`
7. Формирование итоговой записи

## Определение полярности

Метод `_loadPoleRules` при инициализации класса читает `apis/sources/source-camps.json` — базу из 67 источников, распределённых по трём полюсам:

- russian — 31 источник
- western — 22 источника
- non_aligned — 14 источников

Правила сортируются по длине подстроки в обратном порядке — более специфичные совпадения имеют приоритет. Результат кэшируется в `this._poleRules`.

Метод `_detectPole(source)` проверяет имя источника на вхождение подстрок из базы. Приоритетные правила обрабатывают известные конфликты:

- forbes + .ru в имени источника → russian
- forbes + .com в имени источника → western

При отсутствии совпадений — возвращает `unknown`.

## Выходной формат

- id — детерминированный хеш от source, title, published_at
- source — имя источника (строка)
- pole — геополитическая полярность: russian / western / non_aligned / unknown
- published_at — ISO-дата
- title — очищенный заголовок
- body — очищенное тело, до 10000 символов
- entities — массив извлечённых сущностей (не более 30)
- story_id — id сюжета (null при нормализации)
- related_stories — массив id связанных сюжетов (пустой при нормализации)
- url — ссылка на источник
- category — категория события
