# ИИ-агент автоматического расследования: agentic_engine.py

## Простое объяснение (для новичков)

Этот файл — «главный инспектор» системы. Он не просто считает цифры, он строит логические цепочки. При получении сигнала тревоги (алерта) он сам, без участия человека, проходит по чек-листу и собирает готовый отчёт.

**Что он делает:**

1. **Собирает контекст** — берёт последние 50 новостей по теме, чтобы понять предысторию.
2. **Ищет подмену понятий** — сравнивает слова и смысл, ищет, где формулировки расходятся с содержанием.
3. **Ищет пустоты** — смотрит, кто об этой теме молчит.
4. **Делает прогноз** — проверяет, ожидается ли всплеск в ближайшие дни.
5. **Пишет вывод** — формирует короткий текст на человеческом языке с рекомендацией.

**Зачем это нужно:**

Аналитик не должен вручную собирать досье по каждому сигналу. Агент делает черновик за секунды. Аналитик получает готовый материал и тратит время на проверку выводов, а не на сбор данных.

**Аналогия:**

Представьте стажёра, которому дали чёткий чек-лист: «сначала посмотри последние 50 новостей по теме, потом проверь, где слова расходятся со смыслом, потом посмотри, кто об этом молчит, потом загляни в прогноз — и напиши мне короткую записку». Агент делает ровно это, только за секунды и без устали.

## Научная база (для специалистов)

Архитектура следует паттерну **agentic pipeline**: декомпозиция задачи на упорядоченные шаги с передачей промежуточных результатов.

**Ключевые принципы:**

- **Слабая связанность.** Каждый шаг вызывает специализированный модуль (`nlp_semantic_core`, `counter_intel_engine`, `predictive_engine`). Замена одного модуля не ломает остальные.
- **Тестируемость.** Каждый шаг можно проверить отдельно.
- **Детерминированная генерация.** Формирование вывода — шаблонная генерация на f-строках, без «свободной» генерации текста. Это снижает риск необоснованных утверждений.
- **Закрытие соединений.** `conn.close()` после каждого шага — защита от утечек соединений с БД при массовой работе.

**Паттерн Pipeline:**

Алерт → Контекст → Подмена понятий → Пустоты → Прогноз → Бриф
text


Каждый шаг получает результат предыдущего и передаёт следующему. Это классическая архитектура «конвейера обработки», знакомая по ETL-системам и системам обработки потоков данных.

## Как работает (пошагово)

1. `run_auto_investigation(topic_id)` — точка входа; принимает тему и параметры окна.
2. **Шаг «контекст»:** SQL-выборка последних 50 новостей по теме (`LIMIT 50`).
3. **Шаг «подмена понятий»:** для каждой новости вызывается `detect_term_substitution` из NLP-модуля.
4. **Шаг «пустоты»:** вызывается `detect_information_voids` — кто игнорирует тему.
5. **Шаг «прогноз»:** вызывается `forecast_topic_spike` — ожидается ли всплеск.
6. Все результаты упаковываются в словарь `brief`.
7. `generate_conclusion(brief)` формирует текстовое резюме с рекомендацией (например, «рекомендуется усилить мониторинг»).
8. Соединения с БД закрываются после каждого шага.

Практические рекомендации

    Агент — инструмент подготовки черновика, а не замены аналитика. Финальные выводы требуют человеческой проверки.

    Ограничивайте число шагов и таймауты. Цепочка из тяжёлых модулей может работать минуты.

    Кэшируйте результаты промежуточных шагов по (topic_id, window). Повторные алерты по той же теме не должны пересчитывать всё заново.

    Логируйте, какие модули вернули ошибку. Бриф должен явно указывать на неполноту данных.

    Не включайте в бриф утверждения, не подкреплённые данными шагов — это снижает доверие к системе.

    Формируйте вывод шаблонно — на f-строках, без «свободной» генерации. Это детерминированно и воспроизводимо.
