# 11. Построитель сюжетов

## Назначение

Кластеризация событий в сюжеты по метрике сходства сущностей, заголовков и тел. Расчёт эвристического веса достоверности сюжета (bias_rank_weight) на основе геополитической полярности источников и детекции синдикации.

## Класс

StoryBuilder

## Методы

- `addToStories(newEvents, existingStories)` — распределение событий по существующим сюжетам или создание новых
- `_similarity(event, story)` — расчёт сходства события и сюжета
- `detectSyndication(text)` — детекция маркеров перепечатки в тексте
- `_getStoryPoles(story)` — сбор множества полюсов всех событий сюжета
- `_hasSyndicationInStory(story)` — проверка наличия синдикации в сюжете
- `_computeBiasRank(story)` — вычисление bias_rank_weight сюжета
- `_rebuildIndex(stories)` — перестроение инвертированного индекса
- `_indexStory(story, idx)` — добавление сюжета в индекс
- `_candidates(event)` — быстрый поиск сюжетов-кандидатов
- `_updateRelatedStories(story, allStories)` — обновление связей между сюжетами
- `getIndexStats()` — статистика индекса

## Алгоритм

1. Перестроение инвертированного индекса по сущностям из существующих сюжетов
2. Для каждого нового события — быстрый поиск кандидатов через индекс (только сюжеты, содержащие хотя бы одну общую сущность). Сложность O(1) на событие вместо O(N) по всем сюжетам
3. Расчёт метрики сходства для каждого кандидата через `_similarity`:
   - сходство сущностей (Jaccard) × вес 0.5
   - сходство заголовков (Jaccard по словам) × вес 0.3
   - сходство тел (Jaccard по 4-словным шинглам) × вес 0.2
   - Cross-pole boost +0.05, если событие и сюжет из разных полюсов
4. Если найдено сюжетное сходство выше порога — событие добавляется к сюжету, обновляются сущности, start_time, related_stories
5. Если сюжет не найден — создаётся новый сюжет с новым id
6. После обработки всех событий — вычисление bias_rank_weight для каждого сюжета через `_computeBiasRank`

## Метрика сходства

Сходство события и сюжета вычисляется как взвешенная сумма трёх компонентов:

- Сходство сущностей (вес 0.5) — Jaccard по множествам сущностей
- Сходство заголовков (вес 0.3) — Jaccard по словам длиной более 2 символов
- Сходство тел (вес 0.2) — Jaccard по 4-словным шинглам

Дополнительный Cross-pole boost +0.05 применяется, если полюс события отличается от полюсов сюжета. Boost небольшой и положительный — не ломает существующий порог. Логика: независимое подтверждение события с двух полюсов академически сильнее повторения внутри одного полюса.

Порог сходства по умолчанию — 0.35.

## Инвертированный индекс

Для быстрого поиска кандидатов используется структура `_entityIndex` — Map от сущности (в нижнем регистре) к множеству индексов сюжетов в массиве. При обработке события `_candidates(event)` собирает все индексы сюжетов, содержащих хотя бы одну сущность события. Это сокращает число сравнений с O(N) до O(K), где K — число сюжетов с общими сущностями.

## Детекция синдикации

Метод `detectSyndication(text)` ищет в тексте маркеры перепечатки по 10 регулярным выражениям:

- по материалам
- по сообщению
- по данным
- according to
- reported by
- sources said / sources told
- citing
- цитирует
- ссылкой на
- ref to / reference to

Метод `_hasSyndicationInStory(story)` проверяет все события сюжета на наличие этих маркеров в заголовке или теле.

## Вес достоверности (bias_rank_weight)

Метод `_computeBiasRank(story)` рассчитывает эвристический вес достоверности сюжета в диапазоне от 0 до 1 на основе трёх факторов:

- количество событий в сюжете
- полярности источников (cross-pole или same-pole)
- наличие синдикации

Формула:

- cross-pole без синдикации → 0.9
- cross-pole с синдикацией → 0.5
- same-pole (несколько источников одного полюса) → 0.6
- один источник → 0.3
- нет событий → 0

Значение записывается в поле `bias_rank_weight` каждого сюжета. Используется как сортировочный вес для ранжирования сюжетов, не как вердикт достоверности.

## Связи между сюжетами

Метод `_updateRelatedStories(story, allStories)` создаёт связи между сюжетами при наличии 3 и более общих сущностей. Связи хранятся в поле `related_stories` обоих сюжетов.

## Выходной формат

- id — идентификатор сюжета вида story_N
- title — заголовок первого события сюжета
- summary — сводка (заполняется позже суммаризатором)
- status — статус сюжета (active)
- start_time — время первого события
- end_time — время последнего события
- entities — массив уникальных сущностей всех событий сюжета
- events — массив событий
- related_stories — массив id связанных сюжетов
- bias_rank_weight — эвристический вес достоверности (0-1)
