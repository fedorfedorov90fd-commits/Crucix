## 1. НАЗНАЧЕНИЕ И МЕСТО В ЭКОСИСТЕМЕ CRUCIX

### 1.1. Что такое Crucix — экосистема из 5 карт

Crucix — геополитическая OSINT-платформа. Она состоит из **5 автономных карт**, каждая визуализирует свой класс данных:

1. **Event Map** (`/event-map/`) — точечные события на карте (митинги, атаки, инциденты). **84 слоя**, маркеры. **ЭТА КАРТА.**
2. **Metrics Map** (`/metrics-map/`) — количественные индикаторы по странам (экономика, финансы, ESG, кибер, энергетика). 75 слоёв, choropleth.
3. **Semantic Map** (`/semantic-map/`) — семантический анализ текстов (тональность, нарративы, дезинформация). 35 слоёв.
4. **Forecast Map** (`/forecast-map/`) — вероятностные прогнозы (рецессия, конфликты, риски). 16 слоёв.
5. **Network Map** (`/network-map/`) — графы связей (кибер-сети, торговля, финансы, миграция). 12 слоёв, SVG-граф.

### 1.2. Зачем именно 5 карт, а не одна

Пять карт — это реализация принципа **Separation of Concerns** (Dijkstra 1974). Каждый класс данных требует собственной модели визуализации:

- **События** → позиция + цвет (точечные маркеры). Канал: Position. Ёмкость: высокая для локализации.
- **Количественные индикаторы** → позиция (страна) + интенсивность цвета (choropleth). Канал: Position + Color intensity. Munzner 2014, Table 5.3 — полностью сепарабельны.
- **Семантика** → позиция + категориальный цвет + форма. Канал: Position + Hue + Shape.
- **Вероятности** → позиция + цвет + прозрачность (opacity). Канал: Position + Color intensity + Transparency.
- **Связи** → топология графа (force-directed). Канал: Position (force) + Shape.

Попытка объединить всё в одну карту нарушила бы **принцип сепарабельности каналов** (Munzner 2014). Пользователь не смог бы воспринимать одновременно 5 разных кодировок без когнитивной интерференции. Разделение на 5 карт — научно обоснованное решение, а не организационное удобство.

### 1.3. Что делает Event Map

Event Map визуализирует **точечные события по всему миру**. Каждый слой — это категория событий, каждый маркер — конкретный инцидент:

- Конфликты: вооружённые столкновения, пограничные инциденты, военные операции
- Протесты: митинги, забастовки, демонстрации, массовые выступления
- Катастрофы: природные бедствия, промышленные аварии, техногенные катастрофы
- Кибер: атаки, взломы, утечки данных, инциденты ИБ
- Политика: выборы, перевороты, отставки, назначения, смены режима
- Дипломатия: саммиты, договоры, санкции, переговоры
- Экономика: дефолты, банкротства, рыночные события, торги
- Терроризм: атаки, заговоры, аресты, предотвращения
- Миграция: пересечения границ, перемещения беженцев
- Здоровье: вспышки заболеваний, эпидемии
- Инфраструктура: отключения, сбои, disruptions
- Социальные: забастовки, бунты, гражданские волнения

Итого: **84 слоя в 12 категориях**.

Каждый слой при активации:
1. Получает данные из API `/api/layers/<layerId>` (или `/api/geo/markers`).
2. Если API недоступен (404) — срабатывает **автономный fallback**: данные генерируются локально из `countries.js` через детерминированный генератор. Для каждой страны создаётся 2–5 маркеров с координатами страны + детерминированным сдвигом.
3. Маркеры размещаются на карте через `updateMarkers`.
4. Маркеры кластеризуются при приближении (Leaflet marker cluster).
5. Popup маркера показывает: название события, категорию, дату, источник, координаты.
6. Логирует результат: `[Markers] layer=X, count=1080, fallback=true`.

### 1.4. Отличия от Metrics Map

Event Map и Metrics Map различаются классом визуализации:

- **Event Map:** каждая точка — отдельное событие (инцидент, митинг). Тысячи маркеров. `vizType='marker'`.
- **Metrics Map:** каждая страна — агрегат числового индикатора. 90 стран. `vizType='choropleth'` или `'series'`.

Event Map генерирует данные из событий, Metrics Map — из индикаторов. Это разные модели данных, и обе не сводятся друг к другу без потери смысла.

## 6. КАК РАБОТАЕТ КАЖДЫЙ ТИП СЛОЯ

### 6.1. Marker (84 слоя — основной тип)

При клике на слой:
1. `loadLayer(layerId)` вызывается из `layers.js`.
2. `EventMap.interceptLoad(layerId)` перехватывает.
3. `vizType === 'marker'` → `loadMarkerLayer(layer)`.
4. `fetch('/api/layers/<id>')`.
5. Если 404 → `renderMarkerFallback(layer)`:
   - Детерминированный seed по `layer.id`.
   - Для каждой из 90 стран — 2–5 маркеров (зависит от категории и статуса страны).
   - Позиция = координаты страны + детерминированный сдвиг (±2° lat, ±2° lng).
   - Тип маркера = категория слоя (конфликт → красный, протест → оранжевый, кибер → синий и т.д.).
   - Добавляются в `window.markerData`.
   - Перерисовываются через `updateMarkers`.
6. Если API работает — данные применяются напрямую.

Итого при полной активации всех 84 слоёв: 84 × ~15 = **~1260 маркеров**.

### 6.2. Кластеризация

Маркеры кластеризуются через Leaflet MarkerCluster:
- `maxClusterRadius: 50` — радиус объединения в пикселях.
- `spiderfyOnMaxZoom: true` — при максимальном зуме маркеры «раскрываются».
- `showCoverageOnHover: false` — не показывать область покрытия.
- При зуме > 6 — маркеры отображаются индивидуально.
- При зуме < 4 — кластеры объединяются в крупные группы.

### 6.3. Тепловая карта (heat-timeline.js)

Тепловая карта включается кнопкой HEAT:
- Конвертирует маркеры в heat layer через `L.heatLayer`.
- Интенсивность = плотность маркеров в области.
- Радиус = 25 пикселей.
- Размытие = 15.
- Дополнительный слой временной шкалы показывает распределение событий по времени.

- Количества источников (множественные → выше приоритет).

## 10. ПАЛИТРЫ И ВИЗУАЛИЗАЦИЯ

### 10.1. Цветовая схема маркеров

Цвета маркеров соответствуют категориям (см. раздел 9.1). Дополнительные визуальные коды:
- **Размер** — пропорционален приоритету: Low=18px, Medium=22px, High=26px, Critical=30px.
- **Прозрачность** — 0.8 для активных, 0.4 для неактивных категорий.
- **Обводка** — белая, 1.5px, для визуального отделения от фона.
- **Z-index** — Critical поверх всех остальных.

### 10.2. Цветовая схема кластеров

Кластеры окрашиваются по доминирующей категории:
- Если > 50% маркеров в кластере — конфликты → красный.
- Если > 50% — кибер → синий.
- Иначе — смешанный серый.
- Размер кластера = количество маркеров: 10/50/100/500+ — 4 ступени.

## 12. ЧТО НУЖНО ДОДЕЛАТЬ

### 12.1. Тепловая карта (heat-timeline.js)
Проблема: тепловая карта может некорректно конвертировать маркеры в heat layer при большом количестве слоёв.

Требуется:
- Проверить, что `toggleHeat` корректно собирает координаты всех активных маркеров.
- Настроить радиус и интенсивность в зависимости от зума.
- Добавить легенду тепловой карты.

### 12.2. Временная шкала
Проблема: временная шкала может не синхронизироваться с маркерами по датам.

Требуется:
- Каждому маркеру присвоить временную метку (timestamp).
- Временная шкала фильтрует маркеры по диапазону.
- Добавить слайдер диапазона дат.

### 12.3. Кнопка «Включить все»
Проблема: аналогично Metrics Map — цикл может не обработать все 84 слоя.

Требуется:
- Проверить, что `enableAllLayers()` обрабатывает все 84 слоя.
- Добавить логирование в каждой итерации.
- Возвращать класс active кнопке после загрузки.

### 12.4. Размер снапшота
Целевой размер: 1–2 МБ при 84 слоях с маркерами.

Проверка: после активации всех слоёв размер должен быть ~1.5 МБ. Если меньше — снапшот не собирает все маркеры.

## 16. API-ЭНДПОИНТЫ, ОЖИДАЕМЫЕ НА СЕРВЕРЕ

### 16.1. Marker-слои (84)

Для каждого marker-слоя ожидается эндпоинт:
```
GET /api/layers/<layerId>
```

Ответ:
```json
{
  "type": "FeatureCollection",
  "features": [
    {
      "type": "Feature",
      "properties": {
        "label": "Вооружённый конфликт",
        "category": "conflicts",
        "priority": "High",
        "date": "2026-09-28",
        "source": "ACLED"
      },
      "geometry": { "type": "Point", "coordinates": [lng, lat] }
    }
  ]
}
```

Если эндпоинт не отвечает (404) — сработает `renderMarkerFallback`.

### 16.2. Маркеры (общий эндпоинт)
```
GET /api/geo/markers
```

### 16.3. CII API
```
GET /api/cii-api
```

Если 404 — сработает `updateCIIFromLocal()` (fallback на локальные данные).

## 17. КОНТРАКТЫ МЕЖДУ КАРТАМИ

### 17.1. Принцип автономии

Каждая карта полностью автономна. Ноль cross-map зависимостей в скриптах и данных. Единственная разрешённая форма связи — навигационные ссылки в UI (переход между картами).

### 17.2. Навигация (5 переключателей)

```html
<a class="map-switch-btn active" data-map="events" href="./">Events</a>
<a class="map-switch-btn" data-map="metrics" href="../metrics-map/">Metrics</a>
<a class="map-switch-btn" data-map="meanings" href="../semantic-map/">Semantic</a>
<a class="map-switch-btn" data-map="relations" href="../network-map/">Network</a>
<a class="map-switch-btn" data-map="forecasts" href="../forecast-map/">Forecast</a>
```

### 17.3. Формат mapType

```html
<script>window.CrucixMap = { mapType: 'events', name: 'Crucix — Event Map' };</script>
```

### 17.4. Формат manifest.json

```json
{
  "mapType": "events",
  "name": "Crucix — Event Map",

  "layers": 84,
  "categories": 12,
```

## 21. ГЛОССАРИЙ

- **allLayers** — массив 84 конфигураций слоёв. Создаётся в `layers.js`. Каждый элемент: `{id, name, category, vizType, color, icon}`.
- **activeLayerIds** — Set активных id. Может содержать `'all'`.
- **markerData** — массив всех маркеров на карте. Заполняется `renderMarkerFallback`.
- **allMarkers** — копия `markerData` для откатов.
- **Cluster** — группа маркеров, объединённых при отдалении.
- **Priority** — уровень важности маркера (Low/Medium/High/Critical).
- **Fallback** — автономная генерация данных при отсутствии API.
- **CII** — Country Instability Index, индекс нестабильности страны.
- **SSI** — Strategic Stress Index, стратегический индекс напряжения.
