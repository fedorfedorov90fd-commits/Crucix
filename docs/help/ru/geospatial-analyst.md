# Геопространственный анализ: geospatial-analyst.mjs

## Простое объяснение (для новичков)

Этот файл — «географ» системы. Он смотрит на новости и отвечает на вопрос: «Где это происходит?» И не просто «где», а «насколько интенсивно» и «где об этом молчат».

**Что он делает:**

1. **Считает плотность событий по странам** — сколько новостей приходится на каждую страну. Но не просто считает, а с весами: США важнее Буркина-Фасо, Украина важнее Люксембурга.
2. **Ищет «белые пятна»** — если в важном регионе (например, Израиль или Украина) по критической теме ноль новостей, это аномалия. Значит, там что-то происходит, но об этом молчат.
3. **Считает индекс согласованности источников** — насколько широко каждый источник покрывает разные регионы. Узкий источник (пишет только о своей стране) получает низкий индекс. Широкий (пишет обо всём мире) — высокий.

**Зачем это нужно:**

Обычные системы мониторят то, что сказано. Этот модуль добавляет географическое измерение: где события происходят, а где — молчат. Это важно, потому что молчание в важном регионе часто информативнее шума.

**Аналогия:**

Представьте, что вы смотрите на карту мира. Яркие точки — там, где много новостей. Тёмные пятна — там, где новостей нет. Но не все тёмные пятна одинаковы: если это Люксембург — нормально. Если это Украина — аномалия. Модуль различает эти случаи через веса регионов.

## Научная база (для специалистов)

Модуль реализует **геопространственный анализ** (GEOINT) на основе трёх метрик:

1. **Плотность с весами** — количество событий по регионам, взвешенное по важности региона.
2. **Аномалии «информационного вакуума»** — регионы, где за окно времени нет событий, при этом регион считается «важным» (вес > 0.5).
3. **Индекс согласованности источников** — насколько широко каждый источник покрывает разные регионы.

**Формально:**

Для каждого региона `r` вычисляется:

**weighted_density(r) = count(r) / weight(r)**

где `count(r)` — число событий в регионе, `weight(r)` — вес региона из `REGION_WEIGHTS`.

**Нормализация:**

**normalized_density(r) = (count(r) / max_count) · 100**

где `max_count` — максимум по всем регионам.

**Аномалия:**

**anomaly(r) = true**, если `count(r) / max_count < 0.1` и `weight(r) > 0.5`.

**Индекс согласованности:**

Для каждого источника `s` считается доля уникальных регионов, которые он освещает:

**consistency(s) = unique_regions(s) / total_regions**

**Веса регионов:**

Задаются в `REGION_WEIGHTS` (объект-словарь `country_code → number`). Определяют, какие страны считаются приоритетными. Должен быть определён в том же модуле или импортирован из отдельного конфига.

**Почему веса важны:**

Без весов Люксембург и США были бы равны. С весами — США важнее в 10 раз. Это отражает редакционную политику мониторинга: мы хотим видеть, что происходит в важных регионах, а не во всех подряд.

**Ограничения:**

- `detectGeographicAnomalies` чувствительна к окну времени: при слишком маленьком окне будет много ложных срабатываний, при слишком большом — можно пропустить короткие «провалы».
- Веса регионов (`REGION_WEIGHTS`) нужно актуализировать вручную или по внешним правилам.
- Если событий мало или они распределены неравномерно, нормализация по максимуму может давать искажённые проценты. В таких случаях лучше использовать скользящее среднее или процентили.

## Как работает (пошагово)

1. `calculateGeographicDensity(events)` принимает массив событий.
2. Для каждого события извлекается `location.country_code`.
3. Если код есть — увеличивается счётчик для региона.
4. Вычисляется `weighted_density` и `normalized_density`.
5. `detectGeographicAnomalies(events, window)` ищет регионы с нулём событий за окно времени.
6. Если регион «важный» (`weight > 0.5`) — помечается как аномалия.
7. `calculateConsistencyIndex(events)` считает, сколько уникальных регионов освещает каждый источник.
8. Результаты возвращаются в формате, готовом для API и дашборда.

**Формат ответа:**

```javascript
{
  density: [
    {
      country_code: 'USA',
      raw_count: 45,
      weighted_density: '45.00',
      normalized_density: '100.0',
      anomaly: false
    },
    {
      country_code: 'RUS',
      raw_count: 30,
      weighted_density: '37.50',
      normalized_density: '66.7',
      anomaly: false
    }
  ],
  anomalies: [
    {
      country_code: 'UKR',
      reason: 'EXPECTED_BUT_SILENT',
      severity: 'high'
    }
  ],
  consistency: [
    { source: 'ТАСС', unique_regions: 5, consistency: 0.5 },
    { source: 'Reuters', unique_regions: 10, consistency: 1.0 }
  ]
}

Пример использования
javascript

import { calculateGeographicDensity, detectGeographicAnomalies, calculateConsistencyIndex } from './scripts/analyzers/geospatial-analyst.mjs';

const events = await loadEvents();

// Плотность по регионам
const density = calculateGeographicDensity(events);
console.log(density.density);

// Аномалии (регионы без событий)
const anomalies = detectGeographicAnomalies(events, 24);
console.log(anomalies);

// Индекс согласованности источников
const consistency = calculateConsistencyIndex(events);
console.log(consistency);

Что вернёт:

    density — массив регионов с raw_count, weighted_density, normalized_density, anomaly.

    anomalies — массив регионов с аномалиями (например, UKR без событий).

    consistency — массив источников с unique_regions и consistency.

Практические рекомендации

    REGION_WEIGHTS — актуализируйте вручную или по внешним правилам. Веса отражают редакционную политику мониторинга, а не «истину».

    Окно времени (window) — 24 часа по умолчанию. Малое окно (1–6 ч) — реакция на «горячие» события. Большое (48–168 ч) — фоновый анализ.

    detectGeographicAnomalies — чувствительна к окну времени. При слишком маленьком окне будет много ложных срабатываний. При слишком большом — можно пропустить короткие «провалы».

    Нормализация по максимуму — может давать искажённые проценты при малом числе событий. Для устойчивости используйте скользящее среднее или процентили.

    Кэширование — результаты можно кэшировать в БД (по ключу geo-density-YYYY-MM-DD) и обновлять раз в N минут. Не пересчитывайте на каждый запрос.

    RAG-слой — аномальные регионы можно использовать как контекст для AI-fallback: «в стране X нет новостей за 24 часа — проверь альтернативные источники».

    country_code — ISO 3166-1 alpha-3 (USA, RUS, CHN). Не используйте alpha-2 (US, RU, CN): это сломает совместимость.

    События без location — игнорируются. Если у события нет country_code, оно не попадает в плотность. Это нормально: не все новости имеют геолокацию.

    conn.close() — не применимо (это JS, не Python). Но кеш очищается при перезапуске сервера.

    Для отчётов — переводите числа в относительную шкалу (например, нормируйте на максимальное историческое значение), иначе читателю трудно интерпретировать абсолютные величины.
