# Конфигурация детектора молчания: silence.json

## Простое объяснение (для новичков)

Этот файл — «настройки» для модуля, который ищет темы, о которых молчат. Он говорит системе: «Считай тему молчащей, если о ней написали меньше N раз за последние 24 часа, а у другой группы — в M раз больше».

**Что внутри:**

```json
{
  "hours": 24,
  "min_count": 3,
  "max_ratio": 5
}

    hours — за сколько часов смотреть данные (по умолчанию 24).

    min_count — минимальное количество упоминаний темы у одной группы, чтобы она считалась «значимой» (по умолчанию 3).

    max_ratio — максимальное соотношение между группами, при котором тема ещё не считается «молчащей» (по умолчанию 5).

Как это работает:

    Если тема упоминается у группы A 40 раз, а у группы B — 0, это western_silence (ratio = ∞).

    Если у A — 10, у B — 1, это western_undercovered (ratio = 10).

    Если у A — 3, у B — 2, это не аномалия (ratio = 1.5, меньше 5).

Зачем это нужно:

Вы сразу видите, о чём молчат. Если тема «энергетика» активно обсуждается одной группой, а другая её игнорирует — это сигнал. Модуль ловит такие аномалии автоматически.

Аналогия:

Представьте, что вы слушаете радио. Одна станция вещает круглосуточно, другая — молчит. Вы не знаете, почему вторая молчит: может, сломалась, а может — намеренно. Модуль замечает это молчание и подсвечивает: «здесь что-то не так».
Научная база (для специалистов)

Конфигурационный файл задаёт параметры детектора «информационного молчания», реализованного в scripts/analyzers/silence-detector.mjs.

Формально:

Для каждой темы t вычисляются:

    count_A(t) — число упоминаний темы t у группы A за окно hours.

    count_B(t) — число упоминаний темы t у группы B за тот же период.

    ratio(t) = max(count_A, count_B) / min(count_A, count_B) — соотношение.

Классификация:

    western_silence — count_russian >= min_count И count_western = 0. Ratio = ∞.

    russian_silence — count_western >= min_count И count_russian = 0. Ratio = ∞.

    western_undercovered — count_russian >= min_count И count_western >= 1 И ratio > max_ratio.

    russian_undercovered — count_western >= min_count И count_russian >= 1 И ratio > max_ratio.

    normal — иначе.

Почему min_count: 3:

Одно упоминание — случайность. Два — совпадение. Три — паттерн. Если тема упоминается меньше 3 раз, она не считается «значимой» — это шум.

Почему max_ratio: 5:

Если соотношение меньше 5 — это не аномалия. Например, 10 vs 2 — ratio 5, это ещё в пределах нормы (обе группы пишут, просто одна активнее). Если 10 vs 1 — ratio 10, это уже western_undercovered (одна группа почти игнорирует).

Почему hours: 24:

Суточный цикл новостей. Меньше — растёт шум. Больше — теряется реактивность.

Ограничения:

    Пороги зависят от объёма потока. Для малого потока (100 статей) min_count: 3 может быть слишком высоким. Для большого (1000+) — слишком низким.

    max_ratio: 5 — эмпирический. Калибруйте на исторических данных.

    Детектор работает на уровне тем (taxonomy), а не отдельных слов. Это уменьшает шум, но требует хорошего словаря понятий.

Как работает (пошагово)

    silence-detector.mjs при запуске читает config/silence.json.

    Загружает articles за последние hours часов.

    Группирует по темам (через taxonomy-multilayer.mjs) и по группам (russian, western, neutral).

    Для каждой темы считает count_russian, count_western, count_neutral.

    Вычисляет ratio по формуле выше.

    Классифицирует: western_silence, russian_silence, western_undercovered, russian_undercovered, normal.

    Сохраняет в таблицу information_gaps с полями topic, gap_type, severity, russian_count, western_count, total_events.

Формат ответа:
json

{
  "topic": "энергетика",
  "gap_type": "western_silence",
  "severity": "high",
  "russian_count": 40,
  "western_count": 0,
  "total_events": 45,
  "ratio": "inf"
}

Пример использования

Стандартный конфиг:
json

{
  "hours": 24,
  "min_count": 3,
  "max_ratio": 5
}

Чувствительный конфиг (для малого потока):
json

{
  "hours": 12,
  "min_count": 2,
  "max_ratio": 3
}

Консервативный конфиг (для большого потока):
json

{
  "hours": 48,
  "min_count": 5,
  "max_ratio": 10
}

Применение:
bash

# Изменить конфиг
nano config/silence.json

# Пересобрать information_gaps
psql -d crucix -c "DELETE FROM information_gaps;"
node --env-file=.env scripts/analyzers/silence-detector.mjs

Практические рекомендации

    hours: 24 — оптимально для суточного цикла новостей. Меньше — растёт шум, больше — теряется реактивность.

    min_count: 3 — для потока 300–500 статей в сутки. Для малого потока (100) — снижайте до 2. Для большого (1000+) — повышайте до 5.

    max_ratio: 5 — эмпирический. Для более строгого детектора — снижайте до 3. Для более мягкого — повышайте до 10.

    Калибруйте на исторических данных. Прогоните систему с разными порогами на данных за прошлый месяц и сравните: где детектор был полезен, а где — шум.

    DELETE FROM information_gaps перед пересборкой — метрика пересчитываемая. Накопление даёт дубликаты.

    severity — high для silence (ratio = ∞), normal для undercovered (ratio < 10). Это отражает силу сигнала.

    total_events — общее число событий по теме. Полезно для контекста: 40 упоминаний у одной группы могут быть значимыми, а 4 — нет.

    Не используйте min_count: 1. Одно упоминание — это шум, а не сигнал. Детектор будет находить «молчание» везде.

    Не используйте max_ratio: 1. Это будет означать «любое неравенство — аномалия». Слишком много ложных срабатываний.

    Держите конфиг под версионным контролем. Изменение порогов меняет результаты. Фиксируйте версию в отчётах.
