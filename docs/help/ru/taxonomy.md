# Словарь понятий: taxonomy.json

## Простое объяснение (для новичков)

Этот файл — «справочник тем» для системы. Он говорит: какие темы существуют, какие слова к ним относятся, как они связаны между собой и в каких контекстах встречаются.

**Что внутри:**

```json
{
  "entities": {
    "россия": {
      "type": "country",
      "ru": "Россия",
      "en": "Russia",
      "aliases": ["россия", "рф", "российская федерация", "russia", "russian federation"],
      "parent": null,
      "contexts": ["politics", "energy", "conflict"]
    },
    "москва": {
      "type": "city",
      "ru": "Москва",
      "en": "Moscow",
      "aliases": ["москва", "москве", "москвы", "moscow"],
      "parent": "россия",
      "contexts": ["politics", "economy"]
    },
    "путин": {
      "type": "person",
      "ru": "Путин",
      "en": "Putin",
      "aliases": ["путин", "владимир путин", "putin"],
      "parent": null,
      "contexts": ["politics", "conflict"]
    }
  },
  "settings": {
    "group_cities_by_parent": true,
    "group_persons_by_parent": false
  }
}

Что означает каждое поле:

    type — тип сущности: country, city, person, organization, region.

    ru, en — названия на русском и английском.

    aliases — все варианты написания (синонимы, словоформы, переводы).

    parent — родительская сущность. Для городов — страна. Для персон — null (персоны не группируются).

    contexts — контексты, в которых сущность встречается: politics, economy, conflict, energy, cyber, sport, culture, health.

    settings — правила группировки: group_cities_by_parent, group_persons_by_parent.

Зачем это нужно:

Чтобы система понимала, что «россия», «рф», «russia», «российская федерация» — это одна сущность. И что «москва» — это город в «россии». И что «путин» — это отдельная персона, а не часть «россии».

Аналогия:

Это как справочник в библиотеке. Вы ищете книгу про Россию — и находите все варианты: «Россия», «РФ», «Russian Federation». Справочник знает, что это одно и то же. И знает, что «Москва» — это город в России, а «Путин» — отдельный человек.
Научная база (для специалистов)

Файл задаёт словарь понятий (semantic vocabulary) с иерархической структурой и контекстами.

Формально:

Файл задаёт:

    Множество сущностей E = {e_1, e_2, ..., e_n} — страны, города, персоны, организации.

    Тип сущности type: E → {country, city, person, organization, region}.

    Алиасы aliases: E → 2^S, где S — множество строк (варианты написания).

    Иерархия parent: E → E ∪ {null} — родительская сущность.

    Контексты contexts: E → 2^C, где C = {politics, economy, conflict, energy, cyber, sport, culture, health}.

Иерархия:

    Города группируются в страну: москва.parent = россия. Это позволяет избежать дублирования: «Москва» и «Россия» — не две разные темы, а одна (Россия) с уточнением (Москва).

    Персоны не группируются: путин.parent = null. Это ключевое решение: «Путин» — самостоятельная тема, а не часть «России». Если группировать, потеряем 13 сигналов про Путина.

Почему персоны не группируются:

Персоны — самостоятельные акторы. «Путин» и «Россия» — связанные, но разные сущности. Если сгруппировать «Путина» в «Россию», получим одну большую тему (40+13 = 53), но потеряем возможность видеть отдельные сигналы про Путина (13 событий).

Контексты:

Контексты позволяют различать, в каком смысле упоминается сущность. «Россия» в контексте energy — это про нефть и газ. «Россия» в контексте conflict — про военные действия. «Россия» в контексте sport — про Олимпиаду.

Settings:

    group_cities_by_parent: true — города группируются в страну.

    group_persons_by_parent: false — персоны не группируются.

Ограничения:

    Алиасы должны быть в нижнем регистре. Морфология (падежи, числа) закрывается через алиасы.

    Тип сущности (type) — стабильный. Не меняйте без необходимости.

    parent — только для городов. Для персон — null. Для стран — null.

    Контексты — эмпирические. Не все сущности имеют все контексты.

Как работает (пошагово)

    taxonomy-multilayer.mjs при старте читает config/taxonomy.json.

    Парсит JSON, извлекает entities и settings.

    Строит aliasMap — Map от алиаса к ID сущности.

    categorizeItem(item) проходит по всем алиасам. Если в заголовке есть хоть одно слово — присваивает ID.

    Если group_cities_by_parent = true и сущность — город — заменяет на parent.

    Если group_persons_by_parent = false — оставляет персону как есть.

    detectInformationGaps проверяет: если в теме за последние N часов массив ID пуст — это аномалия.

Что происходит при добавлении новой сущности:

    Добавьте объект в entities.

    Укажите type, ru, en, aliases, parent, contexts.

    Сохраните файл.

    При следующем запуске таксономия подхватит новую сущность.

Что происходит при изменении группировки:

    Измените settings.group_cities_by_parent или settings.group_persons_by_parent.

    Сохраните файл.

    При следующем запуске таксономия применит новые правила.

Пример использования

Текущий конфиг (25 сущностей, 97 aliases, 8 контекстов):
json

{
  "entities": {
    "россия": { "type": "country", "aliases": ["россия", "рф", "russia"], "parent": null, "contexts": ["politics", "energy", "conflict"] },
    "москва": { "type": "city", "aliases": ["москва", "moscow"], "parent": "россия", "contexts": ["politics", "economy"] },
    "путин": { "type": "person", "aliases": ["путин", "putin"], "parent": null, "contexts": ["politics", "conflict"] },
    "украина": { "type": "country", "aliases": ["украина", "ukraine"], "parent": null, "contexts": ["conflict", "politics"] },
    "зеленский": { "type": "person", "aliases": ["зеленский", "zelensky"], "parent": null, "contexts": ["politics", "conflict"] }
  },
  "settings": {
    "group_cities_by_parent": true,
    "group_persons_by_parent": false
  }
}

Добавление новой сущности (например, «Китай»):

"китай": {
  "type": "country",
  "ru": "Китай",
  "en": "China",
  "aliases": ["китай", "китая", "китае", "china", "chinese", "prc"],

  "contexts": ["politics", "economy", "energy"]

"пекин": {
  "type": "city",
  "ru": "Пекин",

  "aliases": ["пекин", "пекина", "beijing"],
  "parent": "китай",

Практические рекомендации

    ID сущностей — стабильные. На них ссылаются БД и отчёты. Меняйте только ru, en, aliases.

    Алиасы — в нижнем регистре. Приведение к нижнему регистру делает код. Морфологию (падежи, числа) закрывайте через алиасы.

    Города группируются в страну. Это правило: group_cities_by_parent: true. Если его отключить, «Москва» и «Россия» станут разными темами — это потеря смысла.

    Персоны не группируются. Это ключевое решение: group_persons_by_parent: false. Если сгруппировать «Путина» в «Россию», потеряем 13 сигналов про Путина.

    Контексты — эмпирические. Не все сущности имеют все контексты. «Путин» в контексте sport — редкость. «Россия» в контексте sport — Олимпиада.

    parent — только для городов. Для персон — null. Для стран — null. Для регионов — может быть страна.

    Держите файл под версионным контролем. Изменение алиасов меняет результаты категоризации. Фиксируйте версию в отчётах.

    Для многоязычных корпусов добавляйте алиасы на всех рабочих языках. Модуль ищет совпадения по всем записям массива.

    Не удаляйте старые сущности. Даже если сущность больше не актуальна — оставьте её. Старые данные в БД могут ссылаться на её ID.

    type — стабильный. Не меняйте без необходимости. Тип используется в отчётах и API.

    settings — два параметра. group_cities_by_parent и group_persons_by_parent. Меняйте осознанно.

    Файл читается при старте. Если вы изменили его — перезапустите модуль. Иначе изменения не применятся.
