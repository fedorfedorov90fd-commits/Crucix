# Crucix Pipeline — фазы A–U

**Назначение:** описание полного 16-фазного конвейера прогностического движка Crucix.
**Актуальная версия:** 7.0.0 (16 фаз).

---

## Общая картина

Конвейер запускается после каждого sweep (15 минут). Каждая фаза — независимый блок с graceful degradation. Падение одной фазы не убивает весь конвейер.

Фазы A–R — базовый конвейер (v5.0). Фазы S, T, U добавлены в v6.0/v7.0 как независимые расширения.

---

## Базовый конвейер A–R (v5.0)

| Фаза | Название | Модули |
|------|----------|--------|
| A | Загрузка данных | sweep → features |
| B | Базовые модели | bayesian, naivebayes, markov, montecarlo |
| C | Научный синтез | timeseries, cascade, calibration |
| D | Нейросетевой слой | neural, graph_neural, reinforcement |
| E | Продвинутые модели | hawkes, hmm, kalman, ising, evt, copula, bocpd, particle |
| F | Источники | prediction_markets, multilang, satellite |
| G | Граф знаний | knowledge graph build |
| H | Калибровка | Brier Score, Platt scaling |
| I | Ансамблирование | weighted ensemble |
| J | Рефлексивная коррекция | applyReflexiveCorrection |
| K | Объяснимость | permutation importance, counterfactuals |
| L | Active Learning | выбор следующих источников |
| M–Q | v2.0/v3.0/v5.0 | temporal_causal, multilayer_causal, narrative_warfare, hypergraph_contagion, attention_dynamics, adversarial_coevolution, multiscale_attention, opponent_ppo, bayesian_causal |
| R | v5.0 финал | hypergraph_discovery, federated_hypergraph |

## Фаза S — v6.0 научный синтез

**Файл:** apis/predict/engine_v6_patch.mjs → runV6Phase

**Модули:** 5
- neural_causal_discovery.mjs
- continual_learning.mjs
- causal_rl.mjs
- quantum_hypergraph.mjs
- zk_federated.mjs

### Как работает

    const v6Result = await runV6Phase(history, { disabled: [] });

1. Проверка circuit breaker для каждого модуля.
2. Проверка history.length >= minHistory (20-30).
3. Параллельный запуск через Promise.allSettled.
4. Каждый модуль с timeout 60-120 секунд.
5. При падении — запись в failures.

### Время

~1.5-2 секунды (все модули параллельно, на 40 sweep'ах).

### Расширение snapshot

applyV6ToSnapshot добавляет snapshot.v6_extensions с результатами по каждому модулю + signals для explanation.

---

## Фаза T — каталог (6 модулей)

**Файл:** apis/predict/engine_v6_patch.mjs → runCatalogPhase

**Модули:** 6
- models/mcmc.mjs
- models/physics_inspired.mjs
- automl.mjs
- anomaly_detection.mjs
- models/graph_sage.mjs
- models/actor_critic.mjs

### Как работает

Идентично фазе S, но с другими модулями. Параллельно с S (можно запускать одновременно).

### Время

~1-1.5 секунды (все модули параллельно).

### Расширение snapshot

applyV6ToSnapshot добавляет snapshot.catalog_extensions.

---

## Фаза U — v7.0 Simulation Engine

**Файл:** apis/predict/engine_v7_patch.mjs → runV7Phase

**Модуль:** 1 (но внутри — 4 подмодуля: world_model + neural_ode + dreamer + continuous_causal)

### Как работает

    const v7Phase = await runV7Phase(history, {
      horizon: 12,
      modules: {...},
    });

1. Circuit breaker для simulation_engine_v7.
2. Проверка history.length >= 30.
3. Импорт apis/predict/v7/simulation_engine.mjs.
4. Запуск crucixSimulationEngine — последовательно 4 подмодуля.
5. Timeout 180 секунд (долго).
6. applyV7ToSnapshot расширяет snapshot.v7_extensions.

### Время

~16-30 секунд (4 подмодуля последовательно).

### Расширение snapshot

- snapshot.v7_extensions.synthesis
- snapshot.v7_extensions.answers
- snapshot.explanation.reasoning_steps — шаги v7
- snapshot.explanation.summary — дополняется

---

## Порядок выполнения в engine.mjs

    // ... фазы A-R выполнены ...
    const forecast = { ... };  // snapshot собран

    // ФАЗЫ S+T (параллельно)
    try {
      const [v6Phase, catalogPhase] = await Promise.all([
        runV6Phase(history, {}),
        runCatalogPhase(history, {}),
      ]);
      applyV6ToSnapshot(forecast, v6Phase, catalogPhase);
    } catch (e) { ... }

    // ФАЗА U (после S+T)
    try {
      const v7Phase = await runV7Phase(history, {...});
      applyV7ToSnapshot(forecast, v7Phase);
    } catch (e) { ... }

    // Публикация
    await phaseZ_Dissemination(forecast);

**Почему такой порядок:**
- S и T параллельны (независимы).
- U зависит от history, но не от результатов S/T.
- Можно было бы все три параллельно, но U требует много ресурсов — запускается отдельно.

---

## Graceful degradation

Каждая фаза изолирована:
- try/catch вокруг всей фазы.
- Failure записывается в forecast.failures.
- Остальные фазы продолжают работать.
- Snapshot сохраняется даже если U упала.

---

## Circuit breaker

Глобальный (на процесс) для каждой фазы:
- threshold = 3 падения подряд
- cooldown = 5 запусков пропуска
- После cooldown счётчик сбрасывается, модуль пробует снова

Это защита от бесконечно падающих модулей в production.

---

## Timeout wrapper

Каждый модуль обёрнут в Promise.race с timeout:
- S/T: 60-120 секунд
- U: 180 секунд

Если модуль не завершился — reject с `timeout after Nms`.

# Crucix v6.0 — пять модулей научного синтеза

**Версия:** 6.0.0
**Расположение:** `apis/predict/v6/`
**Назначение:** пять независимых методов для углубления прогностического анализа поверх основной 13-фазной цепочки (A–R).

---

## Общая картина

v6.0 — это пять модулей, каждый из которых решает самостоятельную научную задачу:

| Модуль | Наука | Ключевая идея |
|--------|-------|---------------|
| `neural_causal_discovery.mjs` | Нейросетевой discovery DAG | NO TEARS + transformer |
| `continual_learning.mjs` | Continual Learning | EWC + Synaptic Intelligence |
| `causal_rl.mjs` | Causal RL | Q-learning с causal mask |
| `quantum_hypergraph.mjs` | Квантовый отжиг | QUBO + Path-Integral MC |
| `zk_federated.mjs` | ZK + federated | Schnorr proofs + DP |

Все пять подключаются к движку через фазу S в `engine_v6_patch.mjs` и запускаются параллельно через `Promise.allSettled` с per-module timeout и circuit breaker.

---

## 1. Neural Causal Discovery

**Файл:** `apis/predict/v6/neural_causal_discovery.mjs`
**Строк:** ~350
**Экспорт:** `NeuralCausalDiscovery`, `MultiHeadAttention`, `crucixNeuralCausalDiscovery`

### Задача

Дано: временной ряд наблюдений переменных (vix, tension, conflicts, sanctions, radiation). Найти структуру причинного графа (DAG) — какие переменные влияют на какие.

### Метод

1. **NO TEARS acyclicity constraint** (Zheng et al., 2018): вместо комбинаторного поиска — непрерывная оптимизация. Ограничение ацикличности:
   h(W) = tr(e^(W ∘ W)) - d = 0
   где W — матрица весов, ∘ — поэлементное умножение.

2. **Multi-Head Self-Attention** применяется к латентным представлениям переменных для усиления сигнала.

3. **Loss:** MSE реконструкции + L1-sparsity + lambda·|h(W)|.

4. **Gradient:** численный (finite differences), так как нет backprop через матричную экспоненту.

### Выход

Поля результата: module, available, nVariables, nTimesteps, discoveredEdges (массив {from, to, weight, direction}), nEdges, isAcyclic, density, interpretation.

### Когда использовать

- Оператор спрашивает: «какие переменные реально влияют на tension?»
- Нужна структурная карта причинности для дальнейшего анализа.
- Как вход для causal_rl и continuous_causal.

---

## 2. Continual Learning

**Файл:** `apis/predict/v6/continual_learning.mjs`
**Строк:** ~650
**Экспорт:** `EWCLearner`, `SynapticIntelligence`, `crucixContinualLearning`

### Задача

Модель учится на новых sweep'ах, но не забывает старые паттерны (кризисы 2024, редкие события). Классическая нейросеть при дообучении «забывает» предыдущие данные — catastrophic forgetting.

### Два метода

1. **EWC (Elastic Weight Consolidation)** — Kirkpatrick et al., 2017:
   - После обучения на задаче A фиксируем Fisher Information Matrix F для каждого веса.
   - При обучении на B добавляем штраф: lambda · sum(F_i · (theta_i - theta_A_i)^2)
   - Веса с высокой Fisher «заморожены», с низкой — свободны.

2. **Synaptic Intelligence** — Zenke et al., 2017:
   - Онлайн-накопление importance: omega += g^2 / (loss + zeta)
   - Не требует отдельного прохода для Fisher.

### Архитектура

MLP: inputSize → hiddenSize → outputSize (3 класса: crisis/elevated/stable).

### Persistence

Состояние сохраняется в runs/predictions/continual_learner.json. При загрузке проверяется валидность: все веса должны быть finite.

### Выход

Поля: module, method, taskId, tasksLearned, lossBefore, lossAfter, lossReduction, forgettingBefore, forgettingAfter, forgettingDelta, prediction (class + probabilities), fisherNorm.

### Когда использовать

- Каждый sweep: модель дообучается на новых данных без потери старого знания.
- Метрика forgettingDelta — насколько модель забыла старые паттерны (чем меньше, тем лучше).

---

## 3. Causal Reinforcement Learning

**Файл:** `apis/predict/v6/causal_rl.mjs`
**Строк:** ~640
**Экспорт:** `CausalEnvironment`, `CausalQLearner`, `CausalPolicyGradient`, `crucixCausalRL`

### Задача

Агент учится выбирать действия (observe / monitor / sanctions_low / sanctions_high / intervention), но не через корреляции, а через причинную структуру. Действие допустимо только если узел, на который оно направлено, не имеет confounders.

### Три компонента

1. **CausalEnvironment** — MDP поверх DAG:
   - State: (vix, tension, conflicts, sanctions, radiation)
   - Actions: do(X=x) для узлов-причин + observe
   - Dynamics: dz_i/dt = sum(w_ij · parent_j) + noise
   - Reward: -2·tension - vix - 1.5·conflicts + бонус за снижение

2. **CausalQLearner** — Q-learning с causal mask:
   - Q-table: Map(stateKey → Float64Array(nActions))
   - Маска допустимых действий для каждого состояния
   - epsilon-greedy policy

3. **CausalPolicyGradient** — REINFORCE с causal mask.

### Выход

Поля: module, method, training (avgReward, causalRatio), evaluation (policyAvg, randomAvg, improvementPct), causalInsights (массив с node/ateHigh/direction/policyPrefers), recommendedAction.

### Когда использовать

- Оператор спрашивает: «какое действие оптимально?»
- Counterfactual-анализ: «что если мы применим санкции?»
- Оценка политик через evaluatePolicy.

## 4. Quantum-Inspired Hypergraph Sampling

**Файл:** `apis/predict/v6/quantum_hypergraph.mjs`
**Строк:** ~490
**Экспорт:** `QUBOFormulation`, `QuantumAnnealer`, `HypergraphMAP`, `crucixQuantumHypergraph`

### Задача

Поиск MAP-структуры гиперграфа (N-арные причинные связи) — NP-трудная комбинаторная задача. Решается через квантовый отжиг.

### Три компонента

1. **QUBOFormulation** — построение Ising-модели:
   - Бинарная переменная s_e ∈ {0,1} для каждого кандидата-гиперребра
   - c[i] = -CMI(edge_i) + lambda_BIC·2^|edge_i|
   - Q[i][j] = lambda_overlap · |parents_i ∩ parents_j| если оба имеют один target

2. **QuantumAnnealer** — Path-Integral Quantum Annealing (Suzuki, 1995):
   - P реплик Ising-модели
   - Кинетический член J(t) для туннелирования
   - Отжиг по температуре T и gamma

3. **HypergraphMAP** — сборка гиперграфа из бинарного решения + проверка ацикличности DFS.

### Выход

Поля: module, nQubits, annealing (bestEnergy, convergence), hypergraph (nHyperedges, avgHyperedgeSize, totalMI, isAcyclic), topEdges.

### Когда использовать

- Нужны N-арные связи: не пары (A→B), а группы (A+B+C→D).
- Когда обычный DAG-discovery не находит причин.
- Производительность: QUBO + annealer работают за ~200-500 ms.

---

## 5. Zero-Knowledge Federated Learning

**Файл:** `apis/predict/v6/zk_federated.mjs`
**Строк:** ~600
**Экспорт:** `ZKSchnorrProver`, `DPMechanism`, `FederatedNode`, `SecureAggregator`, `crucixZKFederated`

### Задача

Распределённое обучение: несколько узлов (региональные Crucix-инстансы) обучают локальные модели, обмениваются градиентами, но не раскрывают локальные данные. Плюс защита от poisoning-атак.

### Три компонента

1. **ZKSchnorrProver** — протокол Шнорра + Fiat-Shamir:
   - Доказательство знания секретного ключа без раскрытия
   - 2048-bit MODP Group (RFC 3526)

2. **DPMechanism** — Gaussian Mechanism:
   - (epsilon, delta)-дифференциальная приватность
   - sigma = sensitivity · sqrt(2·ln(1.25/delta)) / epsilon
   - Clipping + Gaussian noise

3. **SecureAggregator** — FedAvg с poisoning defense:
   - ZK-верификация proof каждого узла
   - MAD (Median Absolute Deviation) для обнаружения outliers
   - Weighted average (веса пропорциональны 1/loss)

### Выход

Поля: module, nNodes, rounds, privacy (epsilon, delta, privacySpent), training (initialLoss, finalLoss, lossReduction), security (zkProtocol, poisoningDefense, totalRejected).

### Когда использовать

- Развёртывание Crucix на нескольких серверах / регионах.
- Когда нельзя передавать сырые данные между узлами (regulation, privacy).
- Защита от злонамеренных узлов в federated-сети.

## Интеграция в engine

Все 5 модулей v6.0 подключаются через фазу S в engine_v6_patch.mjs.

### API

    import { runV6Phase } from './engine_v6_patch.mjs';
    const v6Result = await runV6Phase(history, {
      disabled: [],
      timeoutMs: 60000,
    });

Поля v6Result: modules (объект с результатами по каждому модулю), okCount, totalModules, elapsedMs.

### Circuit breaker

После 3 падений подряд модуль отключается на 5 запусков. Восстанавливается автоматически.

### Параллельный запуск

Promise.allSettled — падение одного не блокирует остальные.

### Расширение snapshot

Функция applyV6ToSnapshot(snapshot, v6Phase, catalogPhase) добавляет:
- snapshot.v6_extensions.modules — результаты по каждому модулю
- snapshot.v6_extensions.signals — извлечённые сигналы для explanation
- snapshot.explanation.reasoning_steps — добавленные шаги
- snapshot.explanation.summary — расширенная интерпретация

## 1. World Model

**Экспорт:** WorldModel, VAE, MDNRNN, Controller, crucixWorldModel

### Задача

Агент учится «воображать» будущее в сжатом латентном пространстве. Не нужно ждать реальных данных — можно развернуть симуляцию на N шагов вперёд.

### Три компонента

1. **VAE (Variational Autoencoder)**:
   - Encoder: x (11 признаков) → h (hiddenDim) → (mu, logvar) → z (latentDim)
   - Decoder: z → h → x_hat
   - Reparameterization: z = mu + exp(0.5·logvar)·epsilon
   - Option deterministic=true для gradient evaluation

2. **MDN-RNN** (Mixture Density Network RNN):
   - LSTM cell с gates i/f/o/g
   - MDN head: h → (pi, mu, sigma) — смесь K гауссов на каждый latent dim
   - P(z_{t+1} | h_t) = sum_k pi_k · N(mu_k, sigma_k^2)

3. **Controller** — линейная политика a = tanh(W·[z;h] + b)

### Imagination

Функция imagine(z0, horizon) разворачивает N шагов:
1. Controller выбирает action.
2. RNN forward: sample z_{t+1} из mixture.
3. Сохраняем (z_t, a_t, z_{t+1}, h_t).

### Выход

crucixWorldModel(history) возвращает: training (vae metrics, rnnTrained), quality (avgReconError, reconQuality), imagination (trajectory, trend, imaginedFeatures), direction (escalation/deescalation/stable).

## 2. Neural ODE

**Файл:** apis/predict/v7/neural_ode.mjs
**Строк:** ~729
**Экспорт:** NeuralODEFunc, NeuralODETrainer, rk4Solve, counterfactual, rewind, escalationRate, crucixNeuralODE

### Задача

Вместо дискретной последовательности z_{t+1} = f(z_t) — непрерывная динамика dz/dt = f_theta(z, t). Состояние определено для любого t, не только на сетке sweep'ов.

### Метод

1. **NeuralODEFunc** — MLP, параметризующий dz/dt = f_theta(z, t).
2. **RK4 solver** — метод Рунге-Кутты 4-го порядка. Точность ~1e-4 при 100 шагах на интервале длиной 1.
3. **NeuralODETrainer** — обучение через finite differences (вместо полного adjoint method Chen 2018).

### Counterfactual

- **counterfactual(f, z0, intervention)** — сравнение с вмешательством.
- **rewind(f, z0, stepsBack)** — решить ODE назад во времени (t < 0).
- **escalationRate(f, trajectory)** — скорость |dz/dt| в каждой точке.

### Выход

crucixNeuralODE(history) возвращает: training (lossBefore, lossAfter, lossReduction), forecast (trajectory, trend, direction, initialRate, finalRate), counterfactual, rewind.

## 3. Dreamer

**Файл:** apis/predict/v7/dreamer.mjs
**Строк:** ~838
**Экспорт:** Dreamer, Actor, Critic, computeReward, crucixDreamer

### Задача

Actor-Critic обучение полностью в latent space через imagination World Model. Никаких реальных взаимодействий — всё внутри «сна».

### Три компонента

1. **Actor** — политика pi(a|z), softmax over actions.
2. **Critic** — value V(z), MLP.
3. **Dreamer** — оркестратор:
   - rollout(z0) → траектория через world_model
   - computeLambdaReturns(trajectory) — TD(lambda)
   - trainStep: actor update с advantage, critic update с MSE
   - normalizeReturns — критично для сходимости

### Reward

computeReward(decoded, prevDecoded):
- -2·tension - 1·vix - 1.5·conflicts - 0.5·sanctions
- Штраф за рост (dTension, dConflicts)

### Выход

crucixDreamer(history) возвращает: evaluation (before/after meanReturn, improvement), bestAction (name + actionDistribution), finalRollout, training metrics.

### Замечание

На синтетике за 10-15 шагов политика почти не улучшается — это ожидаемо. Hafner обучает DreamerV3 на 100k+ шагов. Для production нужны большие эпизоды.

## 4. Continuous Causal

**Файл:** apis/predict/v7/continuous_causal.mjs
**Строк:** ~755
**Экспорт:** CausalDAG, ContinuousSCM, crucixContinuousCausal

### Задача

Синтез Neural ODE (B2) + причинного вывода (Pearl). Динамика не просто непрерывная — она подчинена причинной структуре. Counterfactual через do-operator.

### Структурное уравнение

    dz_i/dt = f_i( {z_j : j ∈ parents(i)}, t ) + epsilon_i

Родители определяются из DAG. Do-operator: зафиксировать z_j = value на [t0, t1], разорвав входящие стрелки.

### Два ключевых компонента

1. **CausalDAG**:
   - parents/children/descendants/ancestors
   - topologicalOrder
   - **induceFromData** — через lag-correlation + time-precedence

2. **ContinuousSCM**:
   - initFunctions: per-node MLP
   - forward: динамика только от parents
   - solve: RK4 с intervention
   - counterfactual: baseline vs intervention
   - estimateATE: Average Treatment Effect

### Важное открытие

Для observational данных направление причинности без времени определить НЕЛЬЗЯ. Поэтому induceFromData использует **time-precedence**: ребро i→j только если max_lag corr(x_i[t], x_j[t+lag]) > обратного.

### Выход

crucixContinuousCausal(history) возвращает: dag (nodes, edges, topologicalOrder), training (lossBefore, lossAfter), forecast (trajectory, trend, direction), counterfactual, ate (perVar с ate/std/sign).

## 5. Simulation Engine

**Файл:** apis/predict/v7/simulation_engine.mjs
**Строк:** ~523
**Экспорт:** crucixSimulationEngine, synthesize, extractDirections, consensusDirection, answerQuestions

### Задача

Оркестратор: запускает все 4 модуля и синтезирует результат. Отвечает на вопросы оператора.

### Синтез

extractDirections(v7Results) — извлекает направление из каждого модуля:
- world_model → direction (escalation/deescalation/stable)
- neural_ode → знак trend.tension.delta
- dreamer → bestAction → интерпретация
- continuous_causal → forecast.direction

consensusDirection — доминирующее направление + agreement (доля согласных).

Confidence = 0.7·agreement + 0.3·coverage:
- agreement — доля модулей с одним направлением
- coverage — доля активных модулей от 4

### Q&A

answerQuestions генерирует ответы на 5 предопределённых вопросов:
1. Что будет через N часов?
2. Как быстро меняется состояние?
3. Что если ввести санкции?
4. Какое действие оптимально?
5. Какие переменные — настоящие причины?

Каждый ответ включает confidence (high/moderate/low) и source (какой модуль).

### Выход

crucixSimulationEngine(history) возвращает: moduleStatus, activeModules/totalModules, synthesis (consensus, confidence, reasoningSteps), answers, results (сырые результаты 4 модулей), interpretation.
