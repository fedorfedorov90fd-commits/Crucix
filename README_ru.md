## 🚀 Описание

**Crucix** — платформа для сбора, анализа и визуализации данных из открытых источников. Предназначена для мониторинга геополитической, экономической, военной и экологической обстановки в реальном времени.

Архитектура построена по принципу **«Корзина → AI → Карта»**:

- **Сбор** — данные приходят из 226 источников в корзину (`data/basket/`)
- **Анализ** — 59 анализаторов считают индексы, композиты, прогнозы (`data/analytics/`)
- **AI** — локальный LLM (Ollama) генерирует брифы и прогнозы
- **Карта** — результат визуализируется в **5 автономных карт**, каждая из которых отображает свой класс данных

### Ключевые возможности

- ✅ **226 OSINT-источников** — спутники, авиация, конфликты, экономика, экология
- ✅ **59 анализаторов** — индексы, детекторы, прогнозы, композиты
- ✅ **370+ API-модулей** — все эндпоинты данные из корзины
- ✅ **8 категорий аналитики** — index, detector, forecast, semantic, flow, market, specialist, space
- ✅ **5 автономных карт** — Event, Metrics, Semantic, Forecast, Network — каждая со своими слоями, палитрами и моделями визуализации
- ✅ **222 слоя суммарно** — 84 + 75 + 35 + 16 + 12, разнесены по 5 картам по принципу сепарабельности каналов
- ✅ **Инфраструктурный анализатор** — 114 объектов, 15 эндпоинтов
- ✅ **Автообновление** каждые 15 минут через SSE
- ✅ **Telegram + Discord боты** с двухсторонним управлением
- ✅ **AI-аналитика** через Ollama (локально, без облака)
- ✅ **Модульная архитектура** — легко расширять
- ✅ **Zero cloud, zero telemetry, zero subscriptions**

## ⚡ Быстрый старт

### Локальный запуск

```bash
# 1. Клонировать репозиторий
git clone https://github.com/calesthio/Crucix.git
cd Crucix

# 2. Установить зависимости (только Express)
npm install

# 3. Скопировать шаблон .env и добавить API-ключи
cp .env.example .env

# 4. Запустить дашборд
npm run dev
```

Дашборд откроется на `http://localhost:3117`

Если `npm run dev` не работает, запустите напрямую:

```bash
node --trace-warnings server.mjs
```

### Docker

```bash
git clone https://github.com/calesthio/Crucix.git
cd Crucix
cp .env.example .env
docker compose up -d
```

## 🗺️ Пять карт Crucix — пять измерений реальности

### Почему пять, а не одна

Визуализация данных — это перевод информации в зрительные сигналы, которые мозг способен обработать. Каждый тип данных требует своего «языка»: события требуют точек на карте, числовые показатели — заливки территорий, связи — графа с рёбрами. Когда разные типы данных смешиваются на одном полотне, мозг не справляется — сигналы интерферируют, как два радиоканала на одной частоте.

Это не организационное удобство, а следствие из **теории каналов восприятия** (Munzner, *Visualization Analysis & Design*, 2014, Table 5.3). У человеческого зрения есть ограниченный набор каналов: позиция, цвет, размер, форма, прозрачность. Каждый канал имеет разную «пропускную способность» — способность точно передавать количественные или категориальные значения. Когда два типа данных претендуют на один и тот же канал одновременно, возникает **когнитивная интерференция**: наблюдатель не может отделить один сигнал от другого.

**Принцип сепарабельности каналов** (Munzner 2014) гласит: два визуальных канала сепарабельны, если их можно воспринимать одновременно без взаимных помех. Пять классов данных в Crucix используют пять разных комбинаций каналов:

| Карта | Каналы визуализации | Тип данных | vizType |
|-------|---------------------|-----------|---------|
| **Event Map** | Position + Hue + Shape | Точечные события | `marker` |
| **Metrics Map** | Position + Color intensity | Количественные индикаторы по странам | `choropleth` / `series` |
| **Semantic Map** | Position + Hue (категориальный) + Shape | Тональность и нарративы | `choropleth` (diverging) |
| **Forecast Map** | Position + Color intensity + Transparency | Вероятности с уверенностью | `probability` |
| **Network Map** | Position (force) + Shape + Edge width | Связи и отношения | `graph` (SVG) |

Если бы все пять жили на одной карте, четыре из пяти кодировок пришлось бы либо отключить, либо наложить друг на друга — и ценность каждой упала бы до нуля.

**Простыми словами:** представьте, что вы смотрите на карту мира, где одновременно красными точками отмечены теракты, страны раскрашены по уровню инфляции, поверх наложены стрелки торговых связей, а ещё прозрачность показывает вероятность рецессии. Разобраться в этом невозможно — глаз не может одновременно читать четыре разных «языка». Поэтому каждый язык получает свою карту.

### Принцип автономии

Каждая из пяти карт — **полностью автономна**. Это реализовано через паттерн **Bulkhead** (Nygard, *Release It!*, 2007): если одна карта падает, четыре остальные продолжают работать. Автономность гарантируется шестью правилами (R1–R6):

- **R1:** Ни один `<script>`, `<link>` или `fetch` не выходит за пределы своей папки. Проверка: `grep -rn '\.\./' index.html js/*.js` возвращает 0 строк.
- **R2:** Географические границы (`world.geojson`) лежат локально в `data/` каждой карты.
- **R3:** Файл `layers.js` каждой карты содержит только свои слои — ноль чужих.
- **R4:** Конфигурация (`maps-config.js`, `presets.json`) — своя для каждой карты.
- **R5:** `manifest.json` каждой карты фиксирует `local_cross_map: 0`, `failure_domain: 1`.
- **R6:** Сбой в одной карте не влияет на остальные четыре.

Каждая карта живёт в своей папке: `/dashboard/public/<map-name>/` со своим `index.html`, `js/`, `css/`, `data/`, `presets/`. Нет общих скриптов, общих стилей, общих данных — только общий сервер.

### 1. Event Map — Карта событий

**Расположение:** `/dashboard/public/event-map/`
**URL:** `http://localhost:3117/event-map/`
**Слоёв:** 84 в 12 категориях

Event Map — это карта мира, на которой точечными маркерами отображаются конкретные события: протесты, военные инциденты, кибератаки, дипломатические встречи, катастрофы, миграционные волны, вспышки болезней. Каждая точка — одно событие с координатами, временем, категорией и приоритетом.

**Модель данных:** один маркер = одно событие. Тысячи маркеров на карте, сгруппированных в 84 слоя по 12 категориям (конфликты, протесты, катастрофы, кибер, политика, дипломатия, экономика, террор, миграция, здоровье, инфраструктура, социальные). Маркеры кластеризуются при зуме, раскрашиваются по категории, получают popup с детализацией при клике.

**Визуальный канал:** Position + Hue + Shape. Позиция на карте = географические координаты события. Цвет = категория. Форма = тип (круг, треугольник, квадрат).

**Чем отличается от Metrics Map:** Event Map показывает отдельные события (митинг 15 марта в Тбилиси), Metrics Map — агрегированные показатели по странам (уровень безработицы в Грузии = 14%). Событие не сводится к числу, а число не сводится к событию — это разные онтологии.

**Чем отличается от Network Map:** Event Map показывает точки на географической карте. Network Map показывает связи между узлами в абстрактном пространстве графа — там нет широт и долгот.

**Папка:**
```
event-map/
├── index.html
├── manifest.json
├── EVENT-MAP-MANIFEST.md
├── ARCHITECTURE.md
├── AUTONOMY-CHARTER.md
├── css/event-map.css
├── js/
│   ├── core.js
│   ├── countries.js
│   ├── layers.js          ← 84 слоя, 12 категорий
│   ├── maps-config.js
│   ├── map-controls.js
│   ├── markers.js          ← генерация и кластеризация маркеров
│   ├── event-map.js
│   ├── copy-data.js
│   ├── heat-timeline.js
│   ├── ssi.js
│   ├── refresh.js
│   ├── cii.js
│   ├── logger.js
│   └── init.js
├── data/world.geojson
└── presets/presets.json
```

**Маркеры и кластеризация:**
- До 1000+ маркеров на слой, с детерминированным геосдвигом по seed.
- Кластеризация: Leaflet.markercluster с adaptive zoom.
- Приоритизация: 5 уровней (critical → low), влияют на размер и z-index.
- Popup: категория, описание, источник, время, координаты.

**Автономный fallback:**
При отсутствии API данные генерируются локально: 2 маркера на страну × 90 стран = 180 маркеров на слой. Позиция — координаты страны + детерминированный сдвиг. Категория и приоритет — по seed слоя.

### 2. Metrics Map — Карта количественных индикаторов

**Расположение:** `/dashboard/public/metrics-map/`
**URL:** `http://localhost:3117/metrics-map/`
**Слоёв:** 75 в 13 категориях

Metrics Map — это choropleth-карта мира, где каждая страна закрашивается цветом, интенсивность которого соответствует значению числового показателя. Инфляция, ВВП, безработица, долг/ВВП, индекс доллара, спреды, кривая доходности, уран, киберугрозы, ESG-метрики, HDI, расходы на оборону — 75 индикаторов в 13 категориях.

**Модель данных:** одна страна = одно значение индикатора. 90 стран на карте, значение классифицируется методом Jenks DP (или Quantile / Equal Interval / Standard Dev / Manual — по домену), затем применяется палитра ColorBrewer (sequential или diverging). Результат — заливка стран с легендой, показывающей пороги классов, метод классификации и качество (GVF).

**Визуальный канал:** Position + Color intensity. Позиция = территория страны. Интенсивность цвета = значение показателя. Эти два канала полностью сепарабельны (Munzner 2014) — позиция передаёт «где», цвет передаёт «сколько».

**Чем отличается от Semantic Map:** Metrics Map показывает количественные показатели (инфляция = 7.2%). Semantic Map показывает категориальную тональность (настроение = «негативное», «нейтральное», «позитивное»). Числа и категории — разные типы данных, и для них нужны разные палитры: sequential (для чисел) и diverging (для категорий с нейтралью посередине).

**Чем отличается от Forecast Map:** Metrics Map отображает текущие, наблюдаемые значения. Forecast Map отображает вероятности будущих событий с дополнительным каналом — прозрачностью, кодирующей уверенность модели. Текущее значение и вероятность будущего — разные семантические сущности.

**Папка:**
```
metrics-map/
├── index.html
├── manifest.json
├── METRICS-MAP-MANIFEST.md
├── ARCHITECTURE.md
├── AUTONOMY-CHARTER.md
├── css/metrics-map.css
├── js/
│   ├── core.js
│   ├── countries.js        ← 90 стран с координатами и статусами
│   ├── layers.js           ← 75 слоёв, 13 категорий
│   ├── maps-config.js      ← методы классификации, палитры, breaks
│   ├── series-adapter.js    ← series → choropleth (14 модулей, spatial proxies)
│   ├── map-controls.js     ← Leaflet init, Jenks DP, ColorBrewer, GVF, legend
│   ├── markers.js          ← 6 marker-слоёв × 180 = 1080 маркеров
│   ├── metrics-map.js      ← decision tree: choropleth / series / marker
│   ├── copy-data.js        ← снапшот ~500 КБ
│   ├── heat-timeline.js
│   ├── ssi.js              ← Strategic Stress Index
│   ├── refresh.js
│   ├── cii.js              ← Country Instability Index (fallback)
│   ├── logger.js
│   └── init.js
├── data/world.geojson      ← локальная копия границ (252 КБ)
└── presets/presets.json    ← 5 пресетов с уникальными ключами
```

**Методы классификации (Jenks 1963, Brewer 2005):**

| Метод | Формула | Применение |
|-------|---------|-----------|
| Jenks DP | минимизация SDCM, \(O(k \cdot n^2)\) | По умолчанию |
| Quantile | равные группы | При выбросах |
| Equal Interval | \((max - min) / k\) | Плавные шкалы |
| Standard Dev | \(\mu \pm 0.5\sigma\), \(\pm 1.5\sigma\) | Нормальное распределение |
| Manual | пороги эксперта | ISM 50, recession 20/40/60/80 |

Контроль качества: \(GVF = (SDAM - SDCM) / SDAM > 0.7\). Типичные значения в Metrics Map: 0.90–0.93.

**Палитры ColorBrewer:**
- Sequential (7): Blues, YlOrRd, Greens, Oranges, Purples, BuPu, OrRd
- Diverging (4): RdYlGn5, RdBu5, BrBG5, PiYG5

Доменные правила: PMI → diverging RdYlGn5 с manual breaks [42, 47, 53, 58] (ISM 50 = граница). Recession → sequential YlOrRd5 с manual breaks [20, 40, 60, 80]. Copper/Gold → diverging RdBu5, Jenks. Yield Curve → diverging RdBu5, Jenks (инверсия = красный).

**Типы слоёв:**
- **Choropleth (56):** заливка стран по значению индикатора. API → fallback (детерминированный seed по `layer.id`, base(status) + noise).
- **Series (14):** рыночные ряды → choropleth через `SeriesAdapter` с spatial proxies (us_market, oil_producers, financial_centers...). 6 трансформаций: weighted_value, stress_indicator, ratio_indicator и др.
- **Marker (6):** точечные маркеры на choropleth-карте (180 маркеров/слой, 1080 при полной активации).

**Автономный fallback:**
При отсутствии API данные генерируются локально из `countries.js`: детерминированный seed по `layer.id`, для каждой из 90 стран значение = base(status) + noise(seed), Jenks классификация, `applyChoropleth()`, логирование GVF.

### 3. Semantic Map — Карта семантического анализа

**Расположение:** `/dashboard/public/semantic-map/`
**URL:** `http://localhost:3117/semantic-map/`
**Слоёв:** 35 в 12 категориях

Semantic Map — это карта мира, где страны закрашиваются по тональности текстов: негативная, нейтральная, позитивная. Тональность вычисляется из потоков новостей и социальных медиа по каждому региону. Дополнительно: нарративы, дезинформация, медийный тон, пропаганда, инфовойна, когнитивные искажения, манипуляции, токсичность.

**Модель данных:** одна страна = категориальный класс тональности (5 классов по Cowan 2001: very_negative, negative, neutral, positive, very_positive). 35 слоёв в 12 категориях (тональность, нарративы, дезинформация, медийный тон, пропаганда, инфовойна, соцсети, темы, достоверность, когнитивные искажения, манипуляции, токсичность).

**Визуальный канал:** Position + Hue (категориальный) + Shape. Палитра — diverging RdYlGn5 (красный → жёлтый → зелёный), где середина = нейтральная тональность, края — крайние значения. Для кластеров нарративов — категориальная Set1. Форма маркера (Circle, Square, Triangle, Diamond) — для категориального различения слоёв.

**Чем отличается от Metrics Map:** Metrics Map классифицирует значения по интенсивности (sequential: «чем больше, тем темнее»). Semantic Map классифицирует по категориям с нейтральным центром (diverging: «плохо — нейтрально — хорошо»). Это разные палитры, потому что число 7.2 (инфляция) не имеет «нейтрального» значения, а тональность «нейтральная» — это нулевая точка на шкале.

**Чем отличается от Event Map:** Event Map показывает отдельные события как точки. Semantic Map показывает агрегированную тональность информационного поля по странам как заливку. Событие — это «что произошло». Тональность — это «как об этом пишут».

### 4. Forecast Map — Карта вероятностных прогнозов

**Расположение:** `/dashboard/public/forecast-map/`
**URL:** `http://localhost:3117/forecast-map/`
**Слоёв:** 16, все типа `probability`

Forecast Map — это карта мира, где страны закрашиваются по вероятности наступления события: рецессия, эскалация конфликта, политический кризис, продовольственный кризис. Каждый прогноз сопровождается **двойным кодированием**: цвет = класс вероятности, прозрачность = уверенность модели.

**Модель данных:** одна страна = вероятность (0–100%) + уверенность модели (0–1). 16 слоёв, все типа `probability`. Горизонт прогноза — от 1 месяца до 1 года.

**Визуальный канал:** Position + Color intensity + Transparency. Это **трёхканальная кодировка** — единственная в Crucix, использующая прозрачность как информационный канал, а не как декорацию. Цвет (sequential YlOrRd5, manual breaks [20, 40, 60, 80]) передаёт класс вероятности. Прозрачность (`opacity = 0.4 + 0.5 × confidence`, Cressie 1993, *Statistics for Spatial Data*) передаёт уверенность модели: чем прозрачнее заливка, тем меньше уверенность в прогнозе.

**Простыми словами:** если прогноз рецессии в стране X — 75%, и модель уверена на 90%, вы увидите ярко-красную заливку. Если та же вероятность 75%, но модель уверена лишь на 40%, заливка будет бледно-красной. Глаз сразу видит: «высокая вероятность, но низкая уверенность — прогноз ненадёжный». На обычной choropleth-карте этой информации нет вообще.

**Чем отличается от Metrics Map:** Metrics Map показывает наблюдаемые факты: инфляция = 7.2%. Forecast Map показывает вероятности будущих событий с метаданными о неопределённости. Факт и прогноз — разные эпистемологические сущности. Факт не имеет «уверенности» (он уже случился). Прогноз без указания уверенности — это не прогноз, а догадка.

**Чем отличается от Semantic Map:** Semantic Map использует diverging палитру (двустороннюю: плохо ↔ хорошо). Forecast Map использует sequential палитру (одностороннюю: 0% → 100%) с дополнительным каналом прозрачности. Двусторонняя палитра не подходит для вероятностей, потому что «0% вероятности» — это не «противоположность 100%», а просто нижняя граница шкалы.

```
├── css/forecast-map.css
├── js/
│   ├── core.js
│   ├── countries.js
│   ├── layers.js           ← 16 слоёв, все типа probability
│   ├── maps-config.js      ← manual breaks [20,40,60,80], YlOrRd5, opacity formula
│   ├── forecast-adapter.js ← spatial proxies для 4 источников прогнозов
```

**Двойное кодирование (Cressie 1993):**
Цвет: sequential YlOrRd5, manual breaks [20, 40, 60, 80] → 5 классов вероятности (very_low, low, medium, high, very_high). Прозрачность: `opacity = 0.4 + 0.5 × confidence`, где confidence ∈ [0, 1]. При confidence = 1.0 → opacity = 0.9 (яркая заливка). При confidence = 0.0 → opacity = 0.4 (бледная заливка). Порог видимости: при opacity < 0.4 заливка не рисуется.

**Spatial proxies для источников прогнозов:**
4 источника: market_prediction (prediction_markets), model_forecast (байесовские модели), ai_forecast (LLM-агенты), composite (ансамбль). Каждый источник маппится на страны через spatial proxy (us_market, eu_zone, emerging_markets, global_all).

**Автономный fallback:**
При отсутствии API данные генерируются локально: вероятность = base(status) + noise(seed), confidence = 0.5 + noise(seed) × 0.3, классификация по manual breaks, двойная заливка (цвет + прозрачность), логирование.

### 5. Network Map — Карта связей и отношений

**Расположение:** `/dashboard/public/network-map/`
**URL:** `http://localhost:3117/network-map/`
**Слоёв:** 12, тип `graph` (SVG force-directed)

Network Map — это не географическая карта. Это **граф связей**, визуализированный через force-directed simulation в SVG. Узлы — страны, организации, финансовые потоки, киберсети. Рёбра — торговые связи, санкционные отношения, миграционные потоки, финансовые каналы. Здесь нет широт и долгот; позиция узла вычисляется физической симуляцией.

**Модель данных:** узлы (entities) + рёбра (relations). 12 слоёв в категориях (кибер-сети, торговля, финансы, миграция, дипломатия, энергетика). Узлы имеют тип (Circle, Square, Triangle, Diamond) и размер (пропорционален Degree centrality). Рёбра имеют ширину (пропорциональна весу связи) и цвет (тип отношения).

**Визуальный канал:** Position (force) + Shape + Edge width. Позиция — не географическая, а топологическая: вычисляется force simulation (кулоновское отталкивание между узлами, гуково притяжение вдоль рёбер, интеграция Верле). Форма узла — категориальный тип (Circle = страна, Square = организация, Triangle = финансовый центр, Diamond = киберузел). Ширина ребра — вес связи.

**Почему Network Map не использует Leaflet и world.geojson:**
Географическая карта (Leaflet + GeoJSON) кодирует позицию через широту и долготу. Но для графа связей географическая позиция — не главное; главное — топология (кто с кем связан, кто центральный, кто периферийный). Force-directed layout размещает связанные узлы рядом, а несвязанные — далеко, независимо от их реального положения на Земле. Если бы мы использовали Leaflet, узлы застряли бы в своих географических координатах и структура связей стала бы нечитаемой.

**Простыми словами:** если Event Map — это карта мира с точками, а Metrics Map — это карта мира с заливкой, то Network Map — это «карта паутины», где связи важнее местоположения. Вы видите, кто связан с кем, кто в центре, кто на периферии, через какие узлы проходит больше всего путей. Это невозможно показать на обычной карте.

**Чем отличается от остальных четырёх карт:**
Network Map — единственная карта без Leaflet и без `world.geojson`. Вместо растрового рендеринга — SVG force-directed graph. Вместо географических координат — топологическая симуляция. Вместо choropleth или marker — рёбра и узлы. Панель досье показывает метрики графа (Degree, Betweenness, PageRank) вместо индикаторов страны.

**Папка:**
```

├── index.html
├── manifest.json
├── NETWORK-MAP-MANIFEST.md
├── ARCHITECTURE.md
├── AUTONOMY-CHARTER.md
├── css/network-map.css
├── js/
│   ├── core.js
│   ├── countries.js        ← справочник узлов (стран, организаций)
│   ├── layers.js           ← 12 слоёв графа
│   ├── network-config.js  ← force simulation параметры (alpha, charge, link distance)
│   ├── graph-engine.js    ← force simulation: Coulomb repulsion, Hooke attraction, Verlet
│   ├── graph-renderer.js   ← SVG рендеринг: узлы, рёбра, метки
│   ├── graph-panel.js      ← панель досье: Degree, Betweenness, PageRank
```

**Force simulation (Barabási 2016, *Network Science*):**
- **Repulsion:** кулоновское отталкивание, `F = k² / d` (Fruchterman-Reingold 1991), где k — идеальная длина связи, d — расстояние.
- **Attraction:** гуково притяжение вдоль рёбер, `F = d² / k`.
- **Integration:** Verlet (velocity-free), `x_new = 2·x − x_prev + a·dt²`.
- **Cooling:** alpha decay от 1.0 до 0.001 за 300 итераций.
- **Стабилизация:** симуляция останавливается при alpha < 0.005.

**4 формы узлов:**
- Circle — страна (90 узлов)
- Square — международная организация
- Triangle — финансовый центр
- Diamond — киберузел

**Метрики графа (панель досье):**
- **Degree centrality** — количество прямых связей узла.
- **Betweenness centrality** — доля кратчайших путей через узел (Freeman 1977).
- **PageRank** — итеративная метрика важности (Page et al. 1999), damping = 0.85.

**Автономный fallback:**
При отсутствии API граф генерируется локально: seed по `layer.id`, 30–60 узлов из справочника, рёбра по weighted random (preferential attachment, Barabási-Albert), force simulation запускается на клиенте.

### Почему карты не могут быть вместе — научное обоснование

#### 1. Когнитивная интерференция каналов

Человеческое зрение способно одновременно обрабатывать 2–3 визуальных канала, но только если они **сепарабельны** — не конкурируют за одни и те же зрительные ресурсы (Munzner 2014, §5.3). Position и Color intensity — сепарабельны. Color intensity и Transparency — **не сепарабельны**: мозг не может отделить «темнее потому что значение выше» от «темнее потому что слой менее прозрачный». Поэтому Forecast Map использует transparency осознанно — как единственный слой, кодирующий неопределённость, и только потому, что probability — единственный тип данных, где неопределённость — часть семантики, а не шум.

Если бы мы попытались наложить choropleth (Metrics) поверх marker (Event), обе кодировки использовали бы позицию на карте, и мозг не смог бы отделить «где событие» от «где заканчивается страна». Результат — визуальный шум, в котором ни один паттерн не считывается.

#### 2. Различие моделей данных

Пять карт — это пять разных **моделей данных**, каждая со своей онтологией:

- **Событие** — точка в пространстве-времени. Сущность: «что-то произошло здесь и сейчас». Атрибуты: координаты, время, категория, приоритет.
- **Индикатор** — число, агрегированное по территории. Сущность: «показатель страны на дату». Атрибуты: значение, единица, период.
- **Тональность** — категория, вычисленная из текстов. Сущность: «как об этом говорят». Атрибуты: класс (5 уровней), источник, confidence.
- **Прогноз** — вероятность будущего события с неопределённостью. Сущность: «что может произойти и насколько мы уверены». Атрибуты: вероятность, горизонт, confidence.
- **Связь** — отношение между сущностями. Сущность: «кто с кем связан». Атрибуты: узлы, рёбра, веса, типы.

Эти модели не сводятся друг к другу. Событие нельзя «усреднить» до индикатора, не потеряв временную и пространственную точность. Индикатор нельзя «раскластеризовать» до событий. Прогноз нельзя «наблюдать» как факт. Связь нельзя «покрасить» как choropleth. Каждая модель требует своего визуального языка, и эти языки несовместимы.

#### 3. Принцип Separation of Concerns (Dijkstra 1974)

Разделение на пять карт — это и архитектурное решение. Каждая карта имеет свой DAG загрузки, свой набор скриптов, свой CSS, свой `manifest.json`, свой `layers.js`. Сбой в одной карте (ошибка в `layers.js`, упавший API, сломанный fallback) не распространяется на остальные. Это паттерн Bulkhead (Nygard 2007): изоляция доменов отказа.

Если бы все слои жили в одном `layers.js` (84 + 75 + 35 + 16 + 12 = 222 слоя), любая синтаксическая ошибка в одном слое уронила бы все 222. С пятью картами ошибка в одном слое Event Map оставляет Metrics, Semantic, Forecast и Network полностью работоспособными.

#### 4. Объяснение для дилетанта

Представьте, что вы работаете в аэропорту и вам нужно одновременно:
1. Отслеживать каждый самолёт на радаре (события — Event Map)
2. Видеть загрузку каждого терминала в процентах (метрики — Metrics Map)
3. Понимать, как пассажиры оценивают сервис (тональность — Semantic Map)
4. Знать вероятность задержек рейсов завтра (прогноз — Forecast Map)
5. Видеть схему маршрутов авиакомпаний (связи — Network Map)

Можно ли всё это нарисовать на одном экране? Технически — да. Но вы ничего не поймёте: точки самолётов будут мешать видеть заливку терминалов, стрелки маршрутов закроют радар, а прозрачность прогноза будет конфликтовать с цветом метрик. Поэтому каждый тип информации получает свой экран. Пять экранов — не потому что так удобнее, а потому что иначе данные становятся невидимыми.

## 🔀 Router v3.1 — Механизм А+Б

**Router** (`server/router.mjs`) — ключевой компонент. Определяет, какой модуль обработает запрос.

### 4 механизма поиска

**1. Механизм А (приоритет) — `export const route`:**

API-модуль сам декларирует префикс:
```javascript
export const route = '/api/layers/infrastructure-api';
export default handleInfrastructureAPI;
```

Router при загрузке модуля читает `module.route` и регистрирует в `modulePrefixCache`. Все последующие запросы к `/api/layers/infrastructure-api/*` идут **микросекундно** из кэша.

**2. routes-api.json — точное совпадение:**

Запись `{ path: '/api/layers/country-instability', module: 'country-instability-api' }`. Работает для legacy-модулей.

**3. routes-api.json — wildcard:**

Запись `{ path: '/api/layers/infrastructure-api/*', module: 'infrastructure-api' }`. Работает как fallback.

**4. Механизм Б — авто-префикс:**

Если файл в `apis/sources/` называется `{name}-api.mjs` — автоматически доступен через `/api/layers/{name}/*`. Для 300+ legacy-модулей.

### Приоритет поиска

1. `modulePrefixCache` (Механизм А) — самый быстрый
2. `routes-api.json (exact)` — точное совпадение
3. `routes-api.json (wildcard)` — с учётом `*`
4. `autoPrefixCache` (Механизм Б) — по имени файла

### Для разработчика

**Новый API-модуль** — рекомендуется добавить `export const route` (Механизм А):

```javascript
// apis/sources/my-module-api.mjs
export const route = '/api/layers/my-module';

export default async function handler(req, res) {
  // ...
}
```

**Больше не нужно** добавлять запись в `routes-api.json` вручную. Модуль сам регистрируется.

## 🧭 Система полярности и сверки нарративов

**Версия:** 1.0 · **Добавлено:** 22–23.09.2026

### Что это

Система, которая **вычисляет геополитическую полярность из данных** и **сверяет российский и западный нарративы по заданной теме**. Не пропаганда — сравнительный анализ фреймингов (comparative framing analysis) на наблюдаемых данных.

**Ключевой принцип:** полюс **вычисляется**, а не задаётся списком. Если данные изменятся — полюс изменится автоматически.

### Компоненты

| Файл | Тип | Назначение |
|------|-----|------------|
| `apis/sources/pole-tracker-api.mjs` | API | Вычисляет полярность стран из 8 basket-индикаторов |
| `apis/sources/narrative-splitter-api.mjs` | API | Сверяет российский и западный нарративы по теме |
| `apis/sources/source-camps.json` | Конфиг | Маппинг источников и baseline стран по полюсам |
| `dashboard/public/pole-map.html` | Страница | Карта полюсов: страны, confidence, векторы |
| `dashboard/public/narrative-arena.html` | Страница | Сверка нарративов: Россия / Запад / Расхождения |
| `scripts/snapshot-rsshub.mjs` | Скрипт | Накопление истории новостей (systemd timer) |

### Страницы

- **🌐 Карта полюсов** — [http://localhost:3117/pole-map](http://localhost:3117/pole-map)
  Показывает три полюса (russian / western / non_aligned) со странами, индекс полярности, векторы (санкции, инфовойна, военное присутствие), basket-статус.

- **⚡ Сверить нарративы** — [http://localhost:3117/narrative-arena](http://localhost:3117/narrative-arena)
  Три колонки: российский нарратив / западный нарратив / расхождения. Пресеты: санкции, Украина, энергопереход, конфликт, газ.

### API-эндпоинты

```bash
# Все полюса
curl http://localhost:3117/api/layers/pole-tracker

# Одна страна детально
curl "http://localhost:3117/api/layers/pole-tracker?country=russia"

# Сверка нарративов по теме
curl -G http://localhost:3117/api/layers/narrative-splitter \
    --data-urlencode "topic=Украина" \
    --data-urlencode "limit=10"

# Детальный вывод
curl "http://localhost:3117/api/layers/narrative-splitter?topic=санкции&detail=true"
```

### Что означают термины

| Термин | Смысл |
|--------|-------|
| **silence** | Одна сторона пишет (N>0), другая молчит (0). Сильнейший сигнал замалчивания |
| **framing_gap** | Обе стороны пишут, но с разным фреймингом |
| **double_standard** | Дисбаланс освещения >3x в одну сторону |
| **polarity_index** | 0..1: 0 = однополярный мир, 1 = максимальная полярность |
| **confidence** | 0..0.98: уверенность в классификации страны |
| **basis** | Источник классификации: `baseline_plus_data` / `data_driven` / `weak_signals` / `no_data` |

### Накопление истории

Скрипт `scripts/snapshot-rsshub.mjs` запускается по **systemd timer каждый час в 02 минуты**:

- Обновляет `data/basket/rsshub.json` через `collect-rsshub.mjs`
- Копирует снимок в `data/analytics/rss-history/rsshub-<timestamp>.json`
- Ведёт индекс `index.json`
- Обрезает архив до 168 снимков (7 дней)

```bash
# Управление таймером
systemctl --user status crucix-rsshub-snapshot.timer
systemctl --user list-timers crucix-rsshub-snapshot.timer
tail -20 logs/rss-history/systemd.log

# Ручной запуск
node scripts/snapshot-rsshub.mjs
```

**Зачем:** через неделю накопится 84 000 items — достаточно для реального анализа co-occurrence тем (threat inflation, selective framing).

- Проверить источник: `curl <api-url>` — отвечает ли?
- Проверить лог `logs/collectors/collect-{name}.log`
- Некоторые источники требуют User-Agent браузера (GDELT)

### Карта не загружается

- Проверить `data/world.geojson` в папке карты — существует ли файл
- Проверить консоль браузера — нет ли 404 на скрипты
- Проверить порядок скриптов в `index.html` — нарушение DAG = падение
- Проверить автономность: `grep -rn '\.\./' index.html js/*.js` — 0 строк

## 📦 Расширения

### Как добавить новый слой на карту

1. **Анализатор** — `scripts/analyzers/{id}.mjs` (читает корзину, пишет в `data/analytics/`)

4. **Слой** — `dashboard/public/<map-name>/js/layers.js` (массив `allLayers`):
   ```javascript
   { id: '{id}', name: 'Название', color: '#цвет', icon: '🎯', category: 'категория', vizType: 'marker' }
   ```
5. **Перезапуск сервера**

### Как создать новый сборщик

1. Файл `scripts/collectors/collect-{name}.mjs`
2. Импорт из открытого API (без ключа)
3. Сохранение в `data/basket/{name}.json`
4. Лог в `logs/collectors/collect-{name}.log`
5. Регистрация в cron

### Как добавить новую карту

Если нужно создать шестую карту для нового класса данных:

1. Создать папку `dashboard/public/<new-map-name>/`

## 📰 SmartScroll — интеграция RSS и Telegram

С 24.09.2026 в проект интегрирован **SmartScroll 1.0.0** — комплект сбора, дедупликации, кластеризации и суммаризации новостных потоков из RSS и Telegram. Результат работы — сюжеты, таймлайны и сводки, встроенные в граф знаний Crucix.

### Ключевое

- **Комплект**: `apis/sources/smartscroll*` — 16 модулей, 3 режима работы (external / local / auto).
- **Коллекторы**: RSS 2.0 + Atom и публичные Telegram-каналы через `t.me/s/` — без API-ключей и токенов.
- **Дедупликация**: 4 уровня — хеш контента, сигнатура сущностей, шинглы Jaccard, косинус TF-IDF.
- **Кластеризация**: inverted index по сущностям — поиск кандидатов за O(1) вместо O(N).
- **Суммаризация**: extractive (TF-IDF + MMR) + abstractive через локальный Ollama с автоматическим fallback.
- **HTTP-сервер**: 8 эндпоинтов на порту `3157` (переменная `SMARTSCROLL_HTTP_PORT`).
- **Метрики**: время по каждой стадии цикла (collect, normalize, dedup, cluster, summarize, store).
- **Отказоустойчивость**: rate limiter (token bucket) и circuit breaker во внешнем адаптере.
- **Валидация дат**: отсев событий старше 10 лет и будущих более чем на 24 часа.

## 1. Краткое резюме

Crucix использует 5 независимых карт вместо монолитного дашборда. Каждая карта обрабатывает только свой тип данных и использует только попарно сепарабельные визуальные каналы. Архитектура обоснована шестью независимыми научными теориями.

На 27 сентября 2026 года: каркас 5 карт создан, 195 базовых слоёв распределены, 48 ранее исключённых модулей добавлены в layers.js соответствующих карт. Event Map — основная рабочая карта (84 слоя). Остальные карты требуют настройки инфраструктуры и UI.

---

## 2. Проблема монолита

- Перегрузка канала — мозг 120 бит/сек, монолит 400+ бит/сек (Shannon 1948; Miller 1956; Cowan 2001)
- Split-attention effect — ментальная интеграция снижает результативность на 30-50% (Ayres & Sweller 2005)
- Channel interference — минимум одна пара каналов integral (Munzner 2014)
- Эмпирика — 70% отказываются от решения из-за перегрузки (Oracle 2023)

Принципиальное различие 5 карт

Разделение на 5 карт сделано потому, что данные, которыми они питаются, несовместимы между собой. Пять карт — это пять разных моделей данных, пять разных единиц измерения, пять разных способов привязки к географии. Их нельзя свести в одну карту без потери смысла.

Из index.html semantic-map видно переключатель карт:
/dashboard/event-map/ — Events
/dashboard/metrics-map/ — Metrics
/dashboard/semantic-map/ — Semantic
/dashboard/forecast-map/ — Forecast
/dashboard/network-map/ — Network

Из manifest.json semantic-map: mapType: "meanings", external_dependencies.local_cross_map: 0. То есть semantic-map объявлена самодостаточной — 0 ссылок на другие карты. Это архитектурный принцип R3 из комментария в layers.js семантики: «только свои слои, 0 ссылок на другие карты».

Конкретно чем semantic-map отличается от metrics-map
Metrics-map — карта измеримых числовых показателей. Единица данных: число (индекс, процент, абсолютная величина). Привязка: страна (полигон) через world.geojson. Тип визуализации: choropleth (заливка стран цветом по значению). Данные: window.layerCache[id] = [{name, value, status}]. Легенда: классы значений через .legend-item/.legend-row с палитрами COLOR_SCHEMES. Конфиг текущего слоя: window.currentChoroplethConfig с полями method, palette, breaks, gvf, stats. Именно эту модель ожидает текущий copy-data.js (v3.0, объединённая версия метрик).

Semantic-map — карта смысловых сущностей. Единица данных: объект (маркер, кластер, тон, достоверность). Привязка: точка (координаты lat/lng) для маркеров, либо абстрактная привязка к теме/нарративу для sentiment/cluster/credibility. Тип визуализации: marker, sentiment, cluster, credibility — не choropleth. Данные: window.layerCache[id] обычно пуст, потому что layer-panel.js::loadLayer не делает fetch и не пишет в кэш. Основной массив — window.markerData, генерируемый в markers.js через Math.random(). Это заглушка, а не реальные данные. Легенда #choropleth-legend присутствует в DOM, но никто её не заполняет. window.currentChoroplethConfig отсутствует. window.COLOR_SCHEMES отсутствует. Палитры хранятся в window.LAYER_OVERRIDES (см. layers.js семантики).

Пять карт — пять моделей
Events — точечные события во времени и пространстве. Единица: событие с датой. Привязка: координаты. Визуализация: маркеры, таймлайн.

Metrics — числовые показатели по странам. Единица: число. Привязка: страна (полигон). Визуализация: choropleth.

Semantic — смысловые сущности (тональность, нарратив, кластеры, достоверность). Единица: объект анализа. Привязка: точка или тема. Визуализация: marker/sentiment/cluster/credibility.

Forecast — прогнозные значения. Единица: прогноз с горизонтом. Привязка: страна или регион. Визуализация: choropleth или маркеры с динамикой.

Network — связи между сущностями. Единица: ребро графа. Привязка: узлы. Визуализация: граф.

Причина разделения: у каждой модели своя единица данных, своя привязка к географии, свой способ визуализации. Свести их в одну карту — значит потерять смысл. Metrics-map нельзя наложить на semantic-map: числа по странам и точки смысловых сущностей не пересекаются по типу.
