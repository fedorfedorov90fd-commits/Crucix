# Crucix Basket Schema v1

Схема единого формата данных корзины Crucix. Версия 1. Принята 18.09.2026.

## Назначение

Каждый файл в `data/basket/` имеет один и тот же формат независимо от источника. Формат определён схемой `data/schemas/basket.v1.json`. Задача — снять с API-модулей обязанность угадывать структуру и дать моделям гарантированный контракт на входные данные.

## Три представления в одном файле

Один файл содержит три независимых представления одного источника:

- `series` — временной ряд. Используется моделями: MCMC, particle filter, Hawkes, BayesNet, GPD, copula, EVT.
- `points` — пространственные точки. Используется для маркеров на карте.
- `regions` — региональные агрегаты. Используется для заливки стран (choropleth).

Потребитель выбирает, какое представление ему нужно. Модель читает `series`, страница карты — `points` или `regions`, страница справки — `meta`.

## Провенанс

Блок `meta` описывает, откуда пришли данные:

- `id` — идентификатор товара, совпадает с именем файла.
- `source` — человекочитаемое название источника.
- `source_url` — точный URL запроса.
- `fetched_at` — когда получено от источника.
- `normalized_at` — когда нормализовано кладовщиком.
- `collector` — имя сборщика.
- `license` — лицензия.
- `count` — общее число записей.
- `granularity` — шаг временного ряда.
- `period` — период в формате ISO 8601 duration.
