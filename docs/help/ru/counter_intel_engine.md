# Контрразведка: counter_intel_engine.py

## Простое объяснение (для новичков)

Этот файл — «сонар» системы. Он ищет не то, что написано, а то, чего **не написано**. Точнее — темы, которые должны обсуждаться, но о которых молчат конкретные группы источников.

**Пример:**

В мире произошло падение рынка. Крупные деловые СМИ обычно пишут об этом в первый час. Если они молчат — это само по себе новость. Модуль это замечает и подсвечивает: «тема есть у одной группы, но отсутствует у другой».

**Что он делает:**

1. **Сравнивает две группы источников** — что пишет группа A, чего не пишет группа B.
2. **Находит «белые пятна»** — темы, которые одна группа освещает, а другая обходит стороной.
3. **Проверяет географию** — если в важном регионе по важной теме у одной группы ноль публикаций, а у другой — много, это аномалия.
4. **Возвращает рекомендацию** — где повестка не сформирована и потенциально открыта для анализа.

**Зачем это нужно:**

Обычные системы мониторят только то, что сказано. Этот модуль добавляет «отрицательный поиск»: он смотрит на пустоты. Это важно, потому что молчание часто информативнее шума.

**Аналогия:**

Представьте, что вы слушаете радио. Одна станция вещает круглосуточно, другая — молчит. Вы не знаете, почему вторая молчит: может, сломалась, а может — намеренно. Модуль замечает это молчание и подсвечивает: «здесь что-то не так».

## Научная база (для специалистов)

Модуль реализует концепцию **информационной асимметрии** через реляционную алгебру. Основная операция — `EXCEPT` (разность множеств): темы группы A минус темы группы B.

**Формально:**

Пусть `T_A` — множество тем, освещаемых группой A за окно времени. `T_B` — множество тем, освещаемых группой B. Тогда:

**voids = T_A \ T_B** (темы, которые есть у A, но нет у B).

Аналогично для географии: `G_A(t)` — множество регионов, освещаемых группой A по теме `t`. `G_B(t)` — множество регионов, освещаемых группой B. `silent_zones = G_A(t) \ G_B(t)`.

**Ожидаемые темы и регионы:**

Задаются в конфигурации как «золотой стандарт» покрытия:
- `EXPECTED_TOPICS` — темы, которые всегда должны быть в эфире (geopolitics, economy, military, cyber, energy).
- `EXPECTED_REGIONS` — регионы, о которых всегда должны писать (USA, CHN, RUS, EU, GBR, UKR, ISR).

Если событие в важном регионе не отражено ожидаемыми источниками — это фиксируется как аномалия `EXPECTED_BUT_SILENT`.

**Временное окно:**

Задаётся через `NOW() - INTERVAL` в SQL. Это делает проверки оперативными: модуль смотрит только на свежие данные, не сканируя всю историю.

**Ограничения:**

- `EXCEPT` по большим таблицам требует индексов по `detected_at` и `topic`. Без индексов запрос будет медленным.
- Порог «нулевых публикаций» лучше заменить на относительный (доля от общего потока группы) — так устойчивее к разнице в объёмах.
- Результаты — это гипотезы, а не факты. Причиной «молчания» может быть и редакционный фокус, и технический сбой сбора.

## Как работает (пошагово)

1. `detect_information_voids(group_a, group_b, hours)` выполняет SQL-запрос с `EXCEPT`:
   - берёт темы группы A за последние `hours` часов;
   - вычитает темы группы B за тот же период;
   - результат — список «слепых зон».
2. `detect_geo_silent_zones(topic, hours)` аналогично проверяет географическое покрытие:
   - берёт регионы, которые освещает группа A по теме `topic`;
   - вычитает регионы, которые освещает группа B;
   - если в важном регионе у B ноль публикаций, а у A — значимое число, регион помечается.
3. Каждой находке присваивается рекомендация: `High-potential injection zone` — зона, где повестка не сформирована и потенциально открыта для анализа.
4. Соединение с БД закрывается в каждой функции (`conn.close()`) — защита от утечек соединений.

**Формат ответа:**

```python
{
    'void_type': 'WESTERN_SILENCE_ON_CRITICAL_TOPIC',
    'topics': ['energy', 'cyber'],
    'recommendation': 'High-potential injection zone'
}

Пример использования
python

from services.counter_intel_engine import detect_information_voids, detect_geo_silent_zones

# Поиск тем, которые есть у одной группы, но отсутствуют у другой
voids = detect_information_voids(group_a="russian", group_b="western", hours=24)
print(voids)
# {'void_type': 'WESTERN_SILENCE_ON_CRITICAL_TOPIC', 'topics': ['energy'], 'recommendation': '...'}

# Поиск географических зон, где тема игнорируется
zones = detect_geo_silent_zones(topic="cyber", hours=24)
print(zones)
# [{'country': 'EU', 'reason': 'EXPECTED_BUT_SILENT'}]

Что происходит:

    Модуль сравнивает, о чём пишут российские СМИ и о чём — западные.

    Если российские пишут об «энергетике», а западные — нет, это попадает в voids.

    Если в ЕС по теме «кибер» пишут только российские, а западные — нет, это попадает в zones.

Практические рекомендации

    Списки ожидаемых тем/регионов держите в конфиге. Они отражают редакционную политику мониторинга, а не «истину». Пересматривайте при изменении состава лент.

    Интерпретируйте пустоты как гипотезы. Причиной может быть и редакционный фокус, и технический сбой сбора. Не делайте выводов без проверки.

    Порог «нулевых публикаций» лучше заменить на относительный (доля от общего потока группы) — так устойчивее к разнице в объёмах.

    Логируйте запросы и их длительность. EXCEPT по большим таблицам требует индексов по detected_at и topic.

    Результаты складывайте в таблицу information_gaps. Это позволяет отслеживать динамику: как менялись «слепые зоны» во времени.

    Не используйте как единственный критерий. Молчание может быть естественным (тема неинтересна), а может быть намеренным (цензура). Контекст важен.

    EXPECTED_BUT_SILENT — самый сильный сигнал. Он означает, что скоординированное молчание важнее любого крика. Но и он требует проверки.

    conn.close() в каждой функции — правило хорошего тона. Без этого при массовой работе кончатся соединения с БД.

    NOW() - INTERVAL — оперативно. Не сканирует всю историю, только свежие данные. Это важно для больших таблиц.
