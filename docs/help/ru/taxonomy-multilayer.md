# Многоуровневая таксономия: taxonomy-multilayer.mjs

## Простое объяснение (для новичков)

Этот файл — «мозг» семантического понимания системы. Он заменяет простой поиск по словам на многоуровневую классификацию. Главная задача — находить **информационные разрывы**: когда о важном событии просто перестают писать.

**Что он делает:**

1. **Классифицирует новости по трём слоям:**
   - **Базовый** (16 тем) — геополитика, экономика, военные, кибер, энергетика.
   - **Языковой** (стемминг, синонимы) — «дипломатия» и «sanctions» относятся к одной теме.
   - **Контекстный** (специфика источников) — для конкретного источника добавляются свои маркеры.
2. **Строит инверсный индекс** — `Map`, где ключ — тема, значение — список ID новостей. Это позволяет мгновенно ответить на вопрос: «Какие новости по теме Энергетика?», не сканируя всю базу.
3. **Находит разрывы** — если важная тема не появлялась за последние 24 часа, система помечает это как `SILENCE_GAP`.

**Зачем это нужно:**

Обычные системы мониторят только то, что сказано. Этот модуль добавляет «отрицательный поиск»: он смотрит на пустоты. Если о падении рынка в первый час молчат все крупные деловые СМИ — это само по себе новость.

**Аналогия:**

Представьте, что вы читаете газеты. Вы замечаете: о погоде пишут все, о спорте — большинство, о культуре — некоторые. Но о важном событии в экономике — никто. Вы говорите: «Стоп, здесь что-то не так». Модуль делает то же самое, но автоматически.

## Научная база (для специалистов)

Модуль реализует **трёхслойную таксономию** с инверсным индексом и детектором аномалий.

**Архитектура:**

- **Базовый слой:** 16 тем, каждая с набором синонимов. Например, `geopolitics: ['дипломатия', 'sanctions', 'переговоры', ...]`.
- **Языковой слой:** стемминг и нормализация. «Санкции», «санкция», «санкционный» → одна лемма.
- **Контекстный слой:** специфика источников. Для `rt.com` — маркеры «многополярность», «суверенитет». Для `bbc.com` — «права человека», «демократия».
- **Инверсный индекс:** `TopicIndex` — `Map<topic, number[]>`. Ключ — тема, значение — массив ID новостей.
- **Детектор разрывов:** `detectInformationGaps(topicIndex, hours)` проверяет, есть ли в теме за последние `hours` часов хотя бы одна новость. Если нет — это `SILENCE_GAP`.

**Формально:**

1. **Классификация:** для каждого item `i` вычисляется множество тем `T(i) ⊆ {t_1, ..., t_16}`.
2. **Инверсный индекс:** `TopicIndex[t] = {i : t ∈ T(i)}`.
3. **Разрыв:** тема `t` имеет разрыв, если `TopicIndex[t] ∩ RecentItems(hours) = ∅`.

**Почему инверсный индекс:**

Вместо того чтобы для каждого запроса сканировать все новости и проверять, есть ли в них тема, мы один раз строим индекс. После этого запрос «все новости по теме X» — это `O(1)` доступ к массиву.

**Почему три слоя:**

- **Базовый** — общие темы, понятные всем.
- **Языковой** — синонимы, чтобы не пропустить перефразирования.
- **Контекстный** — специфика источников, чтобы не смешивать разные смыслы.

**Ограничения:**

- Словарный подход не ловит сарказм и сложные перефразирования. Для этого — `nlp_semantic_core.py` (эмбеддинги).
- `Set` для категорий гарантирует, что новость не будет помечена одной темой дважды.
- Контекстный слой требует ручной настройки для каждого источника. Это трудоёмко, но даёт точность.

## Как работает (пошагово)

1. `categorizeItem(item)` принимает новость.
2. Приводит заголовок к нижнему регистру.
3. Для каждой темы из `TAXONOMY.base` проверяет, есть ли в заголовке хотя бы одно слово из синонимов.
4. Если да — добавляет тему в `Set` категорий.
5. Для конкретного источника (например, `rt.com`) проверяет контекстные маркеры.
6. Если `Set` пуст — добавляет `silence_zone` (аномалия).
7. Обновляет `TopicIndex`: для каждой темы добавляет ID новости.
8. `detectInformationGaps(topicIndex, hours)` проверяет: если в теме за последние `hours` часов массив ID пуст — `SILENCE_GAP`.
9. Возвращает массив категорий и обновлённый `TopicIndex`.

**Формат ответа:**

```javascript
{
  categories: ['geopolitics', 'energy'],
  topicIndex: Map { 'geopolitics' => [1, 5, 12], 'energy' => [3, 7] }
}

Формат разрыва:
javascript

{
  topic: 'geopolitics',
  type: 'SILENCE_GAP',
  duration_hours: 24,
  severity: 'HIGH'
}

Пример использования
javascript

import { categorizeItem, detectInformationGaps } from './scripts/analyzers/taxonomy-multilayer.mjs';

// Классификация новости
const newsItem = {
  id: 1,
  title: 'Переговоры по энергетике возобновились',
  content: '...',
  source: 'rt.com'
};
const { categories, topicIndex } = categorizeItem(newsItem);
console.log(categories); // ['energy', 'geopolitics']

// Поиск разрывов
const gaps = detectInformationGaps(topicIndex, 24);
console.log(gaps);
// [{ topic: 'geopolitics', type: 'SILENCE_GAP', duration_hours: 24, severity: 'HIGH' }]

Что происходит:

    Новость «Переговоры по энергетике» классифицируется как energy (есть слово «энергетика») и geopolitics (есть слово «переговоры»).

    TopicIndex обновляется: energy → [1], geopolitics → [1].

    Если за 24 часа по теме geopolitics не было ни одной новости — это SILENCE_GAP.

Практические рекомендации

    Это реализация «отрицательного поиска». Ищем не то, что сказано, а то, о чём промолчали.

    Данные о разрывах (SILENCE_GAP) записываются в БД — для последующего анализа стратегий.

    Без модуля система видит только «шум», но не «звенящую тишину», предшествующую событиям.

    Превращает Crucix из «архива сказанного» в «карту умалчиваемого».

    config/taxonomy.json — словарь понятий (semantic vocabulary): 25 сущностей, 97 aliases, 8 контекстов. Позволяет менять логику без правки кода.

    group_cities_by_parent: true — города группируются в страну. «Москва» → «Россия».

    group_persons_by_parent: false — персоны не группируются. «Путин» — отдельная тема.

    Контекстный слой требует ручной настройки. Для каждого источника — свой набор маркеров. Это трудоёмко, но даёт точность.

    Set для категорий — гарантирует, что новость не будет помечена одной темой дважды.

    silence_zone — тема для новостей, которые не попали ни в одну из 16 базовых. Это не «мусор», это «аномалия». Она тоже участвует в детекции разрывов.

    Для больших корпусов — TopicIndex может занимать много памяти. Для 10 000+ новостей — используйте БД вместо Map.

    detectInformationGaps — чувствительна к окну времени. Малое окно (1–6 ч) — реакция на «горячие» события. Большое (48–168 ч) — фоновый анализ.

    Комбинируйте с nlp_semantic_core.py. Словарный подход быстрый, но грубый. Эмбеддинги — точнее, но медленнее. Вместе — полная картина.
