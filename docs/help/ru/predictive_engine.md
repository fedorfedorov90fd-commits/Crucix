# Предиктивная аналитика: predictive_engine.py

## Простое объяснение (для новичков)

Этот файл — «хрустальный шар» системы. Он смотрит на историю новостей и предсказывает, когда и по какой теме произойдёт следующий всплеск.

**Что он делает:**

1. **Берёт историю аномалий** — сколько раз за последние месяцы тема «энергетика» вызывала всплеск.
2. **Строит модель** — находит паттерны: например, вбросы по этой теме всегда происходят по понедельникам или после заседаний ООН.
3. **Продолжает ряд** — предсказывает, что будет в ближайшие 3 дня.
4. **Сравнивает с порогом** — если прогноз выше нормы, возвращает дату: «Ожидается всплеск 3 ноября, объём 142 публикации».
5. **Даёт «Lead Time»** — время упреждения. Мы знаем о кризисе за 72 часа до его начала в СМИ.

**Зачем это нужно:**

Обычные системы фиксируют то, что уже произошло. Этот модуль смотрит в будущее. Если он говорит «будет всплеск», аналитик может подготовиться: собрать контекст, проверить источники, подготовить ответ.

**Аналогия:**

Представьте, что вы ведёте дневник погоды. Каждый день записываете: было солнечно, было пасмурно, был дождь. Через месяц вы замечаете: дождь всегда идёт по средам. Модуль делает то же самое, но с новостями: находит ритмы и предсказывает следующий «дождь».

## Научная база (для специалистов)

Модуль реализует **прогнозирование временных рядов** через библиотеку Prophet (Meta).

**Prophet:**

Обобщённая аддитивная модель (GAM) с байесовской регуляризацией точек изменения тренда. Разлагает ряд на компоненты:

**y(t) = g(t) + s(t) + h(t) + ε(t)**

где:
- `g(t)` — тренд (кусочно-линейный с точками изменения).
- `s(t)` — сезонность (недельная, годовая).
- `h(t)` — эффект праздников (опционально).
- `ε(t)` — остаточная компонента.

**Подготовка данных:**

SQL-агрегация `date_trunc('day', detected_at) GROUP BY date` превращает неравномерный поток в регулярный дневной ряд. Это стандартная подготовка для моделей прогнозирования.

**Формально:**

1. `Prophet().fit(data)` обучает модель на исторических данных.
2. `make_future_dataframe(periods=3)` создаёт горизонт прогноза на 72 часа.
3. `model.predict(future)` возвращает `yhat` (точечный прогноз) и доверительные интервалы `yhat_lower`/`yhat_upper`.
4. Строки, где `yhat` превышает порог, помечаются как критические дни.
5. Первая такая дата возвращается как `predicted_spike_at`.

**Почему Prophet, а не ARIMA:**

- **Устойчивость к пропускам.** Не требует регулярного ряда. Если за какой-то день нет данных — не ломается.
- **Устойчивость к выбросам.** Байесовская регуляризация сглаживает аномалии.
- **Интерпретируемость.** Разложение на тренд и сезонность понятно человеку.
- **Простота.** Не требует ручного подбора параметров (в отличие от ARIMA).

**Сценарий «что если» (`simulate_scenario`):**

Копирует выборку, удаляет заданный источник, пересчитывает агрегированный индекс. Это позволяет оценить вклад конкретного источника в общую картину.

**Ограничения:**

- Prophet требует минимум ~14 точек для обучения. При меньшем объёме прогноз статистически ненадёжен.
- Порог нормальности зависит от темы. Разные темы имеют разную базовую интенсивность. Храните в конфиге.
- Доверительные интервалы полезнее точечного прогноза. Если `yhat_lower` уже выше порога — сигнал устойчив.
- Модуль следует запускать по расписанию, а не по каждому запросу. Обучение Prophet относительно дорого.

## Как работает (пошагово)

1. `forecast_topic_spike(topic_id, days_ahead)` принимает ID темы и горизонт прогноза.
2. Делает SQL-выборку исторических аномалий по теме за последние 60 дней.
3. Приводит данные к двум колонкам: `ds` (дата) и `y` (число событий).
4. `Prophet().fit(data)` обучает модель.
5. `make_future_dataframe(periods=3)` создаёт горизонт на 72 часа.
6. `model.predict(future)` возвращает прогноз.
7. Строки, где `yhat` превышает порог из `semantic_core.json`, помечаются как критические.
8. Первая такая дата возвращается как `predicted_spike_at`.
9. `simulate_scenario(topic_id, exclude_source)` — сценарий «что если»: копирует выборку, удаляет источник, пересчитывает индекс.

**Формат ответа:**

```python
{
    'topic_id': 'geopolitics',
    'predicted_spike_at': '2026-11-03T00:00:00',
    'predicted_volume': 142,
    'confidence': 120,  # yhat_lower
    'lead_time_hours': 72
}

Пример использования
python

from services.predictive_engine import forecast_topic_spike, simulate_scenario

# Прогноз всплеска
forecast = forecast_topic_spike("geopolitics")
print(forecast)
# {'predicted_spike_at': '2026-11-03T00:00:00', 'predicted_volume': 142, 'confidence': 120}

# Сценарий «что если»: что будет, если убрать источник
scenario = simulate_scenario("geopolitics", exclude_source="example.com")
print(scenario)
# {'global_index_before': 43, 'global_index_after': 38, 'delta': -5}

Что происходит:

    forecast_topic_spike строит модель на исторических данных по теме «геополитика».

    Prophet находит паттерны: например, всплески всегда по понедельникам.

    Прогноз: 3 ноября ожидается 142 публикации (выше нормы).

    simulate_scenario показывает: если убрать источник example.com, глобальный индекс упадёт с 43 до 38.

Практические рекомендации

    Запускайте по расписанию, а не по запросу. Обучение Prophet относительно дорого (секунды). Не запускайте на каждый fetch.

    Минимум ~14 точек для обучения. При меньшем объёме — возвращайте статус «недостаточно данных». Не давайте ложных прогнозов.

    Порог нормальности — в конфиге. Разные темы имеют разную базовую интенсивность. «Энергетика» может быть 50 публикаций в день, «кибер» — 5. Один порог для всех — неправильно.

    Доверительные интервалы полезнее точечного прогноза. Если yhat_lower уже выше порога — сигнал устойчив. Если yhat выше, а yhat_lower ниже — прогноз ненадёжен.

    Сценарии «что если» — для проверки гипотез. Не используйте как основание для организационных решений без дополнительной проверки.

    date_trunc('day', ...) — стандартная агрегация. Не используйте hour или week: для новостей день — оптимальный интервал.

    psycopg2 — прямая связь с PostgreSQL. Быстро, но требует закрытия соединений (conn.close()).

    Не прогнозируйте на > 7 дней. Горизонт 72 часа — оптимален. Для больших горизонтов — доверительные интервалы становятся слишком широкими.

    simulate_scenario — не удаляет данные из БД. Копирует выборку в памяти. Это безопасно.

    Комбинируйте с chaos_theory_engine.py. Если Ляпунов высокий, а прогноз — всплеск, это сильный сигнал: система «перегрета» и всплеск будет каскадным.
