# Crucix v6.0 — пять модулей научного синтеза

**Версия:** 6.0.0
**Расположение:** `apis/predict/v6/`
**Назначение:** пять независимых методов для углубления прогностического анализа поверх основной 13-фазной цепочки (A–R).

---

## Общая картина

v6.0 — это пять модулей, каждый из которых решает самостоятельную научную задачу:

| Модуль | Наука | Ключевая идея |
|--------|-------|---------------|
| `neural_causal_discovery.mjs` | Нейросетевой discovery DAG | NO TEARS + transformer |
| `continual_learning.mjs` | Continual Learning | EWC + Synaptic Intelligence |
| `causal_rl.mjs` | Causal RL | Q-learning с causal mask |
| `quantum_hypergraph.mjs` | Квантовый отжиг | QUBO + Path-Integral MC |
| `zk_federated.mjs` | ZK + federated | Schnorr proofs + DP |

Все пять подключаются к движку через фазу S в `engine_v6_patch.mjs` и запускаются параллельно через `Promise.allSettled` с per-module timeout и circuit breaker.

## 1. Neural Causal Discovery

**Файл:** `apis/predict/v6/neural_causal_discovery.mjs`
**Строк:** ~350
**Экспорт:** `NeuralCausalDiscovery`, `MultiHeadAttention`, `crucixNeuralCausalDiscovery`

### Задача

Дано: временной ряд наблюдений переменных (vix, tension, conflicts, sanctions, radiation). Найти структуру причинного графа (DAG) — какие переменные влияют на какие.

### Метод

1. **NO TEARS acyclicity constraint** (Zheng et al., 2018): вместо комбинаторного поиска — непрерывная оптимизация. Ограничение ацикличности:
   h(W) = tr(e^(W ∘ W)) - d = 0
   где W — матрица весов, ∘ — поэлементное умножение.

2. **Multi-Head Self-Attention** применяется к латентным представлениям переменных для усиления сигнала.

3. **Loss:** MSE реконструкции + L1-sparsity + lambda·|h(W)|.

4. **Gradient:** численный (finite differences), так как нет backprop через матричную экспоненту.

### Выход

Поля результата: module, available, nVariables, nTimesteps, discoveredEdges (массив {from, to, weight, direction}), nEdges, isAcyclic, density, interpretation.

### Когда использовать

- Оператор спрашивает: «какие переменные реально влияют на tension?»
- Нужна структурная карта причинности для дальнейшего анализа.
- Как вход для causal_rl и continuous_causal.

## 2. Continual Learning

**Файл:** `apis/predict/v6/continual_learning.mjs`
**Строк:** ~650
**Экспорт:** `EWCLearner`, `SynapticIntelligence`, `crucixContinualLearning`

### Задача

Модель учится на новых sweep'ах, но не забывает старые паттерны (кризисы 2024, редкие события). Классическая нейросеть при дообучении «забывает» предыдущие данные — catastrophic forgetting.

### Два метода

1. **EWC (Elastic Weight Consolidation)** — Kirkpatrick et al., 2017:
   - После обучения на задаче A фиксируем Fisher Information Matrix F для каждого веса.
   - При обучении на B добавляем штраф: lambda · sum(F_i · (theta_i - theta_A_i)^2)
   - Веса с высокой Fisher «заморожены», с низкой — свободны.

2. **Synaptic Intelligence** — Zenke et al., 2017:
   - Онлайн-накопление importance: omega += g^2 / (loss + zeta)
   - Не требует отдельного прохода для Fisher.

### Архитектура

MLP: inputSize → hiddenSize → outputSize (3 класса: crisis/elevated/stable).

### Persistence

Состояние сохраняется в runs/predictions/continual_learner.json. При загрузке проверяется валидность: все веса должны быть finite.

### Выход

Поля: module, method, taskId, tasksLearned, lossBefore, lossAfter, lossReduction, forgettingBefore, forgettingAfter, forgettingDelta, prediction (class + probabilities), fisherNorm.

### Когда использовать

- Каждый sweep: модель дообучается на новых данных без потери старого знания.
- Метрика forgettingDelta — насколько модель забыла старые паттерны (чем меньше, тем лучше).

## 3. Causal Reinforcement Learning

**Файл:** `apis/predict/v6/causal_rl.mjs`
**Строк:** ~640
**Экспорт:** `CausalEnvironment`, `CausalQLearner`, `CausalPolicyGradient`, `crucixCausalRL`

### Задача

Агент учится выбирать действия (observe / monitor / sanctions_low / sanctions_high / intervention), но не через корреляции, а через причинную структуру. Действие допустимо только если узел, на который оно направлено, не имеет confounders.

### Три компонента

1. **CausalEnvironment** — MDP поверх DAG:
   - State: (vix, tension, conflicts, sanctions, radiation)
   - Actions: do(X=x) для узлов-причин + observe
   - Dynamics: dz_i/dt = sum(w_ij · parent_j) + noise
   - Reward: -2·tension - vix - 1.5·conflicts + бонус за снижение

2. **CausalQLearner** — Q-learning с causal mask:
   - Q-table: Map(stateKey → Float64Array(nActions))
   - Маска допустимых действий для каждого состояния
   - epsilon-greedy policy

3. **CausalPolicyGradient** — REINFORCE с causal mask.

### Выход

Поля: module, method, training (avgReward, causalRatio), evaluation (policyAvg, randomAvg, improvementPct), causalInsights (массив с node/ateHigh/direction/policyPrefers), recommendedAction.

### Когда использовать

- Оператор спрашивает: «какое действие оптимально?»
- Counterfactual-анализ: «что если мы применим санкции?»
- Оценка политик через evaluatePolicy.

## 4. Quantum-Inspired Hypergraph Sampling

**Файл:** `apis/predict/v6/quantum_hypergraph.mjs`
**Строк:** ~490
**Экспорт:** `QUBOFormulation`, `QuantumAnnealer`, `HypergraphMAP`, `crucixQuantumHypergraph`

### Задача

Поиск MAP-структуры гиперграфа (N-арные причинные связи) — NP-трудная комбинаторная задача. Решается через квантовый отжиг.

### Три компонента

1. **QUBOFormulation** — построение Ising-модели:
   - Бинарная переменная s_e ∈ {0,1} для каждого кандидата-гиперребра
   - c[i] = -CMI(edge_i) + lambda_BIC·2^|edge_i|
   - Q[i][j] = lambda_overlap · |parents_i ∩ parents_j| если оба имеют один target

2. **QuantumAnnealer** — Path-Integral Quantum Annealing (Suzuki, 1995):
   - P реплик Ising-модели
   - Кинетический член J(t) для туннелирования
   - Отжиг по температуре T и gamma

3. **HypergraphMAP** — сборка гиперграфа из бинарного решения + проверка ацикличности DFS.

### Выход

Поля: module, nQubits, annealing (bestEnergy, convergence), hypergraph (nHyperedges, avgHyperedgeSize, totalMI, isAcyclic), topEdges.

### Когда использовать

- Нужны N-арные связи: не пары (A→B), а группы (A+B+C→D).
- Когда обычный DAG-discovery не находит причин.
- Производительность: QUBO + annealer работают за ~200-500 ms.

## 5. Zero-Knowledge Federated Learning

**Файл:** `apis/predict/v6/zk_federated.mjs`
**Строк:** ~600
**Экспорт:** `ZKSchnorrProver`, `DPMechanism`, `FederatedNode`, `SecureAggregator`, `crucixZKFederated`

### Задача

Распределённое обучение: несколько узлов (региональные Crucix-инстансы) обучают локальные модели, обмениваются градиентами, но не раскрывают локальные данные. Плюс защита от poisoning-атак.

### Три компонента

1. **ZKSchnorrProver** — протокол Шнорра + Fiat-Shamir:
   - Доказательство знания секретного ключа без раскрытия
   - 2048-bit MODP Group (RFC 3526)

2. **DPMechanism** — Gaussian Mechanism:
   - (epsilon, delta)-дифференциальная приватность
   - sigma = sensitivity · sqrt(2·ln(1.25/delta)) / epsilon
   - Clipping + Gaussian noise

3. **SecureAggregator** — FedAvg с poisoning defense:
   - ZK-верификация proof каждого узла
   - MAD (Median Absolute Deviation) для обнаружения outliers
   - Weighted average (веса пропорциональны 1/loss)

### Выход

Поля: module, nNodes, rounds, privacy (epsilon, delta, privacySpent), training (initialLoss, finalLoss, lossReduction), security (zkProtocol, poisoningDefense, totalRejected).

### Когда использовать

- Развёртывание Crucix на нескольких серверах / регионах.
- Когда нельзя передавать сырые данные между узлами (regulation, privacy).
- Защита от злонамеренных узлов в federated-сети.

## Интеграция в engine

Все 5 модулей v6.0 подключаются через фазу S в engine_v6_patch.mjs.

### API

    import { runV6Phase } from './engine_v6_patch.mjs';
    const v6Result = await runV6Phase(history, {
      disabled: [],
      timeoutMs: 60000,
    });

Поля v6Result: modules (объект с результатами по каждому модулю), okCount, totalModules, elapsedMs.

### Circuit breaker

После 3 падений подряд модуль отключается на 5 запусков. Восстанавливается автоматически.

### Параллельный запуск

Promise.allSettled — падение одного не блокирует остальные.

### Расширение snapshot

Функция applyV6ToSnapshot(snapshot, v6Phase, catalogPhase) добавляет:
- snapshot.v6_extensions.modules — результаты по каждому модулю
- snapshot.v6_extensions.signals — извлечённые сигналы для explanation
- snapshot.explanation.reasoning_steps — добавленные шаги
- snapshot.explanation.summary — расширенная интерпретация

Тесты: tests/v6/neural_causal_discovery.test.mjs (16) + tests/v6/v6_pack.test.mjs (19). Итого 35 тестов, все PASS.

Healthcheck:

    import { healthcheck } from './engine_v6_patch.mjs';
    const h = healthcheck();

h.v6Modules — 5 модулей, каждый с полями exists / path / minHistory.

Типичные проблемы:

| Симптом | Причина | Решение |
|---------|---------|---------|
| NaN в loss | Численный градиент взорвался | Уменьшить learningRate, добавить clip |
| circuit_open в логе | 3+ падений подряд | Увеличить timeoutMs или временно отключить модуль |
| Невалидный snapshot.v6_extensions | Все модули skip | Проверить history.length ≥ 30 |
