# Кластеризация событий: cluster-events.mjs

## Простое объяснение (для новичков)

Этот файл — «мозг журналиста». Обычный RSS-ридер видит только текст. Этот модуль видит **события**.

**Пример:**

- Новость 1: «Взрыв на площади» (12:00)
- Новость 2: «Мощный хлопок в центре города» (12:01)
- Новость 3: «Полиция оцепила район после инцидента» (12:05)

Для компьютера это три разных строки. Для читателя — одно событие. Модуль понимает это и объединяет их в одну «Карточку события» с весом = 3.

**Зачем это нужно:**

Чтобы «Глобальный индекс» не сходил с ума от количества сообщений, а оценивал значимость самого происшествия. Если 10 газет написали об одном взрыве — это одно событие с весом 10, а не 10 разных событий.

**Аналогия:**

Представьте, что вы читаете утренние газеты. В пяти из них — заметка о вчерашнем пожаре. Вы же не считаете это пятью разными пожарами. Вы понимаете: это один пожар, о котором написали пять газет. Модуль делает то же самое, только автоматически.

## Научная база (для специалистов)

Задача относится к **кластеризации коротких текстов**. Применяются три подхода:

1. **Символьное сходство** — коэффициент Жаккара по множествам слов. Устойчиво к перестановкам, но чувствительно к синонимам.
2. **Векторное представление** — TF-IDF с косинусной близостью. Учитывает частоту слов в корпусе, лучше работает с длинными текстами.
3. **Семантическая близость** — косинусное расстояние между эмбеддингами (`nlp_semantic_core.py`). Понимает синонимы и перефразирования, но требует нейросетевой модели.

**Реализация в Crucix:**

Используется гибридный подход:
- **NE-сходство** (Named Entities) — 0.55 веса.
- **Токены** (значимые слова) — 0.35 веса.
- **Шинглы** (n-граммы, n=3) — 0.10 веса.

Порог кластеризации — 0.45 (`config/clustering.json`). Если сходство выше — записи объединяются в кластер.

**Почему именно такой набор весов:**

- NE дают наибольший вес, потому что названия сущностей (страны, люди, организации) — самые стабильные маркеры события. «Взрыв в Мадриде» и «Теракт в столице Испании» имеют общую NE «Мадрид/Испания».
- Токены добавляют контекст: «взрыв», «теракт», «ЧП» — разные слова, но все указывают на одно событие.
- Шинглы ловят порядок слов: «Путин встретился с Си» и «Си встретился с Путиным» имеют общие шинглы, хотя порядок разный.

**Ограничения:**

- Подпись из трёх слов устойчива к перестановкам, но чувствительна к синонимам: «удар» и «атака» дадут разные кластеры.
- Пороги severity (`count > 10 → critical`, `count > 5 → high`) зависят от объёма потока. Калибруйте на исторических данных.

## Как работает (пошагово)

1. `clusterEvents(events)` принимает массив нормализованных новостей.
2. Для каждой новости извлекаются:
   - NE (Named Entities) — заглавные слова длиной 3+ символа, кроме стоп-слов.
   - Токены — значимые слова (длина > 4), кроме стоп-слов.
   - Шинглы — n-граммы (n=3) из токенов.
3. Строится «подпись» события — комбинация NE, токенов и шинглов.
4. Для каждой новой новости проверяется сходство с существующими кластерами.
5. Если сходство > 0.45 — новость добавляется в существующий кластер, `count` увеличивается.
6. Если нет — создаётся новый кластер с `count = 1`.
7. После прохода формируется массив карточек: представитель кластера, вес (`weight`) и уровень серьёзности (`severity`).

**Формат карточки:**

```javascript
{
  title: "Взрыв в Мадриде",
  link: "https://...",
  published_at: "2026-11-02T12:00:00Z",
  category: "conflict",
  source: "Reuters",
  weight: 7,            // сколько источников осветили
  severity: "high",     // normal / high / critical
  article_ids: [1, 5, 12, 18, 23, 41, 55]  // все статьи кластера
}

Пример использования
javascript

import { clusterEvents } from './scripts/analyzers/cluster-events.mjs';

const news = await processRSSFeed('/api/rss-feed/');
const events = clusterEvents(news);

// events[0] = { title, link, published_at, category, source, weight: 7, severity: 'high' }
console.log(`Событий: ${events.length}, из ${news.length} статей`);

Что происходит:

    Из 500 статей формируется ~300 событий.

    Компрессия — 1.15x (500 → 300). Это означает, что в среднем каждая карточка содержит 1.67 статьи.

    7.7% карточек — multi-source (несколько источников). Остальные — одиночные (один источник).

Практические рекомендации

    Порог «длина слова > 4» — эмпирический: для русского языка отсекает предлоги, но пропускает короткие значимые слова («США», «ЕС»). Добавьте белый список для таких слов.

    Подпись из трёх слов — устойчива к перестановкам, но чувствительна к синонимам. Для повышения качества замените символьную подпись на косинусную близость TF-IDF или эмбеддингов.

    Пороги severity — зависят от объёма потока. Калибруйте на исторических данных: count > 10 → critical, count > 5 → high, иначе normal.

    Модуль не заменяет дедупликацию в collect-rss-unified.mjs. Первый убирает точные повторы заголовков, второй группирует схожие события. Используйте последовательно.

    Для устойчивости к языковым вариациям — храните подписи в нормализованном виде (леммы), если есть морфологический анализатор.

    Результат кластеризации — удобно сохранять в таблицу events, чтобы отслеживать динамику веса события во времени.

    config/clustering.json — порог 0.45. Уменьшите до 0.35, если события не объединяются (много «осколков»). Увеличьте до 0.55, если объединяется лишнее.

    NE regex без \b — \b в JS не работает для кириллицы. Правильно: /[А-ЯЁA-Z][а-яёa-z\-]{2,}/gu.

    normalizeUrl — убирает utm_*, #, trailing slash, http→https. Без этого дедуп по ссылке не работает.

    DELETE FROM events перед пересборкой — если пересчитываете кластеры «с нуля». Иначе копятся старые кластеры.
