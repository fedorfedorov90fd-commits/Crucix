# Словарь понятий: semantic_core.json

## Простое объяснение (для новичков)

Этот файл — «словарь» системы. Он говорит, какие темы искать, какие слова к ним относятся и какие источники к каким группам причислять.

**Что внутри:**

```json
{
  "topics": [
    {
      "id": "t_01",
      "ru": "Геополитика",
      "en": "Geopolitics",
      "synonyms": ["мировой порядок", "balance of power", "дипломатия"]
    },
    {
      "id": "t_02",
      "ru": "Экономика",
      "en": "Economy",
      "synonyms": ["рынки", "finance", "macro", "инфляция"]
    }
  ],
  "source_groups": {
    "western": ["bbc", "reuters", "nyt", "dw"],
    "russian": ["ria", "tass", "rbk", "sputnik"],
    "neutral": ["reuters", "ap", "interfax"]
  },
  "disbalance_triggers": {
    "silence_threshold": 0.15,
    "surge_threshold": 2.0
  }
}

Что означает каждое поле:

    topics — список тем. Каждая тема имеет id (стабильный идентификатор), ru (название по-русски), en (по-английски), synonyms (синонимы для поиска).

    source_groups — группы источников. western, russian, neutral. Используется для сравнения нарративов.

    disbalance_triggers — пороги. silence_threshold — доля публикаций, ниже которой тема считается «молчащей». surge_threshold — относительный объём, выше которого фиксируется всплеск.

Зачем это нужно:

Чтобы система начала искать новую тему, не нужно переписывать код. Достаточно добавить в JSON строку с названием темы и её синонимами. Аналогично, чтобы система знала, какие издания относить к одной группе, достаточно перечислить их в списке.

Аналогия:

Это как меню в ресторане. Вы не переписываете кухню, чтобы добавить новое блюдо. Вы просто дописываете его в меню. Система читает меню и готовит то, что там написано.
Научная база (для специалистов)

Конфигурационный файл задаёт словарь понятий (semantic vocabulary) — конечное множество понятий и отображение «текст → понятие» через список синонимов.

Формально:

Файл задаёт:

    Множество понятий T = {t_1, t_2, ..., t_n} — темы.

    Отображение synonyms: T → 2^S, где S — множество строк (синонимы).

    Разбиение источников G = {g_1, g_2, g_3} — группы.

    Пороги silence_threshold, surge_threshold — параметры статистических детекторов.

Тезаурус:

С точки зрения информационного поиска, это упрощённый тезаурус — множество терминов, связанных отношением эквивалентности. Синонимы в topics[i].synonyms — это классы эквивалентности: «дипломатия» ≡ «geopolitics» для целей категоризации.

Разбиение источников:

source_groups задаёт разбиение множества изданий. Это используется в contrast-engine.mjs для сравнения нарративов между группами. Важно: источник может быть в нескольких группах (например, reuters в western и neutral). Это не ошибка: Reuters — западное агентство, но часто цитируется как нейтральное.

Пороги:

    silence_threshold = 0.15 — если тема занимает менее 15% публикаций группы, она считается «молчащей».

    surge_threshold = 2.0 — если объём публикаций по теме превышает норму в 2 раза, фиксируется всплеск.

Ограничения:

    Синонимы хранятся в нижнем регистре, без словоформ. Морфологию закрывает лемматизация в NLP-слое.

    Группы источников отражают редакционную политику мониторинга, а не «истину». Пересматривайте при изменении состава лент.

    Пороги — не константы природы. Калибруйте на исторических срезах и фиксируйте версию конфига в отчётах.

Как работает (пошагово)

    multilayer-taxonomy.mjs при старте читает config/semantic_core.json.

    Парсит JSON, извлекает topics, source_groups, disbalance_triggers.

    Строит TAXONOMY — объект с синонимами.

    Строит TopicIndex — инверсный индекс «тема → список новостей».

    categorizeItem(item) проходит по всем синонимам. Если в заголовке есть хоть одно слово — присваивает ID.

    detectInformationGaps(topicIndex, hours) проверяет: если в теме за последние N часов массив ID пуст — это аномалия.

    contrast-engine.mjs использует source_groups для сравнения нарративов.

Что происходит при добавлении новой темы:

    Добавьте объект в массив topics.

    Укажите id, ru, en, synonyms.

    Сохраните файл.

    При следующем запуске таксономия подхватит новую тему.

Что происходит при изменении групп источников:

    Измените список в source_groups.

    Сохраните файл.

    При следующем запуске contrast-engine.mjs использует новые группы.

Пример использования

Добавление новой темы (например, «климат»):
json

{
  "id": "t_17",
  "ru": "Климат",
  "en": "Climate",
  "synonyms": ["климат", "потепление", "парник", "climate", "warming", "carbon"]
}

Изменение групп источников:
json

"source_groups": {
  "western": ["bbc", "reuters", "nyt", "dw", "guardian", "npr"],
  "russian": ["ria", "tass", "rbk", "sputnik", "interfax"],
  "neutral": ["reuters", "ap", "france24"]
}

Изменение порогов:
json

"disbalance_triggers": {
  "silence_threshold": 0.20,
  "surge_threshold": 2.5
}

Практические рекомендации

    id должны быть стабильными. На них ссылаются таблицы БД и отчёты. Меняйте только человекочитаемые поля (ru, en) и синонимы.

    Синонимы храните в нижнем регистре и без словоформ. Приведение к нижнему регистру делает код, морфологию лучше закрывать лемматизацией в NLP-слое.

    Группы источников отражают редакционную политику мониторинга. Пересматривайте их при изменении состава лент. Источник может быть в нескольких группах (Reuters — и western, и neutral).

    Пороги — не константы природы. Калибруйте на исторических срезах. Фиксируйте версию конфига в отчётах для воспроизводимости.

    Держите файл под версионным контролем. Изменение синонимов меняет результаты категоризации. Это должно быть отслеживаемо.

    Для многоязычных корпусов добавляйте синонимы на всех рабочих языках. Модуль таксономии ищет совпадения по всем записям массива.

    Не удаляйте старые темы. Даже если тема больше не актуальна — оставьте её. Старые данные в БД могут ссылаться на её id.

    source_groups — три группы. Если нужна четвёртая (например, asia) — добавьте. Но убедитесь, что все модули, которые используют группы, знают о новой.

    disbalance_triggers — два порога. silence_threshold — для детектора молчания. surge_threshold — для детектора всплесков. Меняйте осознанно.

    Файл читается при старте. Если вы изменили его — перезапустите модуль. Иначе изменения не применятся.

    scripts/analyzers/source-coordination.mjs — использует source_groups (рядом).
