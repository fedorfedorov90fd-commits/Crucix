# Human Feedback Learning — замысел модуля

**Статус: спроектирован, не написан.**

Папка-памятник замысла. Здесь всё, что нужно, чтобы через месяц вернуться и продолжить с того же места — без потери контекста, без переизобретения.

---

## Что это

Модуль `human_feedback.mjs` замыкает обучающий цикл прогностической системы через оператора-человека.

В мире LLM это называется RLHF — Reinforcement Learning from Human Feedback, обучение с подкреплением на основе обратной связи от человека. Применённое не к языковой модели, а к прогностическому ансамблю Crucix.

**Короткая формулировка: оператор подтверждает или опровергает прогноз — система сразу корректирует веса признаков, не дожидаясь, пока событие произойдёт или не произойдёт.**

---

## Почему это важно

Пять причин, каждая из которых — самостоятельный мотив.

### 1. Быстрое обучение на малых данных

Пока у Crucix нет 3–6 месяцев истории (об этом прямо говорит план вытряха), обычный Brier Score работает плохо — ему не хватает разрешённых прогнозов. Обратная связь оператора даёт сигнал сразу, без ожидания.

### 2. Обработка редких событий

Катастрофические события редки. Brier Score по ним почти не двигается: одно событие на сто прогнозов статистически незначимо. Оператор может отметить «этот прогноз катастрофы правдоподобен» — и это уже сигнал, несмотря на отсутствие самого события.

### 3. Доверие оператора к системе

Когда оператор видит, что его оценка действительно меняет модель — он начинает работать с системой, а не против неё. Это не украшение, а практическая необходимость: без доверия оператор не станет тратить время на разметку.

### 4. Соединение двух типов знания

Модель даёт вероятности, но не понимает контекста. Оператор понимает контекст, но не считает вероятности в реальном времени. Обратная связь — точка соединения. Экспертное знание превращается в форму, которую модель может использовать.

### 5. Механизм «что если»

Оператор может вручную изменить входные данные («предположим, санкции введут через 48 часов») и увидеть, как изменится прогноз. Это не просто интерфейс — это ещё один сигнал: если оператор часто меняет одно и то же входное значение, значит модель его недооценивает.

---

## Конкурентное преимущество

Ни Palantir, ни Recorded Future, ни Seldon Vault публично не делают этого.

У Palantir Maven операторская валидация есть — но она не превращается в автоматическое обновление весов. У Recorded Future есть обратная связь от аналитиков — но она уходит в отчёт, не в модель. У Seldon Vault 11 LLM-агентов, но нет оператора-человека в петле обучения.

Crucix может стать первым открытым инструментом, где оператор замыкает цикл обучения напрямую.

---

## Три возможные архитектуры

### Вариант 1. Простой

Оператор ставит метку good/bad на прогноз. Система хранит историю меток и через простой градиентный шаг обновляет веса признаков: good — признакам, повлиявшим на прогноз, повышаем вес; bad — понижаем.

Плюсы: просто, быстро, понятно.
Минусы: грубо, нет градаций, нет текстовых комментариев.

### Вариант 2. Полный RLHF

Оператор ранжирует пары прогнозов («прогноз A лучше, чем прогноз B»). Система учится на предпочтениях через reward model.

Плюсы: академически строго, стандарт для LLM.
Минусы: требует больше данных оператора, сравнивать пары сложнее, чем ставить метку.

### Вариант 3. Гибридный (рекомендуется)

Оператор ставит метку good/bad/uncertain, плюс может дать текстовый комментарий («не учтён фактор X»). Система обновляет веса, комментарии уходят в отдельный поток для будущего дообучения LLM-слоя.

Плюсы: практичность + гибкость, совместимо с реальной работой оператора.
Минусы: чуть сложнее в реализации, но не критично.

## Пять причин, почему модуль заморожен

### 1. Нет пары в оркестраторе

В `apis/predict/engine.mjs` (4часть, строки 7–1200) нет вызова `human_feedback`. Там есть только `active_learning.mjs`. Прежде чем писать модуль, надо решить: до фазы D (ансамблирование), после фазы F (калибровка), или параллельно.

**Рекомендация AI: после фазы F.** Потому что веса признаков обновляются уже с учётом калибровки. Если обновлять до калибровки, потом калибровка может срезать эффект обратной связи.

### 2. Нет источника обратной связи

Интерфейс оператора (дашборд с кнопками good/bad) не создан. Без интерфейса модуль будет ждать сигнала, которого не будет.

**Решение: файл `human_feedback.dashboard.html` в этой же папке.**

### 3. Не определена политика обновления весов

Модель должна знать: обновлять веса признаков, веса источников, веса моделей ансамбля, или всё сразу?

**Рекомендация AI: начать только с весов признаков.** Это самый прямой и понятный слой. Веса источников и моделей ансамбля подключаются позже, когда станет ясна эффективность базового механизма.

### 4. Нет режима «что если»

Механизм ручного изменения входных данных требует отдельного интерфейса и отдельной логики.

**Решение: отдельная секция в `human_feedback.dashboard.html`.**

### 5. Не решено, что делать с текстовыми комментариями

Игнорировать? Сохранять в лог? Отправлять в LLM?

**Рекомендация AI: сохранять в лог.** Отправка в LLM — отдельная задача, которая требует доработки LLM-слоя. На первом этапе комментарии служат контекстом для аналитика при следующем просмотре истории.

## Четыре зависимости (что ждёт реализации снаружи)

Этот модуль не работает в одиночку. Чтобы он ожил, нужны четыре вещи:

1. **Интерфейс оператора.** Дашборд с кнопками good/bad/uncertain и полем комментария. Уже есть — файл `human_feedback.dashboard.html` в этой папке.

2. **Интеграция в engine.mjs.** Вызов `human_feedback` после фазы F. См. `engine_integration.md`.

3. **Хранилище истории.** Файл `runs/predictions/human_feedback.json`. Создаётся автоматически при первом обращении.

4. **Потребитель обновлённых весов.** Механизм, который читает обновлённые веса и использует их в следующем sweep. Пока не реализован — веса сохраняются, но никто их не читает.

Из четырёх зависимостей в этой папке реализованы две: интерфейс оператора и интеграционный план.

## Мотив и настроение

Этот модуль — не «ещё одна фича». Это попытка сделать Crucix не просто системой, которая считает вероятности, а системой, которая учится у человека.

Модель без обратной связи — как эксперт без оппонента. Он может быть прав, но он не знает, где ошибается. Оператор — оппонент, который видит то, чего модель не видит. Замыкание их в один цикл — это не про технологию, это про эпистемологию.

Если Crucix станет первой открытой платформой, где оператор замыкает цикл обучения напрямую, — это будет не про производительность и не про количество сигналов. Это будет про то, как знание одного человека превращается в знание системы.
