# 001. Два независимых pipeline обработки новостей

Дата: 2026-09-26
Статус: accepted
Уровень уверенности: высокий

Контекст

В Crucix существуют две системы обработки новостей, развивавшиеся независимо. SmartScroll — превращение потока новостей в связные сюжеты с временной динамикой, дедупликацией 4 уровня, кластеризацией, суммаризацией и bias-aware весом достоверности. Contract-v3 pipeline — плоский новостной поток с circuit breaker, классификацией URL (direct/tor/dead) и прямым API. Возник вопрос: объединить или оставить оба.

Рассмотренные варианты

Вариант A. Оставить оба. Плюсы: разделение ответственности, независимое масштабирование, тестируемость, замена без переписывания. Минусы: частичное дублирование данных на уровне OPML-URL.

Вариант B. Свести к одному. Плюсы: один источник истины. Минусы: потеря flat-потока для быстрого API, усложнение SmartScroll.

Вариант C. Оставить оба, разделив по слоям. Плюсы: как A, но с явным разделением ролей. Минусы: требует архитектурного документа.

Решение

Выбран вариант A (идентичен C). Обоснование: слои разные, файлы разные, цели разные. Дублирование по данным допустимо. Дублирование по функции запрещено. Правило 1070 (дубли — только синтез) соблюдено.

Границы: SmartScroll — сюжеты, дедуп 4 уровня, кластеризация, bias_rank_weight, граф знаний. Contract-v3 — flat-поток, circuit breaker, direct/tor/dead, прямые API.

Точки соприкосновения: общие OPML-URL, общий справочник source-camps.json, общий справочник countries.json.

Запрещено: SmartScroll читает data/basket/rss.json; Contract-v3 читает smartscroll-stories.json; cross-pipeline вызовы функций.

Последствия

Что даёт: каждый pipeline — эксперт в своей задаче; независимое масштабирование; возможность заменить один; соответствие separation of concerns.

Что ограничивает: часть данных дублируется; требуется синхронизация source-camps.json.

Компромиссы: осознанно принимаем частичное дублирование данных ради независимости слоёв.
